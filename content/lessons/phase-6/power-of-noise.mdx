## Core idea

Conventional wisdom says: **only retrieve relevant documents**. But research by Cuconasu et al. (2024) found something shocking:

> Including **irrelevant documents** in the RAG prompt can improve accuracy by **over 30%** compared to using only relevant documents!

### The Experiment Results

| Configuration         | Accuracy  |
| --------------------- | --------- |
| Gold only             | 67.2%     |
| Gold + Related        | 71.8%     |
| **Gold + Irrelevant** | **84.5%** |
| Related only          | 45.3%     |

### Why Does Noise Help?

**1. Attention Calibration**: When all documents are relevant, the LLM's attention is diffused. Adding irrelevant documents creates **contrast**, making relevant info stand out.

**2. Reducing Hallucination**: Related-but-not-answering documents introduce confusion:

```text
Query: "What is the capital of Australia?"

Related docs (harmful):
- "Sydney is Australia's largest city..."
- "Melbourne hosts the Australian Open..."
→ LLM might say Sydney or Melbourne

Irrelevant docs (helpful):
- "Photosynthesis converts light to energy..."
- "The Roman Empire fell in 476 AD..."
→ LLM ignores these, focuses on finding actual answer
```

**3. Verification Signal**: Clearly irrelevant content signals to the LLM that not all retrieved content is useful, encouraging critical evaluation.

### Implementation

```python
def optimal_document_mix(gold_doc, candidates, k=5):
    """Create optimal document mix based on noise research."""
    # Classify candidates
    relevant = [d for d in candidates if is_relevant(d)]
    irrelevant = [d for d in candidates if not is_relevant(d)]

    # Build mix: 1 gold + 1-2 relevant + 2-3 irrelevant
    final = [gold_doc]
    final.extend(relevant[:2])
    final.extend(irrelevant[:k - len(final)])

    return final
```

## Failure modes

<Callout type="warning" title="Common Pitfalls">
**Weak LLMs get confused**: This technique works best with strong models (GPT-4 class) that can filter noise.

**Too much noise**: Beyond 30-40% irrelevant docs, performance degrades.

**Wrong domain noise**: Noise should be clearly irrelevant, not subtly misleading.

**Multi-hop queries**: For questions requiring synthesis across documents, noise hurts.

**Retrieval failure masked**: If your gold documents aren't in the mix, noise doesn't help.

</Callout>

## Production defaults

| Setting      | Recommended Value  | Notes                        |
| ------------ | ------------------ | ---------------------------- |
| Noise ratio  | 20-30%             | For factual QA               |
| Noise ratio  | 0-10%              | For synthesis/research tasks |
| Position     | Gold at start/end  | Avoid "lost in the middle"   |
| Noise source | Random from corpus | Or anti-correlated retrieval |

**When to apply:**

- Factual QA with clear answers
- Strong LLMs (GPT-4, Claude)
- High-quality gold documents available

**When NOT to apply:**

- Code generation
- Multi-step reasoning
- Weaker models (7B parameter range)
