## Core idea

Based on research from [Barnett et al., 2024](https://arxiv.org/abs/2401.05856), RAG systems fail in **7 predictable ways**. Understanding these helps you debug systematically instead of randomly tweaking parameters.

```
┌─────────────────────────────────────────────────────────────────┐
│                   THE 7 RAG FAILURE POINTS                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  FP1: Missing Content       → Answer not in knowledge base      │
│  FP2: Missed Top Ranks      → Right doc, wrong rank             │
│  FP3: Not in Context        → Retrieved but not used            │
│  FP4: Not Extracted         → In context but LLM missed it      │
│  FP5: Wrong Format          → Right answer, wrong structure     │
│  FP6: Incorrect Specificity → Too vague or too detailed         │
│  FP7: Incomplete Response   → Partial answer only               │
│                                                                  │
│           FP1-2: RETRIEVAL │ FP3-7: GENERATION                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## FP1: Missing Relevant Content

### Symptom

The answer to the user's question **does not exist** in your knowledge base.

### Example

- User asks: "What's the return policy for electronics?"
- Knowledge base only has return policy for clothing.
- System either hallucinates or says "I don't know."

### Diagnosis

```python
def diagnose_fp1(question: str, knowledge_base: list[str]) -> bool:
    """
    Manual check: Can a human find the answer in the KB?
    """
    # Have a human annotator search the KB
    # If they can't find it, it's FP1
    return human_can_find_answer(question, knowledge_base)
```

### Fixes

| Fix                           | When to Use                              |
| ----------------------------- | ---------------------------------------- |
| Expand knowledge base         | Answer should exist but doesn't          |
| Add "I don't know" guardrails | Prevent hallucination on missing content |
| Log unanswerable queries      | Build queue for content creation         |
| Fallback to web search        | For dynamic/current information          |

## FP2: Missed the Top Ranked Documents

### Symptom

The answer **exists** in the knowledge base but wasn't retrieved in top-K results.

### Example

- User asks: "What's the battery life of Product X?"
- Answer is in document #247, but retrieval only returns top 10.
- The correct document ranked at position 50.

### Diagnosis

```python
def diagnose_fp2(question: str, retriever, ground_truth_doc_id: str, k: int = 10) -> dict:
    """
    Check if the correct document is retrieved but ranked too low.
    """
    results = retriever.search(question, top_k=1000)  # Get many results

    for rank, doc in enumerate(results, 1):
        if doc.id == ground_truth_doc_id:
            return {
                "failure_point": "FP2" if rank > k else None,
                "actual_rank": rank,
                "target_k": k,
                "fix": "Improve retrieval" if rank > k else "Retrieval OK"
            }

    return {"failure_point": "FP1", "actual_rank": None}  # Not found at all
```

### Fixes

| Fix                | Impact                                |
| ------------------ | ------------------------------------- |
| Increase top-K     | Quick fix, may add noise              |
| Add reranker       | Reorder results with cross-encoder    |
| Improve embeddings | Fine-tune or switch embedding model   |
| Hybrid search      | Add BM25 for keyword matching         |
| Query expansion    | Reformulate query for better matching |

## FP3: Not in Context (Consolidation Failure)

### Symptom

The correct documents were retrieved, but **not included in the LLM context** due to consolidation.

### Example

- Retriever returns 50 chunks (too many for context).
- Consolidation picks 5 chunks.
- The critical chunk is in the 50 but not the 5.

### Diagnosis

```python
def diagnose_fp3(retrieved_docs: list, context_docs: list, ground_truth_doc_id: str) -> dict:
    """
    Check if the answer was retrieved but dropped during consolidation.
    """
    in_retrieved = any(d.id == ground_truth_doc_id for d in retrieved_docs)
    in_context = any(d.id == ground_truth_doc_id for d in context_docs)

    if in_retrieved and not in_context:
        return {
            "failure_point": "FP3",
            "fix": "Improve consolidation strategy"
        }
    return {"failure_point": None}
```

### Fixes

| Fix                           | Description                          |
| ----------------------------- | ------------------------------------ |
| Better context selection      | Use MMR (Maximal Marginal Relevance) |
| Increase context budget       | If using small context, expand       |
| Hierarchical summarization    | Summarize chunks before context      |
| Prioritize by query relevance | Re-score before consolidation        |

## FP4: Not Extracted (LLM Missed It)

### Symptom

The answer is **in the context**, but the LLM failed to extract it correctly.

### Example

- Context contains: "Return window: 30 days"
- User asks: "How long do I have to return items?"
- LLM says: "I couldn't find the return window."

### Causes

- Too much noise or contradicting information in context
- Answer buried among irrelevant text
- LLM distracted by similar but wrong information

### Diagnosis

```python
def diagnose_fp4(context: str, question: str, expected_answer: str, llm_answer: str) -> dict:
    """
    Human verification: Is the answer clearly in context but LLM missed it?
    """
    answer_in_context = expected_answer.lower() in context.lower()
    llm_correct = expected_answer.lower() in llm_answer.lower()

    if answer_in_context and not llm_correct:
        return {
            "failure_point": "FP4",
            "fix": "Improve prompt or reduce context noise"
        }
    return {"failure_point": None}
```

### Fixes

| Fix                    | Description                          |
| ---------------------- | ------------------------------------ |
| Reduce context noise   | Remove low-relevance chunks          |
| Improve prompting      | Add explicit extraction instructions |
| Use stronger LLM       | GPT-4 extracts better than GPT-3.5   |
| Chain-of-thought       | Ask LLM to reason step-by-step       |
| Highlight key sections | Use markdown/formatting to emphasize |

## FP5: Wrong Format

### Symptom

The answer is correct but in the **wrong format** (not a table, not a list, etc.).

### Example

- User asks: "List the top 5 features as bullet points"
- LLM returns a paragraph instead of bullets.

### Fixes

| Fix                          | Example                       |
| ---------------------------- | ----------------------------- |
| Explicit format instructions | "Return as a numbered list:"  |
| Few-shot examples            | Show desired format in prompt |
| JSON mode                    | Force structured output       |
| Post-processing              | Parse and reformat output     |

---

## FP6: Incorrect Specificity

### Symptom

The answer is **too vague** or **too detailed** for the user's needs.

### Example (Too Vague)

- User: "How do I configure SSL for my server?"
- Answer: "You need to set up certificates." (Not helpful)

### Example (Too Detailed)

- User: "What's Docker?"
- Answer: [5000-word technical deep-dive] (Overwhelming)

### Fixes

| Fix                        | Description                              |
| -------------------------- | ---------------------------------------- |
| User intent classification | Detect if user wants overview vs details |
| Persona-based prompting    | "Explain like I'm a beginner"            |
| Progressive disclosure     | Start high-level, offer to go deeper     |
| Follow-up questions        | Ask user to clarify scope                |

---

## FP7: Incomplete Response

### Symptom

The answer is **correct but missing parts** of what was asked.

### Example

- User: "Summarize documents A, B, and C"
- Answer: Summarizes A and B, completely ignores C.

### Causes

- Multi-part questions are hard for LLMs
- Context too long, later parts lost
- Attention drifts to earlier items

### Fixes

| Fix                 | Description                                |
| ------------------- | ------------------------------------------ |
| Decompose questions | Ask about A, B, C separately, then combine |
| Checklist prompting | "Make sure you cover: A, B, C"             |
| Verify completeness | Ask LLM to check if all parts answered     |
| Map-reduce          | Process each part independently            |

## Failure modes

This entire lesson covers the 7 failure modes. Here's a quick summary for reference:

| Failure Point             | Category   | Quick Fix                    |
| ------------------------- | ---------- | ---------------------------- |
| **FP1** Missing Content   | Retrieval  | Expand KB, add fallbacks     |
| **FP2** Missed Rankings   | Retrieval  | Rerank, hybrid search        |
| **FP3** Not in Context    | Generation | Better consolidation         |
| **FP4** Not Extracted     | Generation | Reduce noise, better prompts |
| **FP5** Wrong Format      | Generation | Format instructions          |
| **FP6** Wrong Specificity | Generation | Intent classification        |
| **FP7** Incomplete        | Generation | Decompose questions          |
