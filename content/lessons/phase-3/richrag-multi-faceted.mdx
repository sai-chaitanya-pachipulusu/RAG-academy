## Core idea

Standard RAG excels at narrow, factual queries but struggles with **broad, multi-faceted questions** like "Tell me about climate change." It typically retrieves documents about ONE aspect, producing incomplete answers.

**RichRAG** handles multi-faceted queries through three components:

1. **Sub-Aspect Explorer**: Identifies different aspects of the query
2. **Multi-Faceted Retriever**: Retrieves documents for each aspect
3. **List-wise Ranker**: Selects diverse, comprehensive document set

### Sub-Aspect Exploration

```python
def explore_sub_aspects(query: str, llm, num_aspects: int = 5) -> list[str]:
    """Discover sub-aspects of a broad query."""
    prompt = f"""Identify {num_aspects} distinct sub-aspects a comprehensive
    answer should cover for: "{query}"

    List each as a brief phrase."""

    response = llm.generate(prompt)
```

### Coverage-Based Selection

Instead of ranking by relevance alone, select documents that **maximize coverage** of all aspects:

```python
def select_diverse_documents(candidates, sub_aspects, k=5):
    """Greedily select docs that maximize aspect coverage."""
    selected = []

    for _ in range(k):
        best_doc = None
        best_marginal_coverage = 0

        for doc in candidates:
            # Calculate additional coverage this doc would add
            marginal = calculate_marginal_coverage(
                selected + [doc], sub_aspects
            )
            if marginal > best_marginal_coverage:
                best_marginal_coverage = marginal
                best_doc = doc

        if best_doc:
            selected.append(best_doc)
            candidates.remove(best_doc)

    return selected
```

## Failure modes

<Callout type="warning" title="Common Pitfalls">
**Aspect explosion**: Too many aspects dilute retrieval quality. Limit to 5-7.

**Aspect overlap**: Similar aspects retrieve duplicate documents. Deduplicate before ranking.

**False multi-faceted detection**: Simple queries get over-decomposed. Add a detection step.

**Latency**: Multiple retrieval calls add latency. Parallelize aspect retrieval.

**Coverage vs relevance**: Over-optimizing coverage may include low-relevance docs.

</Callout>

## Production defaults

| Setting                 | Recommended Value | Notes                     |
| ----------------------- | ----------------- | ------------------------- |
| Max aspects             | 5-7               | Balance coverage vs noise |
| Docs per aspect         | 3-5               | Then deduplicate          |
| Final docs              | 5-10              | Input to generation       |
| Multi-faceted threshold | LLM detection     | Filter simple queries     |

**RichRAG paper results** (WikiPassageQA):

- Standard RAG: ROUGE-L 0.34
- Query Expansion: ROUGE-L 0.37
- **RichRAG: ROUGE-L 0.44**

**When to use RichRAG:**

- Open-ended exploratory questions
- Research and learning queries
- "Tell me about X" style queries
- Comparison and analysis requests
