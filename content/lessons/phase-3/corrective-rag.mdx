## Core idea

Standard RAG assumes retrieved documents are relevant. But retrieval often fails silently—the LLM receives irrelevant context and hallucinates.

**CRAG (Corrective RAG)** adds a retrieval evaluator that:

1. **Assesses document relevance** with a confidence score
2. **Triggers corrective actions** based on confidence level
3. **Falls back to web search** for low-confidence retrievals

### Three-Action System

| Confidence  | Action    | Behavior                               |
| ----------- | --------- | -------------------------------------- |
| **> 0.7**   | CORRECT   | Use retrieved docs, refine to key info |
| **0.3–0.7** | AMBIGUOUS | Augment with additional sources + web  |
| **< 0.3**   | INCORRECT | Abandon local retrieval, use web only  |

### Implementation

```python
from enum import Enum

class Action(Enum):
    CORRECT = "correct"
    AMBIGUOUS = "ambiguous"
    INCORRECT = "incorrect"

def evaluate_retrieval(query: str, docs: list, relevance_scores: list) -> tuple:
    """Determine action based on max relevance score."""
    if not relevance_scores:
        return Action.INCORRECT, 0.0

    max_score = max(relevance_scores)

    if max_score > 0.7:
        return Action.CORRECT, max_score
    elif max_score >= 0.3:
        return Action.AMBIGUOUS, max_score
    else:
        return Action.INCORRECT, max_score

def crag_retrieve(query: str, retriever, web_searcher, evaluator):
    """Complete CRAG pipeline."""
    # Step 1: Initial retrieval
    docs = retriever.retrieve(query, k=5)
    scores = [evaluator.score(query, doc) for doc in docs]

    # Step 2: Evaluate confidence
    action, confidence = evaluate_retrieval(query, docs, scores)

    # Step 3: Take corrective action
    if action == Action.CORRECT:
        return refine_documents(docs, query)
    elif action == Action.AMBIGUOUS:
        web_docs = web_searcher.search(query)
        return docs + web_docs
    else:
        return web_searcher.search(query)
```

### Decompose-Then-Recompose

For CORRECT action, CRAG refines documents by extracting only relevant sentences:

```python
def decompose_recompose(doc: str, query: str, llm) -> str:
    """Extract only the relevant portions of a document."""
    # Decompose into atomic facts
    facts = llm.extract_facts(doc)

    # Filter relevant facts
    relevant = [f for f in facts if llm.is_relevant(f, query)]

    # Recompose
    return " ".join(relevant)
```

## Failure modes

<Callout type="warning" title="Common Pitfalls">
**Evaluator hallucinations**: The relevance evaluator itself can be wrong—validate with human labels.

**Web search latency**: Web fallback adds 500ms-2s latency. Cache frequent queries.

**Rate limiting**: Web search APIs have rate limits. Implement backoff and caching.

**Threshold sensitivity**: The 0.3/0.7 thresholds may not work for all domains—tune with evaluation data.

**Cascading errors**: If web search also returns irrelevant results, the system has no fallback.

</Callout>

## Production defaults

| Setting        | Recommended Value | Notes                                        |
| -------------- | ----------------- | -------------------------------------------- |
| High threshold | 0.7               | Tune based on your evaluator's calibration   |
| Low threshold  | 0.3               | Below this, local retrieval is unreliable    |
| Web search K   | 5                 | Balance coverage vs. noise                   |
| Evaluator      | Cross-encoder     | ms-marco-MiniLM-L-12-v2 is fast and accurate |
| Cache TTL      | 1 hour            | For web search results                       |
