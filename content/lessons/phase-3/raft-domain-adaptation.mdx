## Core idea

General-purpose LLMs struggle with domain-specific RAG because they don't know **how to use** retrieved documents effectively. RAFT teaches the model to:

1. **Identify relevant documents** among distractors
2. **Extract key information** with chain-of-thought reasoning
3. **Cite sources** in responses

### The Study Analogy

Standard RAG is like taking an open-book exam without studying—you have access to the textbook but don't know how to find answers quickly.

**RAFT teaches the model HOW to use the book.**

### Training Data Format

Each training example includes:

- **Question**: The query to answer
- **Oracle document**: Contains the answer (included ~80% of the time)
- **Distractor documents**: Related but don't answer the question
- **Answer**: Chain-of-thought reasoning with citations

```python
def create_raft_example(qa_pair, corpus, retriever, num_distractors=4):
    question = qa_pair["question"]
    answer = qa_pair["answer"]
    oracle_doc = qa_pair["oracle_doc"]

    # Get distractors (similar but not answering)
    retrieved = retriever.retrieve(question, k=num_distractors + 5)
    distractors = [d for d in retrieved if d.content != oracle_doc][:num_distractors]

    # Include oracle 80% of the time
    include_oracle = random.random() < 0.8

    if include_oracle:
        context_docs = [oracle_doc] + [d.content for d in distractors]
    else:
        context_docs = [d.content for d in distractors]

    random.shuffle(context_docs)

    # Format with chain-of-thought answer
    return {
        "instruction": format_instruction(question, context_docs),
        "output": f"Based on Document X, ... ##Final answer##"
    }
```

### Chain-of-Thought Format

Answers should include reasoning and citations:

```text
Looking at Document 2, it states that "Premium users get 1000 requests
per minute." This is 10x higher than the free tier mentioned in
Document 1. ##1000 requests per minute##
```

## Failure modes

<Callout type="warning" title="Common Pitfalls">
**Overfitting to format**: If all training examples have the same structure, the model may fail on variations.

**Distractor leakage**: Distractors that accidentally contain partial answers corrupt training.

**Oracle dependency**: Without the 20% no-oracle examples, the model can't handle "unanswerable" queries.

**Domain shift**: Training on one domain may not transfer to related domains.

**Quality of QA pairs**: Poor question-answer pairs lead to poor fine-tuning.

</Callout>

## Production defaults

| Setting            | Recommended Value | Notes                                           |
| ------------------ | ----------------- | ----------------------------------------------- |
| Oracle probability | 0.7–0.9           | Higher = better with oracle, lower = robustness |
| Num distractors    | 3–5               | More = harder task, more robust model           |
| QA pairs per doc   | 3–5               | Balance coverage vs. training time              |
| Fine-tuning epochs | 2–4               | Monitor for overfitting                         |
| Learning rate      | 1e-5 to 5e-5      | Standard for instruction tuning                 |

**RAFT paper results** (domain-specific benchmarks):

- Llama-7B + RAG: 58.2%
- GPT-4 + RAG: 78.4%
- **Llama-7B + RAFT: 71.8%** (nearly GPT-4 level!)

**When to use RAFT:**

- High-stakes domains (medical, legal, financial)
- Consistent document formats (APIs, manuals)
- 100+ domain documents available
- Performance > cost trade-off
