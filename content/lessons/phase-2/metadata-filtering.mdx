## Core idea

### Why metadata filtering matters

Without filtering, every query searches your **entire corpus**. With filtering:
- **Faster**: Search smaller subset
- **More relevant**: Exclude irrelevant documents
- **Multi-tenant safe**: Enforce access control

### Metadata schema design

```python
# Good metadata schema
{
    # Identity
    "doc_id": "doc_123",
    "chunk_id": "doc_123_chunk_5",
    
    # Access control (CRITICAL)
    "tenant_id": "acme_corp",
    "access_level": "internal",
    
    # Structure
    "doc_type": "policy",
    "section": "security",
    "page": 5,
    
    # Temporal
    "created_at": "2024-01-15",
    "effective_date": "2024-02-01",
    "expires_at": "2025-01-15",
    
    # Quality
    "language": "en",
    "confidence": 0.95,
    
    # Custom
    "product": "api_gateway",
    "region": "us-east-1",
}
```

### Filter-first vs filter-after

| Approach | Speed | Recall | Use When |
|----------|-------|--------|----------|
| **Filter-first** | Fast | Lower | User specifies clear scope |
| **Filter-after** | Slow | Higher | Unsure what user wants |
| **Hybrid** | Medium | High | Production default |

```python
# Filter-first (faster, less recall)
results = vector_db.query(
    vector=query_embedding,
    filter={"tenant_id": "acme", "doc_type": "policy"},
    top_k=10
)

# Filter-after (slower, more recall)
results = vector_db.query(
    vector=query_embedding,
    top_k=100
)
results = [r for r in results if r.metadata["tenant_id"] == "acme"]

# Hybrid (balance)
results = vector_db.query(
    vector=query_embedding,
    filter={"tenant_id": "acme"},  # Hard filter
    top_k=50
)
# Then soft-filter/rerank by doc_type
```

### Query routing

Route different queries to different retrieval strategies:

```python
class QueryRouter:
    def route(self, query: str) -> Dict:
        """
        Route query to appropriate retrieval strategy.
        """
        # Extract intent
        intent = self.classify_intent(query)
        
        if intent == "lookup":
            # Exact match needed
            return {
                "strategy": "bm25_only",
                "index": "keyword_index",
                "filters": self.extract_filters(query)
            }
        
        elif intent == "comparison":
            # Multiple retrievals needed
            return {
                "strategy": "multi_query",
                "index": "hybrid_index",
                "decompose": True
            }
        
        elif intent == "recent":
            # Time-sensitive
            return {
                "strategy": "hybrid",
                "index": "main_index",
                "filters": {"date_after": self.get_recent_date()},
                "boost": {"recency": 1.5}
            }
        
        else:
            # Default semantic search
            return {
                "strategy": "hybrid",
                "index": "main_index"
            }
    
    def classify_intent(self, query: str) -> str:
        # Simple keyword-based classification
        if any(w in query.lower() for w in ["latest", "recent", "new", "today"]):
            return "recent"
        if any(w in query.lower() for w in ["compare", "vs", "difference"]):
            return "comparison"
        if any(w in query.lower() for w in ["error code", "id:", "ticket #"]):
            return "lookup"
        return "semantic"
```

### Multi-index routing

Different indexes for different content:

```python
INDEX_REGISTRY = {
    "code": {
        "index": "code_index",
        "embedding_model": "code-embedding-model",
        "chunking": "ast_based",
    },
    "docs": {
        "index": "docs_index", 
        "embedding_model": "text-embedding-3-small",
        "chunking": "markdown_aware",
    },
    "support": {
        "index": "support_index",
        "embedding_model": "text-embedding-3-small",
        "chunking": "conversation_aware",
    },
}

def route_to_index(query: str) -> str:
    """Route query to appropriate index."""
    if any(kw in query.lower() for kw in ["code", "function", "class", "import"]):
        return "code"
    if any(kw in query.lower() for kw in ["ticket", "support", "help"]):
        return "support"
    return "docs"
```

## Failure modes

1. **No tenant isolation**: Security vulnerability.
2. **Over-filtering**: Miss relevant results.
3. **Under-filtering**: Search too much, slow + noisy.
4. **Stale metadata**: Filters based on outdated info.
5. **Filter explosion**: Too many filter dimensions.

## Production defaults

- **Always filter by tenant** (non-negotiable for multi-tenant).
- **Log filter usage** for debugging and optimization.
- **Self-query for complex queries** only (adds latency).
- **Index per content type** if content is heterogeneous.
