## Goals

- Build the smallest RAG loop that still teaches correct production instincts.
- Learn the “grounded answer” rule: cite evidence or refuse.
- Understand what to add next (hybrid retrieval, reranking, eval).

## Prereqs

- Read: **Why RAG Exists**, **Embedding Fundamentals**, **Tokenizers & Context**, **Chunking 101**.

## Core idea

### The minimal RAG pipeline

Even “hello world RAG” has the same structure as production:

1. Prepare chunks (+ optional metadata)
2. Retrieve top-k chunks for a query
3. Build a prompt that forces grounding

<Callout title="RAG is a retrieval system first" variant="info">
  If the <strong>right evidence</strong> isn’t in your top‑k, no amount of prompt engineering will save you.
  Treat retrieval quality as an engineering problem: log it, measure it, iterate it.
</Callout>

## Failure modes

- **Wrong evidence in top‑k**: the model answers confidently using irrelevant chunks.
- **Over-retrieval**: too many chunks → lost-in-the-middle → model ignores the key line.
- **Prompt injection**: retrieved content contains instructions → the model follows them unless you treat sources as untrusted.

## Production defaults

- Retrieval: **hybrid + RRF** → rerank candidates → keep 5–10.
- Context shaping: dedupe, token budget, attention-aware ordering.
- Grounding: citations by chunk id; refusal if evidence is missing.
