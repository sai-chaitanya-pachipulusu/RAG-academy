## Goals

- Learn how to navigate the platform without getting lost.
- Internalize the “build order”: fundamentals → retrieval → rerank → safety → eval → harden.
- Treat challenges as the primary learning unit.

## Prereqs

None.

## Core idea

We optimize for **production competence**, not passive watching:

- **Code-first**: every concept has a challenge.
- **Failure-mode driven**: you’ll learn why systems break, not just the “happy path”.
- **From scratch → production**: implement the core algorithm, then learn the real-world constraints.

The learning loop:

1. **Learn** the concept (short lesson)
2. **Build** the primitive (challenge)
3. **Measure** (tests + later: retrieval metrics + groundedness checks)
4. **Iterate** (hints + debugging tools)

## Failure modes

- **Reading without building**: you will *feel* like you understand but won’t be able to debug real systems.
- **Random technique hopping**: you’ll collect methods without knowing when to use them.
- **Skipping measurement**: you’ll “improve” the system without knowing if it got better.

## Production defaults

- Follow the Study Plan for the default sequence: baseline retrieval → hybrid → rerank → context shaping → safety → eval.
- Use Compare pages when you’re stuck choosing between tools/techniques.
