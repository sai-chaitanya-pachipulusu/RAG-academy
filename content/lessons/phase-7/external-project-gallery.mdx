## 📚 Reference Architectures

### Microsoft GraphRAG

- **Repository**: [microsoft/graphrag](https://github.com/microsoft/graphrag)
- **Key Concept**: Knowledge graph + community detection + summarization
- **When to Use**: Multi-hop reasoning, thematic synthesis, relationship discovery

### RAGAS Evaluation

- **Repository**: [explodinggradients/ragas](https://github.com/explodinggradients/ragas)
- **Key Concept**: RAG Triad (Faithfulness, Relevancy, Context Recall)
- **When to Use**: Automated RAG evaluation at scale

### LangChain RAG

- **Documentation**: [LangChain RAG Tutorial](https://python.langchain.com/docs/tutorials/rag/)
- **Key Concept**: Modular RAG components
- **When to Use**: Quick prototyping, framework-based development

### LlamaIndex

- **Documentation**: [LlamaIndex RAG docs](https://docs.llamaindex.ai/)
- **Key Concept**: Index-centric RAG with multiple index types
- **When to Use**: Complex document structures, property graphs

## Production defaults

### Recommended Stack Pattern

Based on these projects, the consensus stack for 2024/2025:

- **Orchestration**: LangChain or LlamaIndex
- **Vector DB**: Qdrant or Pinecone (Serverless)
- **Model**: GPT-4o (Reasoning) or Llama 3 (Local)
- **Deployment**: Vercel (Frontend) + FastAPI (Backend)

## Failure modes

### 1. Stale Dependencies

Open source projects rot quickly. **Always check `requirements.txt` or `package.json` for versions.**

### 2. Missing Auth

Many prototypes skip authentication. **Do not deploy to production without adding Auth0/Supabase/NextAuth.**

### 3. Rate Limit Naivety

Most demos don't handle 429 errors. **Add exponential backoff before using in production.**
