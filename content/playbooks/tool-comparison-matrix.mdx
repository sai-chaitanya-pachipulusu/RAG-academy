| ColBERT v2         | Stanford | Excellent | ~50ms   | Free (self-host) |

### When to Rerank

- ✅ High-stakes applications (legal, medical)
- ✅ Complex queries requiring deep understanding
- ✅ When you have latency budget (100-300ms)
- ✅ When base retrieval recall is high but precision is low
- ❌ Simple keyword queries
- ❌ Latency-critical applications (<500ms total)

## RAG Frameworks

| Framework       | Language  | Strengths                   | Weaknesses               |
| --------------- | --------- | --------------------------- | ------------------------ |
| LangChain       | Python/JS | Most features, integrations | Complexity, abstractions |
| LlamaIndex      | Python    | Document handling, indices  | Steeper learning curve   |
| Haystack        | Python    | Production-ready, pipelines | Less flexible            |
| Semantic Kernel | C#/Python | Microsoft ecosystem         | Fewer integrations       |
| RAGFlow         | Python    | End-to-end, UI included     | Newer, less mature       |

### When to Use

| Scenario             | Recommended           |
| -------------------- | --------------------- |
| Rapid prototyping    | LangChain, LlamaIndex |
| Document-heavy RAG   | LlamaIndex            |
| Production pipelines | Haystack              |
| Microsoft stack      | Semantic Kernel       |
| Simple use cases     | Build custom          |
