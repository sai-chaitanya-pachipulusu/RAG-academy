# Recursive Retrieval

Implement hierarchical two-stage retrieval that first matches document summaries, then expands to retrieve granular chunks for detailed answers.

## The Problem

If you have 1 million chunks, your retriever might miss the forest for the trees. **Recursive Retrieval** solves this by creating a hierarchy:

1. **Summarize** groups of chunks (e.g., a whole page or section)
2. **Index the summaries** for fast high-level search
3. **Retrieve the best summary**
4. **Expand** it into the raw chunks associated with that summary

This is excellent for questions like _"What does the Q3 report say about revenue?"_ where a single chunk might not capture the full "revenue" context, but the section summary does.

## Your Task

Implement a `RecursiveRetriever` class:

## Algorithm Details

### Stage 1: Summary Retrieval

```python
def retrieve_summaries(self, query: str, k: int = 3) -> list[dict]:
    """Retrieve top-k summaries."""
    query_embedding = self.embedder.encode(query)
    
    # Search summary index
    results = self.summary_index.search(query_embedding, k=k)
    
    return [
        {
            "id": r.id,
            "content": r.content,
            "score": r.score,
            "metadata": r.metadata
        }
        for r in results
    ]
```

### Stage 2: Expansion

```python
def expand_summary(self, summary_id: str, 
                   filter_query: str = None) -> list[str]:
    """Get chunks for a summary, optionally filtered."""
    chunks = self.chunk_store.get(summary_id, [])
    
    if filter_query and len(chunks) > 10:
        # Rerank chunks by relevance to filter_query
        embeddings = self.embedder.encode(chunks)
        query_emb = self.embedder.encode(filter_query)
        
        scores = cosine_similarity([query_emb], embeddings)[0]
        ranked = sorted(zip(chunks, scores), key=lambda x: x[1], reverse=True)
        
        # Return top chunks
        return [c for c, _ in ranked[:10]]
    
    return chunks
```

### Full Pipeline

```python
def retrieve(self, query: str, k_summaries: int = 3,
             k_chunks_per_summary: int = 5) -> list[str]:
    """Two-stage retrieval."""
    # Stage 1: Get summaries
    summaries = self.retrieve_summaries(query, k=k_summaries)
    
    # Stage 2: Expand each summary
    all_chunks = []
    for summary in summaries:
        chunks = self.expand_summary(
            summary["id"], 
            filter_query=query
        )
        all_chunks.extend(chunks[:k_chunks_per_summary])
    
    return all_chunks
```

### With Cross-Summary Reranking

```python
def retrieve_with_rerank(self, query: str, k: int = 10) -> list[str]:
    """Retrieve from multiple summaries and rerank."""
    # Get more summaries initially
    summaries = self.retrieve_summaries(query, k=5)
    
    # Expand all (with higher limit)
    all_chunks = []
    for summary in summaries:
        chunks = self.expand_summary(summary["id"])
        all_chunks.extend(chunks)
    
    # Deduplicate
    seen = set()
    unique_chunks = []
    for chunk in all_chunks:
        if chunk not in seen:
            seen.add(chunk)
            unique_chunks.append(chunk)
    
    # Rerank all chunks
    chunk_embeddings = self.embedder.encode(unique_chunks)
    query_embedding = self.embedder.encode(query)
    
    scores = cosine_similarity([query_embedding], chunk_embeddings)[0]
    ranked = sorted(zip(unique_chunks, scores), key=lambda x: x[1], reverse=True)
    
    return [chunk for chunk, _ in ranked[:k]]
```

## Evaluation Criteria

1. **Summary Precision**: Retrieved summaries are relevant
2. **Expansion Quality**: Chunks match the summary
3. **Overall Recall**: Final chunks answer the query
4. **Efficiency**: Faster than flat search on large collections

## Comparison: Flat vs Recursive Retrieval

| Aspect | Flat | Recursive |
|--------|------|-----------|
| Index Size | O(N) chunks | O(N/c) summaries + chunks |
| Query Time | O(N) comparisons | O(N/c) + O(k×c) |
| Precision | Lower | Higher (filtered by summary) |
| Recall | Good | Better (broader summary match) |
| Storage | Lower | Higher (2x for summaries) |

Where N = total chunks, c = chunks per summary, k = summaries retrieved

## Production Considerations

1. **Summary Quality**: Invest in good summarization
2. **Chunk Mapping**: Maintain reliable summary→chunk links
3. **Expansion Limits**: Cap chunks per summary to control latency
4. **Caching**: Cache summary retrievals
5. **Hybrid**: Combine with flat retrieval for best results
