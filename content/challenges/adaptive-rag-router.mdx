# Adaptive RAG Router

Not all queries need the same treatment. A simple lookup like "What's the return policy?" doesn't need multi-step reasoning, while "Compare our Q1 and Q2 performance and explain the trends" requires iterative retrieval.

**Your task**: Build a router that classifies queries and routes them to the appropriate RAG strategy.

## Hints

<details>
<summary>Hint 1: Rule-based patterns</summary>

Common patterns for each complexity:
- **NO_RETRIEVAL**: Math (`\d+ [+\-*/] \d+`), greetings (`^(hi|hello)`)
- **COMPLEX**: Comparisons (`compare.*and`), analysis (`explain.*trend`)
- **AMBIGUOUS**: Very short queries, pronouns without context

</details>

<details>
<summary>Hint 2: Hybrid approach</summary>

Use rules for high-confidence cases, LLM for uncertain ones:

```python
def classify_query(self, query: str) -> QueryComplexity:
    # Try rules first (fast)
    rule_result = self._rule_based_classify(query)
    if rule_result is not None:
        return rule_result
    
    # Fall back to LLM (slower but accurate)
    return self._llm_classify(query)
```

</details>

def test_router():
    # Mock RAG functions for testing
    def simple_rag(q): return f"[SIMPLE] Answer for: {q}"
    def complex_rag(q): return f"[COMPLEX] Answer for: {q}"
    def direct_llm(q): return f"[DIRECT] Answer for: {q}"
    def rewrite_rag(q): return f"[REWRITE] Answer for: {q}"
    
    router = AdaptiveRAGRouter(simple_rag, complex_rag, direct_llm, rewrite_rag)
    
    correct = 0
    for query, expected in TEST_QUERIES:
        result = router.classify_query(query)
        if result.value == expected:
            correct += 1
            print(f"✓ '{query}' → {result.value}")
        else:
            print(f"✗ '{query}' → {result.value} (expected {expected})")
    
    accuracy = correct / len(TEST_QUERIES)
    print(f"\nAccuracy: {accuracy:.0%}")
    assert accuracy >= 0.75, f"Accuracy {accuracy:.0%} below 75% threshold"
    print("All tests passed!")

test_router()
