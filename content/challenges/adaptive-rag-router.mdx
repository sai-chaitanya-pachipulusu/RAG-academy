<Callout title="Goal" variant="info">
  Build a query router that dynamically selects the optimal RAG strategy based on query complexity.
</Callout>

Not all queries need the same treatment. A simple lookup like "What's the return policy?" doesn't need multi-step reasoning, while "Compare our Q1 and Q2 performance and explain the trends" requires iterative retrieval.

## Complexity Analysis

| Strategy | Time | Cost | Use Case |
|----------|------|------|----------|
| Direct LLM | ~500ms | Low | Factual questions |
| Simple RAG | ~1-2s | Medium | Document lookup |
| Complex RAG | ~5-10s | High | Multi-hop reasoning |
| Rewrite RAG | ~2-4s | Medium | Ambiguous queries |

```python
from enum import Enum
from typing import Callable, Dict, List, Optional
import re

class QueryComplexity(Enum):
    """Query complexity levels for routing decisions."""
    NO_RETRIEVAL = "no_retrieval"  # LLM can answer directly
    SIMPLE = "simple"               # Single retrieval pass
    COMPLEX = "complex"             # Multi-step reasoning
    AMBIGUOUS = "ambiguous"         # Needs clarification


class AdaptiveRAGRouter:
    """
    Router that classifies queries and routes to appropriate RAG strategy.
    
    Strategies:
    - Direct LLM: For factual/math questions
    - Simple RAG: Single retrieval for document lookup
    - Complex RAG: Multi-step for analysis/comparison
    - Rewrite RAG: For ambiguous/unclear queries
    """
    
    def __init__(
        self,
        simple_rag: Callable[[str], str],
        complex_rag: Callable[[str], str],
        direct_llm: Callable[[str], str],
        rewrite_rag: Callable[[str], str]
    ):
        """
        Initialize router with different RAG strategies.
        
        Args:
            simple_rag: Fast single-retrieval RAG
            complex_rag: Multi-step reasoning RAG
            direct_llm: Direct LLM call (no retrieval)
            rewrite_rag: Rewrite query then RAG
        """
        self.simple_rag = simple_rag
        self.complex_rag = complex_rag
        self.direct_llm = direct_llm
        self.rewrite_rag = rewrite_rag
        
        # Pattern definitions
        self.math_pattern = re.compile(r'\d+\s*[+\-*/]\s*\d+')
        self.greeting_pattern = re.compile(r'^(hi|hello|hey|greetings)\b', re.I)
        self.comparison_pattern = re.compile(r'\b(compare|vs|versus|difference|similarities)\b', re.I)
        self.analysis_pattern = re.compile(r'\b(analyze|explain|why|how does|trend)\b', re.I)
    
    def classify_query(self, query: str) -> QueryComplexity:
        """
        Classify query complexity using rules and heuristics.
        
        Returns:
            QueryComplexity enum value
        """
        query_lower = query.lower().strip()
        
        # Rule 1: Math problems → Direct LLM
        if self.math_pattern.search(query):
            return QueryComplexity.NO_RETRIEVAL
        
        # Rule 2: Greetings → Direct LLM
        if self.greeting_pattern.match(query):
            return QueryComplexity.NO_RETRIEVAL
        
        # Rule 3: Very short queries → Ambiguous
        if len(query_lower.split()) <= 2:
            return QueryComplexity.AMBIGUOUS
        
        # Rule 4: Comparisons or analysis → Complex
        if self.comparison_pattern.search(query) or self.analysis_pattern.search(query):
            return QueryComplexity.COMPLEX
        
        # Rule 5: Simple lookups → Simple
        lookup_patterns = [
            r'\b(what is|what are|who is|when|where|how do i|how to)\b',
            r'\b(return policy|password|login|contact|price|cost)\b'
        ]
        for pattern in lookup_patterns:
            if re.search(pattern, query_lower):
                return QueryComplexity.SIMPLE
        
        # Default: Simple RAG
        return QueryComplexity.SIMPLE
    
    def route(self, query: str) -> str:
        """
        Route query to appropriate RAG strategy and return answer.
        
        Args:
            query: User query
        
        Returns:
            Generated answer from selected strategy
        """
        complexity = self.classify_query(query)
        
        if complexity == QueryComplexity.NO_RETRIEVAL:
            return self.direct_llm(query)
        elif complexity == QueryComplexity.SIMPLE:
            return self.simple_rag(query)
        elif complexity == QueryComplexity.COMPLEX:
            return self.complex_rag(query)
        elif complexity == QueryComplexity.AMBIGUOUS:
            return self.rewrite_rag(query)
        
        # Fallback
        return self.simple_rag(query)
    
    def route_with_metrics(self, query: str) -> Dict:
        """
        Route query and return answer with metrics.
        
        Returns:
            Dict with answer, complexity, and timing
        """
        import time
        
        start = time.time()
        complexity = self.classify_query(query)
        
        if complexity == QueryComplexity.NO_RETRIEVAL:
            answer = self.direct_llm(query)
            retrieval_calls = 0
        elif complexity == QueryComplexity.SIMPLE:
            answer = self.simple_rag(query)
            retrieval_calls = 1
        elif complexity == QueryComplexity.COMPLEX:
            answer = self.complex_rag(query)
            retrieval_calls = 3  # Estimated
        elif complexity == QueryComplexity.AMBIGUOUS:
            answer = self.rewrite_rag(query)
            retrieval_calls = 2
        else:
            answer = self.simple_rag(query)
            retrieval_calls = 1
        
        latency_ms = (time.time() - start) * 1000
        
        return {
            "answer": answer,
            "complexity": complexity.value,
            "latency_ms": latency_ms,
            "retrieval_calls": retrieval_calls
        }
```

## Best Practices

1. **Hybrid approach**: Use rules for high-confidence, LLM for edge cases
2. **Monitor accuracy**: Track classification correctness
3. **Fallback gracefully**: Default to simple RAG when uncertain
4. **Latency awareness**: Track timing for each path
5. **Cost tracking**: Monitor spend per complexity level

## Production Tips

- Start with rule-based classification
- Add LLM fallback for uncertain cases
- A/B test different routing strategies
- Monitor per-path metrics (latency, cost, quality)
