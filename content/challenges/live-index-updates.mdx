# Live Index Updates

Implement real-time vector index updates without service downtime.

## The Production Challenge

Data never stops flowing—documents update, users edit content, knowledge evolves. Traditional batch reindexing causes:

- **Stale knowledge**: Hours/days of outdated information
- **Downtime**: Service interruption during rebuilds
- **Resource spikes**: Bursty CPU/memory during batch jobs

**Your task**: Build a live indexing system that handles updates in real-time while maintaining search availability.

## Why Live Updates Matter

| Scenario | Without Live Updates | With Live Updates |
|----------|---------------------|-------------------|
| News RAG | 30-min delay on breaking news | Instant availability |
| Support tickets | Stale status replies | Real-time ticket state |
| Code documentation | Outdated API docs | Latest changes reflected |
| Financial data | Delayed market info | Real-time prices |

### Real-World Systems

- **Pinecone**: Metadata updates in milliseconds
- **Weaviate**: Async indexing with eventual consistency
- **Qdrant**: WAL-based persistence for durability
- **Milvus**: Timestamp-based MVCC

## Theoretical Foundation

### Version-Based Concurrency Control

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Writer T1  │     │  Writer T2  │     │   Reader    │
│  v=1, ts=10 │     │  v=2, ts=20 │     │  ts=15      │
└──────┬──────┘     └──────┬──────┘     └──────┬──────┘
       │                   │                   │
       ▼                   ▼                   ▼
┌─────────────────────────────────────────────────────┐
│                    Document Store                     │
├─────────────────────────────────────────────────────┤
│  doc_001: [(v=1, ts=10, vec=[...]),                 │
│           (v=2, ts=20, vec=[...]), marked_active]   │
├─────────────────────────────────────────────────────┤
│  Reader at ts=15 sees v=1 (snapshot isolation)       │
│  New readers at ts>20 see v=2                        │
└─────────────────────────────────────────────────────┘
```

Each update creates a new version; readers see consistent snapshots.

### Thread Safety Patterns

```
Single Writer, Multiple Readers (SWMR):
┌────────────────────────────────────────┐
│         Vector Index (Read-Mostly)      │
├────────────────────────────────────────┤
│  ┌─────────┐    ┌─────────────────┐    │
│  │  Read   │◄───│   Read Lock     │    │
│  │  Path   │    │   (Shared)      │    │
│  │ (99.9%) │    └─────────────────┘    │
│  └────┬────┘           ▲                │
│       │               │                │
│       ▼               │                │
│  ┌─────────┐    ┌───────────────┐      │
│  │  Write  │───►│  Write Lock   │      │
│  │  Path   │    │  (Exclusive)  │      │
│  │ (0.1%)  │    └───────────────┘      │
│  └─────────┘                            │
└────────────────────────────────────────┘
```

## Example Usage

```python
# Create index
index = LiveVectorIndex(dimension=3)

# Track updates via callback
updates_received = []
def on_update(doc):
    updates_received.append(doc)
index.register_callback(on_update)

# Insert documents
doc1 = index.upsert("doc1", [1.0, 0.0, 0.0], "First document")
doc2 = index.upsert("doc2", [0.0, 1.0, 0.0], "Second document")

# Update creates new version
doc1_v2 = index.upsert("doc1", [0.9, 0.1, 0.0], "Updated first document")

# Search (no deleted docs)
results = index.search([1.0, 0.0, 0.0], k=2)
print(f"Found {len(results)} results")

# Delete (soft)
index.delete("doc2")

# Verify deletion
doc2_latest = index.get("doc2")
print(f"doc2 deleted: {doc2_latest.deleted if doc2_latest else 'not found'}")

# Stats
stats = index.get_stats()
print(f"Total versions: {stats['total_versions']}")
print(f"WAL entries: {stats['wal_entries']}")
```

## Concurrency Test

```python
import threading
import random

def test_concurrent_access():
    """Test thread safety with concurrent readers and writers."""
    index = LiveVectorIndex(dimension=3)
    errors = []
    
    # Writer thread
    def writer():
        for i in range(100):
            try:
                index.upsert(f"doc_{i%20}", 
                           [random.random() for _ in range(3)],
                           f"Content {i}")
                time.sleep(0.001)
            except Exception as e:
                errors.append(f"Write error: {e}")
    
    # Reader thread
    def reader():
        for i in range(200):
            try:
                results = index.search([1.0, 0.0, 0.0], k=5)
                time.sleep(0.0005)
            except Exception as e:
                errors.append(f"Read error: {e}")
    
    # Run concurrently
    threads = [
        threading.Thread(target=writer),
        threading.Thread(target=writer),
        threading.Thread(target=reader),
        threading.Thread(target=reader),
        threading.Thread(target=reader),
    ]
    
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    
    assert len(errors) == 0, f"Errors: {errors}"
    print(f"✅ Concurrent test passed!")
    print(f"   Final stats: {index.get_stats()}")

test_concurrent_access()
```

## Real-World Considerations

### Production Vector DB Architectures

| Database | Update Strategy | Consistency | Notes |
|----------|----------------|-------------|-------|
| **Pinecone** | Async metadata | Eventual | Fast metadata, async vector |
| **Weaviate** | Async indexing | Eventual | Background HNSW updates |
| **Qdrant** | WAL + segments | Strong | Segment-based immutability |
| **Milvus** | MVCC | Snapshot | Timestamp-based isolation |
| **pgvector** | PostgreSQL ACID | Strong | Full transactional safety |

### Performance Trade-offs

```
Update Latency vs Query Performance:

Strong Consistency (pgvector, some configs):
├── Writes: 10-50ms (transaction overhead)
├── Reads: 1-5ms
└── Best for: Financial, healthcare, compliance

Eventual Consistency (Pinecone, Weaviate):
├── Writes: <1ms (async)
├── Reads: <10ms
└── Best for: Search, recommendations, content

Custom Hybrid (Milvus, Qdrant):
├── Writes: 5-20ms (buffered)
├── Reads: 2-10ms
└── Best for: Balanced workloads
```
