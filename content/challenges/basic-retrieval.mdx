  Implement Top‑K retrieval: score candidates and return the best k.

## Why this matters in production

Every retrieval system (BM25, dense, hybrid) eventually produces:

- a ranked list of candidates

If you can't implement Top‑K correctly, you can't trust your evaluation or debug ranking issues.

## What you're implementing

Given:

- `vectors: List[List[float]]` (document vectors)
- `query: List[float]`

Return:

- `[(doc_index, score), ...]` sorted by score descending

Rules:

- validate `k > 0`
- if `k > len(vectors)` return all

## The Algorithm

```python
def top_k_retrieval(
    vectors: list[list[float]],
    query: list[float],
    k: int,
    score_fn: callable
) -> list[tuple[int, float]]:
    """
    Retrieve top-k documents by similarity score.
    
    Time Complexity: O(N × d + N log k) where N = docs, d = dimension
    Space Complexity: O(N) for scores, O(k) for heap
    
    Args:
        vectors: Document vectors
        query: Query vector
        k: Number of results to return
        score_fn: Function to compute similarity (e.g., cosine_similarity)
        
    Returns:
        List of (doc_index, score) tuples, sorted by score descending
        
    Raises:
        ValueError: If k <= 0
    """
    if k <= 0:
        raise ValueError("k must be positive")
    
    # Score all documents
    scores = [(i, score_fn(vec, query)) for i, vec in enumerate(vectors)]
    
    # Sort by score descending
    scores.sort(key=lambda x: x[1], reverse=True)
    
    # Return top k
    return scores[:k]
```

## Complexity Analysis

| Aspect | Complexity | Notes |
|--------|------------|-------|
| Scoring | O(N × d) | N docs × d dimensions |
| Sorting | O(N log N) | Standard sort |
| With heap | O(N log k) | More efficient for small k |
| Space | O(N) | Store all scores |

## Optimization: Using a Heap

For large N and small k, use a heap for O(N log k) instead of O(N log N):

```python
import heapq

def top_k_heap(vectors, query, k, score_fn):
    """O(N log k) retrieval using min-heap."""
    # Use negative scores for max-heap behavior
    heap = []
    
    for i, vec in enumerate(vectors):
        score = score_fn(vec, query)
        
        if len(heap) < k:
            heapq.heappush(heap, (score, i))
        elif score > heap[0][0]:
            heapq.heapreplace(heap, (score, i))
    
    # Return sorted by score descending
    return sorted([(i, s) for s, i in heap], key=lambda x: x[1], reverse=True)
```

## Common pitfalls

- Sorting ascending instead of descending.
- Returning scores without indices (you need traceability).
- Not handling edge cases (empty vectors, k=0).
