## Why Reranking Matters

First-stage retrieval (BM25 + dense) optimizes for **recall** — don't miss anything.
Reranking optimizes for **precision** — put the best documents at the top.

```
First Stage: Retrieve 100 candidates (high recall)
    ↓
Reranker: Score each candidate against the query
    ↓
Final: Keep top 5-10 for LLM context (high precision)
```

## Reranker Types

### 1. Cross-Encoder Rerankers

Process query-document pairs together through a transformer:

```
[CLS] query [SEP] document [SEP] → relevance score
```

**Pros**: Highest accuracy (full attention between query and doc)
**Cons**: Slow (can't precompute document representations)

### 2. Late Interaction (ColBERT)

Precompute token embeddings, interaction at query time:

```
Query tokens → Q embeddings
Doc tokens → D embeddings (precomputed)
Score = Σ max similarity (Q_i, D_j)
```

**Pros**: Fast (100x faster than cross-encoder)
**Cons**: Large index (128 vectors per doc)

### 3. LLM-as-Reranker

Use an LLM to score relevance:

```
"Rate the relevance of this document to the query on a scale of 1-5.
Query: {query}
Document: {document}
Rating:"
```

**Pros**: Best for nuanced relevance, zero-shot
**Cons**: Extremely slow and expensive

## Implementation Patterns

### Pattern 1: API Reranker (Cohere)

```python
import cohere

co = cohere.Client("your-api-key")

def rerank_cohere(query: str, documents: List[str], top_k: int = 5) -> List[str]:
    response = co.rerank(
        model="rerank-english-v3.0",
        query=query,
        documents=documents,
        top_n=top_k,
        return_documents=True
    )
    return [r.document.text for r in response.results]
```

### Pattern 2: Open Source (BGE)

```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer
import torch

model_name = "BAAI/bge-reranker-v2-m3"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(model_name)
model.eval()

def rerank_bge(query: str, documents: List[str], top_k: int = 5) -> List[str]:
    pairs = [[query, doc] for doc in documents]

    with torch.no_grad():
        inputs = tokenizer(
            pairs,
            padding=True,
            truncation=True,
            max_length=512,
            return_tensors="pt"
        )
        scores = model(**inputs).logits.squeeze(-1)

    # Sort by score descending
    ranked_indices = torch.argsort(scores, descending=True)[:top_k]
    return [documents[i] for i in ranked_indices.tolist()]
```

### Pattern 3: Cascade Reranker (Fast → Accurate)

```python
def cascade_rerank(query: str, documents: List[str], final_k: int = 5) -> List[str]:
    """
    Stage 1: Fast reranker on 100 candidates → 20
```

### Pattern 4: LLM Listwise Reranking

```python
def llm_rerank(query: str, documents: List[str], top_k: int = 5) -> List[str]:
    """Use LLM to rank documents by relevance."""

    doc_list = "\n".join([f"[{i+1}] {doc[:200]}" for i, doc in enumerate(documents)])

    prompt = f"""Rank these documents by relevance to the query.
Return only the document numbers in order from most to least relevant.

Query: {query}

Documents:
{doc_list}

Ranking (comma-separated numbers):"""

    response = llm.generate(prompt)

    # Parse response: "3, 1, 5, 2, 4" → [3, 1, 5, 2, 4]
    ranking = [int(x.strip()) - 1 for x in response.split(",")]

    return [documents[i] for i in ranking[:top_k]]
```

## Latency Optimization

| Technique                 | Latency Reduction           |
| ------------------------- | --------------------------- |
| Batch processing          | 3-5x faster                 |
| GPU inference             | 10-20x faster than CPU      |
| Model quantization (INT8) | 2x faster, ~1% quality loss |
| Reduce candidate count    | Linear improvement          |
| Async processing          | Better throughput           |

## Edge Cases

| Scenario                        | Handling                                   |
| ------------------------------- | ------------------------------------------ |
| Document longer than 512 tokens | Truncate or chunk + max score              |
| Query longer than model limit   | Truncate (queries rarely exceed limit)     |
| Tie scores                      | Use original retrieval order as tiebreaker |
| All scores very low             | Consider fallback or "no relevant docs"    |
| Single candidate                | Skip reranking (unnecessary)               |
