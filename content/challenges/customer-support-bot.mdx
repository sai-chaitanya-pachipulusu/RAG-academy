## Project Overview

Enterprise support bots need to answer two types of questions:
1. **General policy questions**: "What is your return policy?"
2. **Personalized account questions**: "Can I return MY laptop?"

The second type is harder because it requires combining:
- **Static knowledge** (policy documents, FAQs)
- **Dynamic data** (user orders, account status, recent activity)

### What You'll Build

A Dynamic Support Bot that:
1. **Retrieves relevant policies** from a knowledge base
2. **Fetches live user data** from a database
3. **Synthesizes personalized answers** that apply policies to the user's specific situation
4. **Handles escalation** when human intervention is needed

### Real-World Impact

This architecture powers:
- **Klarna's AI assistant** - Handles 2/3 of customer service chats
- **Zendesk AI** - Automated ticket resolution
- **Salesforce Einstein** - CRM-integrated support bots
- **Intercom Fin** - Contextual customer support

### Policy Retrieval Function

```python
def retrieve_policy(query: str) -> str:
    """
    Retrieve relevant policy based on query keywords.
    
    In production, this would use semantic search over a vector database
    of policy documents.
    
    Args:
        query: User's question
        
    Returns:
        Relevant policy text
    """
    query_lower = query.lower()
    
    if "return" in query_lower:
        return POLICY_DOCS["return_policy"]
    
    if "shipping" in query_lower or "how long" in query_lower or "when" in query_lower:
        return POLICY_DOCS["shipping_policy"]
    
    if "warranty" in query_lower:
        return POLICY_DOCS["warranty_policy"]
    
    return ""
```

### The Support Bot Core

```python
def support_bot_answer(user_id: str, query: str) -> str:
    """
    Generate a personalized support response.
    
    This function combines static policy knowledge with dynamic user data
    to provide context-aware answers.
    
    Args:
        user_id: Unique identifier for the user
        query: User's support question
        
    Returns:
        Personalized response synthesizing policy and user context
    """
    # Step 1: Fetch user state
    user = get_user_state(user_id)
    if not user:
        return "I'm sorry, I couldn't find your account. Please verify your user ID."
    
    # Step 2: Retrieve relevant policy
    policy = retrieve_policy(query)
    
    # Step 3: Get user orders
    orders = user.get("orders", [])
    
    # Step 4: Generate personalized response based on query type
    
    # Case: User asking about their orders
    if "order" in query.lower() or "what did" in query.lower():
        if orders:
            items = [o["item"] for o in orders]
            return f"Hi {user['name']}! You ordered: {', '.join(items)}. Your most recent order status is: {orders[-1]['status']}."
        return f"Hi {user['name']}! I don't see any orders on your account."
    
    # Case: Return eligibility check
    if "return" in query.lower() and orders:
        item = orders[-1]["item"]
        return f"Hi {user['name']}! You ordered a {item}. {policy}"
    
    # Case: Shipping inquiry
    if "shipping" in query.lower() or "when" in query.lower() or "arrive" in query.lower():
        if orders:
            status = orders[-1]["status"]
            return f"Hi {user['name']}! Your order is currently {status}. {policy}"
        return f"Hi {user['name']}! {policy}"
    
    # Default: Return policy only
    return f"Hi {user['name']}! {policy}" if policy else f"Hi {user['name']}! How can I help you today?"
```

### Conversation Memory

For multi-turn support conversations:

```python
class ConversationalSupportBot:
    def __init__(self):
        self.conversations: Dict[str, List[dict]] = {}
    
    def respond(self, user_id: str, query: str) -> dict:
        # Get conversation history
        history = self.conversations.get(user_id, [])
        
        # Build context-aware prompt
        context = self.build_context(history, query)
        
        # Generate response
        response = self.generate(context)
        
        # Store turn
        history.append({"user": query, "bot": response})
        self.conversations[user_id] = history[-10:]  # Keep last 10 turns
        
        return response
```

### Escalation Detection

```python
def should_escalate(query: str, user_state: dict, sentiment: str) -> tuple[bool, str]:
    """
    Determine if conversation should escalate to human agent.
    
    Returns:
        (should_escalate, reason)
    """
    # Escalation triggers
    if sentiment == "angry" or sentiment == "frustrated":
        return True, "Customer showing frustration"
    
    if "refund" in query.lower() and user_state.get("tier") == "premium":
        return True, "Premium customer refund request"
    
    if "lawsuit" in query.lower() or "lawyer" in query.lower():
        return True, "Legal mention detected"
    
    # Check if we've gone in circles
    history = user_state.get("conversation_history", [])
    if len(history) > 5 and self.is_repetitive(history):
        return True, "Conversation going in circles"
    
    return False, ""
```

## Common Pitfalls

1. **Data Leakage**
   - ❌ Retrieving user data without authorization checks
   - ✅ Always verify user_id matches authenticated session

2. **Over-Personalization**
   - ❌ Including too much user data (overwhelming)
   - ✅ Only include relevant context

3. **Stale Policies**
   - ❌ Hardcoding policy text
   - ✅ Retrieve from version-controlled knowledge base

4. **Missing Escalation**
   - ❌ Trying to handle everything automatically
   - ✅ Know when to hand off to humans

5. **PII Exposure**
   - ❌ Logging full credit card numbers, passwords
   - ✅ Redact sensitive data in logs
