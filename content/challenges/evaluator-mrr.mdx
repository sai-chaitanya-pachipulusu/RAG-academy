## The "Rank Matters" Problem

Recall@K is binary: it's either in the list or not. But in RAG, getting the correct document at **Position #1** is much better than getting it at **Position #10**, because LLMs focus most on the beginning and end of context ("lost in the middle" problem).

## MRR Formula

```
MRR = (1/|Q|) × Σᵢ (1 / rankᵢ)
```

Where `rankᵢ` is the position of the first relevant document for query `i`.

### Per-query Reciprocal Rank

| First relevant doc at | Score (1/rank) |
| --------------------- | -------------- |
| Position 1            | 1.000          |
| Position 2            | 0.500          |
| Position 3            | 0.333          |
| Position 5            | 0.200          |
| Position 10           | 0.100          |
| Not found             | 0.000          |

## The Algorithm

```python
def reciprocal_rank(
    retrieved: list[str],
    relevant: set[str]
) -> float:
    """
    Compute Reciprocal Rank for a single query.
    
    Time Complexity: O(N) where N = retrieved
    Space Complexity: O(1) additional
    
    Args:
        retrieved: Ordered list of retrieved document IDs
        relevant: Set of ground-truth relevant document IDs
    
    Returns:
        RR score: 1/rank of first relevant doc, or 0 if none found
    """
    for i, doc_id in enumerate(retrieved, start=1):
        if doc_id in relevant:
            return 1.0 / i
    return 0.0


def mean_reciprocal_rank(
    queries: list[tuple[list[str], set[str]]]
) -> float:
    """
    Compute Mean Reciprocal Rank across multiple queries.
    
    Time Complexity: O(Q × N) where Q = queries, N = retrieved per query
    Space Complexity: O(1) additional
    
    Args:
        queries: List of (retrieved_docs, relevant_docs) tuples
    
    Returns:
        MRR score between 0.0 and 1.0
    """
    if not queries:
        return 0.0
    
    rr_scores = [reciprocal_rank(r, rel) for r, rel in queries]
    return sum(rr_scores) / len(rr_scores)
```

## Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| MRR computation | O(Q × N) | O(1) |

Where Q is the number of queries and N is the number of retrieved documents per query.

## Example calculation

| Query              | First relevant at | Reciprocal Rank |
| ------------------ | ----------------- | --------------- |
| "RAG architecture" | #1                | 1.00            |
| "HNSW complexity"  | #3                | 0.33            |
| "token budget"     | #2                | 0.50            |

MRR = (1.00 + 0.33 + 0.50) / 3 = **0.61**

## When to use MRR

- **Chatbots**: When users see only the top result
- **QA systems**: When the first relevant document is critical
- **Comparing retrieval changes**: MRR is more sensitive than Recall@K

## MRR vs Recall@K

| Metric   | Cares about position? | Use case                      |
| -------- | --------------------- | ----------------------------- |
| Recall@K | No (binary)           | "Did we find it?"             |
| MRR      | Yes (rank matters)    | "How quickly did we find it?" |
