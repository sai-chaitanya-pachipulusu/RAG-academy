## Why Citation Extraction Matters in Production

Citations let users verify RAG answers against sources. Extracting and validating them enables trustworthy AI that shows its work. In production systems, citations are essential for:

- **Verifiability**: Users can check claims against original sources
- **Debugging**: Developers can trace hallucinations to source problems
- **Compliance**: Regulatory requirements often mandate source attribution
- **Trust**: Cited answers are perceived as more credible

### Real-World Scenario

A legal research assistant generates an answer:

> "According to [1], the statute of limitations for contract disputes is 6 years in California. However, [2] notes exceptions for written contracts which may extend to 10 years."

Without citation extraction:
- Can't verify which documents support which claims
- Can't highlight relevant passages in source viewer
- Can't detect if LLM hallucinated citations

With citation extraction:
- Map each claim to specific source documents
- Validate that cited sources actually exist
- Enable click-to-source navigation in UI

## The Mathematical Foundation

### Citation Patterns

Common citation formats in LLM outputs:

| Format | Example | Use Case |
|--------|---------|----------|
| **Numbered** | [1], [2], [3] | Academic papers, ordered sources |
| **Inline** | (Smith 2023), (DOI:10.x) | Author-date, document IDs |
| **Bracketed** | [Source A], [doc-123] | Named references |
| **Superscript** | ¹, ², ³ | Compact formatting |

### Citation Validation

```
Validation Steps:
1. Extract citation markers from text
2. Parse citation indices/identifiers
3. Verify against available source list
4. Flag invalid citations (out of range, non-existent)
5. Generate clean text without markers
```

### Coverage Metrics

```
Citation Coverage = (Number of claims with citations) / (Total claims)
Citation Accuracy = (Valid citations) / (Total citations)
```

## Theoretical Deep Dive

### Citation as Grounding

Citations provide **explicit grounding** — a direct link between claim and evidence:

```
Claim → Citation Marker → Source Document → Evidence Passage
```

This differs from **implicit grounding** where the LLM uses sources without citing them.

### Citation Granularity

| Level | Example | Precision |
|-------|---------|-----------|
| **Document** | [1] | Low (whole document) |
| **Section** | [1.3] | Medium (section 3) |
| **Passage** | [1:45-67] | High (character range) |
| **Sentence** | [1:s5] | High (sentence 5) |

### Hallucinated Citations

LLMs may generate:
- **Non-existent citations**: [5] when only 3 sources exist
- **Incorrect citations**: Citing source A for information from source B
- **Over-citation**: Citing sources that don't support the claim

Detection requires:
1. Index validation (does citation exist?)
2. Semantic verification (does source support claim?)

## Production Considerations

### Citation Prompting

Structure prompts to encourage proper citations:

```
Instructions:
- Cite sources using [1], [2], etc. format
- Place citations immediately after the claim they support
- Every factual claim should have a citation
- If unsure, don't cite rather than guess
```

### Post-Processing Pipeline

```
LLM Output → Extract Citations → Validate → Highlight Sources → Render
```

### UI Integration

Extracted citations enable:
- Click-to-source navigation
- Source highlighting on hover
- Citation count badges
- Missing citation warnings

## Your Task

Implement a citation extractor:

  index: number;           // Citation number (1-indexed)
  position: {              // Position in text
    start: number;
    end: number;
  };
  raw: string;             // Raw citation text (e.g., "[1]")
}

interface CitationExtractionResult {
  citations: Citation[];
  cleanText: string;       // Text without citation markers
  citationPositions: Map<number, number[]>; // index → [positions]
}

interface ValidationResult {
  valid: Citation[];
  invalid: Array<{
    citation: Citation;
    reason: 'out_of_range' | 'invalid_format' | 'duplicate';
  }>;
  stats: {
    total: number;
    valid: number;
    invalid: number;
    coverage: number;  // % of sentences with citations
  };
}

function extractCitations(text: string): CitationExtractionResult {
  /**
   * Extract citation markers from LLM-generated text.
   * 
   * Args:
   *   text: Raw LLM output with citations
   * 
   * Returns:
   *   CitationExtractionResult with extracted citations and clean text
   * 
   * Supported formats:
   *   - [1], [2], [10] (numbered)
   *   - [1, 2], [1-3] (multiple, ranges)
   * 
   * Edge Cases:
   *   - Citations in code blocks: ignore or preserve based on context
   *   - Nested brackets: handle correctly
   *   - Multi-digit: [10], [123] supported
   */
}

function validateCitations(
  citations: Citation[],
  availableSources: number
): ValidationResult {
  /**
   * Validate extracted citations against available sources.
   * 
   * Args:
   *   citations: Extracted citations
   *   availableSources: Number of sources in context (for range check)
   * 
   * Returns:
   *   ValidationResult with valid/invalid split and statistics
   * 
   * Validation rules:
   *   - Index must be >= 1 and <= availableSources
   *   - Duplicate citations allowed but flagged
   */

   * Return text with all citation markers removed.
   * Preserve original spacing and formatting.

### Validation Checklist

- [ ] [1], [2], [10] extracted correctly
- [ ] Multi-digit citations [10]+ handled
- [ ] Position tracking accurate (character indices)
- [ ] Out of range citations flagged (e.g., [5] with 3 sources)
- [ ] Clean text preserves original formatting
- [ ] Empty text handled gracefully
- [ ] No citations returns empty array, original text

## Common Pitfalls

- **Not handling [10]+**: Multi-digit citations common with large context
- **Missing edge cases like [0]**: Zero and negative numbers invalid
- **Position tracking errors**: Off-by-one in character indices
- **Regex greediness**: `[1] and [2]` captured as single match
- **Context sensitivity**: Citations in code blocks vs text
