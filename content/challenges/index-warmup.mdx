# Index Warmup / Cache Preload

Cold indexes have **10x higher latency** than warm ones. The first query after a pod starts might take 500ms instead of 50ms.

**Your task**: Implement a `WarmableIndex` that preloads frequently accessed vectors at startup to eliminate cold start latency.

## The Cold Start Problem

Vector databases store data on disk. Loading into memory takes time:

- First query: Load from disk → 500ms
- Subsequent queries: In memory → 50ms

### Why This Happens

```
Disk Storage → Memmap/Paged Load → Query
     ↓              ↓                ↓
  SSD/NVMe      Kernel cache      L1/L2 cache
  (slow)        (medium)          (fast)
```

On-disk indexes like HNSW have random access patterns incompatible with sequential disk reads.

### Real-World Impact at Scale

| Scenario | Cold Latency (p99) | Warm Latency | Difference |
|----------|-------------------|--------------|------------|
| 1M vectors (flat) | 1200ms | 85ms | 14x |
| 10M vectors (HNSW) | 850ms | 45ms | 19x |
| 100M vectors (IVF) | 2000ms | 120ms | 17x |

**Production Rule**: Always warmup indexes before serving traffic.

## The Solution: Warmup

Pre-load frequently accessed vectors at startup:

```python
index.warmup(["popular_doc_1", "popular_doc_2", ...])
```

### Identifying Hot Data

Track access patterns to find warmup candidates:

- Most frequently accessed docs (top 10%)
- Docs accessed by VIP users
- Common query patterns
- Recent modifications (stale → fresh)

def warmup(self, vector_ids: List[str]) -> int:
    warmed = 0
    for vid in vector_ids:
        if vid in self.disk_vectors and vid not in self.warm_cache:
            self.warm_cache[vid] = self.disk_vectors[vid]
            warmed += 1
    self.stats["warmup_operations"] += warmed
    return warmed

## Theory: Why Warmup Matters

### Hierarchical Memory Architecture

```
┌─────────────────────────────────────────────────┐
│              CPU L1/L2/L3 Cache                  │  < 1ns
├─────────────────────────────────────────────────┤
│              Main Memory (RAM)                  │  100ns
├─────────────────────────────────────────────────┤
│              NVMe SSD                            │  10µs-100µs
├─────────────────────────────────────────────────┤
│              Network Storage                     │  1ms-10ms
└─────────────────────────────────────────────────┘
```

### Page Fault Overhead

When accessing cold data:

1. **Page Fault**: OS interrupts to load page from disk
2. **I/O Wait**: Process blocked during disk read
3. **MMU Update**: Virtual memory mapping updated
4. **Resume**: Process continues

**Cost**: 5-10µs (NVMe) to 5-10ms (network storage) per page

### Quantized Index Warmup

For large indexes, consider partial warmup:

```python
def quantized_warmup(index, budget_mb: int):
    """
    Warmup most valuable vectors within memory budget.
    
    Strategy:
    1. Calculate priority score: frequency × recency ÷ age
    2. Select vectors until budget exhausted
    3. Use quantization (int8, binary) for more vectors
    """
    priority_queue = calculate_priority_vectors(index)
    warmed = []
    used_mb = 0
    
    for vec in priority_queue:
        if used_mb + vec.size_mb > budget_mb:
            break
        warmed.append(vec.warmup())
        used_mb += vec.size_mb
    
    return warmed
```
