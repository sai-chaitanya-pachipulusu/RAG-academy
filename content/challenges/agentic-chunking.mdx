# Agentic Chunking: LLM-Guided Boundaries

## Beyond Rules and Metrics

Semantic chunking uses embedding similarity - a simple metric. But meaning is more nuanced:

```
"Machine learning requires large datasets. For example, GPT was trained on web text."
```

A simple similarity metric might split here. But an LLM would UNDERSTAND that the second sentence is an **example** supporting the first claim.

---

## The Agentic Insight

What if we could ask an LLM:

> "Should these two passages be in the same chunk?"

The LLM can reason about:

- Continuation ("For example...")
- Contrast ("However...")
- Topic shift ("Moving on to...")
- Support ("This demonstrates...")

---

## The Approach

```python
CONTINUE_SIGNALS = ["for example", "for instance", "specifically",
                    "this shows", "in other words"]

BOUNDARY_SIGNALS = ["however", "in contrast", "moving on",
                    "on another note", "separately"]

def should_chunk_here(sent1, sent2):
    # In production: call LLM
    # Here: use heuristic signals

    if any(signal in sent2.lower() for signal in BOUNDARY_SIGNALS):
        return True  # New chunk
    if any(signal in sent2.lower() for signal in CONTINUE_SIGNALS):
        return False  # Same chunk

    return cosine_similarity(embed(sent1), embed(sent2)) < threshold
```

## ⚖️ Tradeoffs

### Pros

- ✅ Understands nuanced relationships
- ✅ Handles complex document structures
- ✅ Can provide reasoning for each split

### Cons

- ❌ Expensive (LLM call per boundary decision)
- ❌ Slower (seconds per document vs milliseconds)
- ❌ Requires careful prompt engineering
