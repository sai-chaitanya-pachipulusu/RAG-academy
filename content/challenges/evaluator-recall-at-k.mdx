## Why Evaluation Matters

You can't improve what you don't measure. In production RAG, you need to know if changing your embedding model or chunk size actually helped.

The **Evaluator Saga** focuses on quantitative metrics for retrieval quality.

## Recall@K (the formula)

Recall@K measures whether **any** of the relevant documents appear in the top K results:

```
Recall@K = |{relevant docs in top-K}| / |{all relevant docs}|
```

For single-ground-truth scenarios (most common in RAG):

- **1.0** if the relevant document is anywhere in top-K
- **0.0** if it's not found

## The Algorithm

```python
def recall_at_k(
    retrieved: list[str],
    relevant: set[str],
    k: int
) -> float:
    """
    Compute Recall@K for retrieval evaluation.
    
    Time Complexity: O(K) where K = cutoff
    Space Complexity: O(1) additional
    
    Args:
        retrieved: Ordered list of retrieved document IDs
        relevant: Set of ground-truth relevant document IDs
        k: Cutoff position (top-K)
    
    Returns:
        Recall@K score between 0.0 and 1.0
    
    Edge cases:
        - k <= 0: returns 0.0
        - Empty retrieved: returns 0.0
        - Empty relevant set: returns 1.0 (convention: nothing to find)
    """
    if k <= 0 or not retrieved or not relevant:
        return 0.0 if not relevant else 1.0
    
    top_k = set(retrieved[:k])
    relevant_found = len(top_k & relevant)
    
    return relevant_found / len(relevant)
```

## Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| Recall@K computation | O(K) | O(1) |

Computing Recall@K involves checking each of the K retrieved documents against the set of relevant documents, which is an O(K) operation with constant additional space.

## Common variants

- **Recall@1**: Strictest — must be the top result (same as Precision@1)
- **Recall@10**: Standard for reranker pipelines (retrieve 20-50, rerank to 10)
- **Recall@100**: Used for initial retrieval stage before reranking

## When to use which?

| Metric       | Use case                                 |
| ------------ | ---------------------------------------- |
| Recall@1     | When only one result is shown (chatbots) |
| Recall@5     | After reranking for RAG context          |
| Recall@10-20 | Retrieval stage evaluation               |
| Recall@100+  | ANN index quality check                  |

## Production tip

Always compute Recall@K **before and after** reranking to isolate retrieval failures from reranking failures.
