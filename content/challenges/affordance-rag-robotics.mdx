## Theory: Affordance-Based Retrieval

### What are Affordances?

Affordances describe the possible actions an agent can perform on an object:

$$
\text{Affordance}(o, a, s) = \begin{cases}
1 & \text{if action } a \text{ can be performed on object } o \text{ in state } s \\
0 & \text{otherwise}
\end{cases}
$$

Where:
- $o$ = Object (e.g., "cup", "door", "button")
- $a$ = Action (e.g., "grasp", "push", "press")
- $s$ = Current state (pose, gripper status, environment)

### Affordance Matching

The retrieval score combines semantic similarity with affordance compatibility:

$$
\text{Score}(q, p, s) = \alpha \cdot \text{sim}(q, p) + \beta \cdot \text{affordance\_match}(p, s) + \gamma \cdot \text{precondition\_sat}(p, s)$$

Where:
- $\text{sim}(q, p)$ = Semantic similarity between query and procedure
- $\text{affordance\_match}(p, s)$ = How well procedure matches current affordances
- $\text{precondition\_sat}(p, s)$ = Precondition satisfaction score
- $\alpha + \beta + \gamma = 1$

## Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| Index procedure | O(d) | O(n × d) |
| State encoding | O(s) | O(d) |
| Affordance matching | O(n × a) | O(k) |
| Plan retrieval | O(n log n) | O(k) |

Where:
- n = number of procedures
- d = embedding dimension
- s = state dimension
- a = average affordances per procedure
- k = top-k results

## Common Pitfalls

1. **State Mismatch**: Retrieving procedures that don't match current robot state
2. **Missing Preconditions**: Not checking if preconditions are satisfied
3. **Action Sequencing**: Incorrect ordering of affordance-based actions
4. **Environment Changes**: Not handling dynamic environment updates
5. **Safety Constraints**: Ignoring safety-critical affordance constraints

class TemporalAffordanceChain:
    """Model affordances with temporal dependencies."""
    
    def validate_sequence(self, actions: list[dict], state: dict) -> bool:
        """Check if action sequence is temporally valid."""
        current_state = state.copy()
        
        for action in actions:
            # Check preconditions
            if not self.check_preconditions(action, current_state):
                return False
            
            # Simulate state transition
            current_state = self.apply_effects(action, current_state)
        
        return True

## Interview Questions

**Q1: How do you handle affordance conflicts (e.g., object is both "graspable" and "pushable")?**

*Answer:*
- Use context to disambiguate (goal: "move cup" → pushable, "drink from cup" → graspable)
- Rank by task relevance
- Query user for clarification if confidence is low

**Q2: Design a system that learns new affordances from demonstration.**

*Answer:*
- Store demonstration trajectories with state-action pairs
- Extract common patterns using clustering
- Generalize to new objects with similar features
- Validate in simulation before deployment

**Q3: How do you ensure safety when retrieving affordance-based actions?**

*Answer:*
- Hard constraints on dangerous affordances
- Simulation-based validation
- Gradual execution with monitoring
- Emergency stop integration
