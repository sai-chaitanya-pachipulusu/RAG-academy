## The "Dense Bottleneck" Problem

Single-vector embeddings (like OpenAI's) compress an entire document into one vector. This loses granular detail — a 10-page document and a 10-word document both become a single 1536-dim vector.

## ColBERT's Solution: Late Interaction

**ColBERT** (Contextualized Late Interaction over BERT) represents every token in a document as its own vector. Scoring uses the **MaxSim** operator:

### The MaxSim Formula

```
Score(Q, D) = Σᵢ maxⱼ (qᵢ · dⱼ)
```

For each query token `qᵢ`, find the document token `dⱼ` it is most similar to, then sum all those maximum similarities.

## Algorithm

1. For each token in the query, compute similarity to ALL document tokens
2. Keep only the maximum similarity (hence "MaxSim")
3. Sum all maxima to get the final relevance score

## Why it works

- **Fine-grained matching**: Part numbers, acronyms, and specific terms match exactly
- **Soft matching**: Related terms still contribute (unlike exact keyword match)
- **Position-agnostic**: Order doesn't matter (unlike sequence models)

## Complexity Analysis

| Aspect | Single-Vector | ColBERT (MaxSim) |
|--------|---------------|------------------|
| Index size | 1 vector/doc | ~128 vectors/doc |
| Query time | O(1) ANN | O(Q × D) per candidate |
| Recall | Good | Excellent |
| Use case | General | High-precision retrieval |

Where Q = query tokens, D = document tokens

## Implementation

```python
import numpy as np
from typing import List

def maxsim_score(
    query_embeddings: np.ndarray,
    doc_embeddings: np.ndarray
) -> float:
    """
    Compute ColBERT MaxSim score.
    
    Args:
        query_embeddings: (num_query_tokens, dim)
        doc_embeddings: (num_doc_tokens, dim)
    
    Returns:
        MaxSim score
    """
    # Normalize embeddings for cosine similarity
    query_norm = query_embeddings / np.linalg.norm(query_embeddings, axis=1, keepdims=True)
    doc_norm = doc_embeddings / np.linalg.norm(doc_embeddings, axis=1, keepdims=True)
    
    # Compute all pairwise similarities: (Q, D)
    similarities = query_norm @ doc_norm.T
    
    # Max over document tokens for each query token
    max_per_query = similarities.max(axis=1)
    
    # Sum over query tokens
    return float(max_per_query.sum())


def batch_maxsim(
    query_embeddings: np.ndarray,
    doc_embeddings_list: List[np.ndarray]
) -> List[float]:
    """
    Compute MaxSim scores for multiple documents.
    
    Args:
        query_embeddings: (Q, dim)
        doc_embeddings_list: List of (D_i, dim) arrays
    
    Returns:
        List of scores
    """
    return [maxsim_score(query_embeddings, doc_emb) for doc_emb in doc_embeddings_list]
```

    query_embeddings: np.ndarray,
    doc_embeddings: np.ndarray

    """
    Compute ColBERT MaxSim score.
    
    Score = Σᵢ maxⱼ (qᵢ · dⱼ)

## Production Usage

ColBERT is typically used as a **reranker** (score top-100 candidates) rather than first-stage retrieval, because storing per-token vectors is expensive at scale.

```python
def colbert_rerank(
    query: str,
    candidates: List[str],
    colbert_model,
    k: int = 10
) -> List[tuple]:
    """Rerank candidates using ColBERT."""
    query_emb = colbert_model.encode_query(query)
    
    scores = []
    for doc in candidates:
        doc_emb = colbert_model.encode_document(doc)
        score = maxsim_score(query_emb, doc_emb)
        scores.append((score, doc))
    
    scores.sort(reverse=True)
    return scores[:k]
```

## Best Practices

1. **Use as reranker**: Don't index everything with ColBERT
2. **Quantize embeddings**: Reduce from float32 to int8 for storage
3. **PLAID indexing**: Use centroid-based candidate filtering
4. **Cache embeddings**: Pre-compute document embeddings
5. **Batch scoring**: Process multiple candidates together
