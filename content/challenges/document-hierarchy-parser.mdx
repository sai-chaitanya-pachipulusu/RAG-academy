# Document Hierarchy Parser

## Overview

Document structure (headings, sections, subsections) provides essential context. This challenge teaches you to parse and preserve hierarchy for section-aware retrieval.

## Why This Matters

- **Context Preservation**: Know which section a chunk comes from
- **Breadcrumb Navigation**: "User Guide > Getting Started > Installation"
- **Improved Chunking**: Respect section boundaries

## Key Concepts

- Heading level detection (H1-H6)
- Nested section building with parent tracking
- Flattening with breadcrumb paths
- Section-aware chunk generation

## Real-World Applications

Notion, Confluence, GitBook, and documentation platforms all leverage hierarchical structure.

## Mathematical Foundation

### Hierarchy Representation

A document hierarchy can be represented as a tree:

$$
H = (V, E, L)
$$

Where:
- $V$ = Set of sections (nodes)
- $E$ = Parent-child relationships (edges)
- $L: V \rightarrow \{1, 2, ..., 6\}$ = Heading level function

### Breadcrumb Path

The breadcrumb path to a section is the sequence of ancestors:

$$
\text{Breadcrumb}(v) = [root, ..., parent(v), v]
$$

### Hierarchy-Aware Chunking

When creating chunks, include hierarchical context:

$$
\text{Chunk}_i = \text{Breadcrumb}(s_i) + \text{Content}(s_i)
$$

Where $s_i$ is the section containing the chunk.

## Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| Heading detection | O(n) | O(h) |
| Tree construction | O(n) | O(n) |
| Breadcrumb generation | O(h) | O(h) |
| Hierarchical chunking | O(n) | O(c × h) |

Where:
- n = number of text blocks
- h = maximum hierarchy depth
- c = number of chunks

## Common Pitfalls

1. **Skipped Levels**: H2 directly under H4 (invalid hierarchy)
2. **Ambiguous Headings**: Bold text vs actual headings
3. **Circular References**: Malformed documents with cycles
4. **Empty Sections**: Headings without content
5. **Mixed Formats**: Different heading styles in same document

### Tree Construction with Validation

```python
class HierarchyBuilder:
    """Build and validate document hierarchy."""
    
    def build_tree(self, headings: list[dict]) -> dict:
        """Build tree from flat heading list."""
        root = {"level": 0, "title": "Root", "children": [], "parent": None}
        stack = [root]
        
        for heading in headings:
            node = {
                "level": heading["level"],
                "title": heading["title"],
                "children": [],
                "content": ""
            }
            
            # Find parent (last node with lower level)
            while stack and stack[-1]["level"] >= heading["level"]:
                stack.pop()
            
            if not stack:
                # Invalid hierarchy - skip or fix
                continue
            
            parent = stack[-1]
            parent["children"].append(node)
            node["parent"] = parent
            stack.append(node)
        
        return root
    
    def validate(self, tree: dict) -> list[str]:
        """Validate hierarchy and return errors."""
        errors = []
        
        def check_node(node, expected_level):
            if node["level"] != expected_level:
                errors.append(f"Level mismatch: {node['title']}")
            
            for child in node.get("children", []):
                check_node(child, expected_level + 1)
        
        check_node(tree, 0)
        return errors
```

### Semantic Hierarchy Enhancement

```python
class SemanticHierarchy:
    """Enhance hierarchy with semantic information."""
    
    def __init__(self, embedding_model):
        self.embedder = embedding_model
    
    def compute_section_embeddings(self, tree: dict):
        """Compute embeddings for each section."""
        def traverse(node):
            if node.get("content"):
                node["embedding"] = self.embedder.encode(
                    node["title"] + "\n" + node["content"]
                )
            
            for child in node.get("children", []):
                traverse(child)
        
        traverse(tree)
    
    def find_similar_sections(self, tree: dict, query: str, threshold: float = 0.8):
        """Find sections semantically similar to query."""
        query_emb = self.embedder.encode(query)
        matches = []
        
        def traverse(node):
            if "embedding" in node:
                similarity = cosine_similarity(query_emb, node["embedding"])
                if similarity > threshold:
                    matches.append({
                        "section": node,
                        "similarity": similarity,
                        "breadcrumb": self.get_breadcrumb(node)
                    })
            
            for child in node.get("children", []):
                traverse(child)
        
        traverse(tree)
        return sorted(matches, key=lambda x: x["similarity"], reverse=True)
```

## Interview Questions

**Q1: How would you handle documents with inconsistent heading levels (e.g., H1 followed by H3)?**

*Answer:*
- Option 1: Normalize by inserting implicit H2
- Option 2: Treat as flat structure with warnings
- Option 3: Use semantic analysis to infer missing levels
- Log warnings for document quality monitoring

**Q2: Design a system that supports multiple document formats with unified hierarchy.**

*Answer:*
- Define canonical internal representation
- Create format-specific parsers (Markdown, HTML, PDF, DOCX)
- Unified tree builder from parsed elements
- Format-agnostic chunking and retrieval
- Extensible plugin architecture for new formats

**Q3: How do you maintain hierarchy when chunking exceeds token limits?**

*Answer:*
- Split large sections while preserving breadcrumb
- Include parent context in each chunk
- Use "continued" markers for split sections
- Consider hierarchical retrieval (retrieve parent, then children)
