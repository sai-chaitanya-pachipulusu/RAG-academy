## Project Overview

Language models have a fundamental limitation: they're trained on static data with a fixed knowledge cutoff. They don't know what happened yesterday, today, or an hour ago. This project solves that problem by building an agent that augments its knowledge with live web search.

### What You'll Build

A News Agent that:
1. **Analyzes user queries** to extract search intent
2. **Generates optimized search queries** from natural language
3. **Retrieves live data** from search APIs (mocked for this challenge)
4. **Synthesizes answers** grounded only in retrieved information

### Real-World Impact

This is the exact architecture powering systems like:
- **Perplexity AI** - AI search engine answering with live sources
- **You.com** - AI assistant with real-time web access
- **ChatGPT with Browse** - OpenAI's web-enabled conversations

## Why This Matters

### The Knowledge Cutoff Problem

```
User: "What was Apple's stock price yesterday?"

Static LLM: "I don't have access to real-time data..."

News Agent: "Apple (AAPL) closed at $150.25 yesterday, up 1.2% 
             from the previous day according to market data."
```

### Live RAG Architecture

```
┌─────────────────┐     ┌──────────────┐     ┌─────────────────┐

└─────────────────┘     └──────────────┘     └─────────────────┘
                                                        │
                                                        ▼
┌─────────────────┐     ┌──────────────┐     ┌─────────────────┐
│  Final Answer   │◀────│  Synthesis   │◀────│  Search Results │
│  "65°F, sunny"  │     │  (LLM)       │     │  (Live data)    │
└─────────────────┘     └──────────────┘     └─────────────────┘
```

## Implementation Guide

### The Search Tool Pattern

```python
# Mock Search API - In production, use Tavily, SerpApi, or Google Custom Search
MOCK_WEB_INDEX = {
    "weather san francisco": "The weather in San Francisco is currently 65°F and sunny.",
    "stock price apple": "Apple (AAPL) is trading at $150.25, up 1.2%.",
    "latest rag techniques": "New techniques involve Agentic flows and GraphRAG for better reasoning.",
}

def search_tool(query: str) -> str:
    """
    Mock search tool. In production, this would call:
    - Tavily API (AI-native search)
    - SerpApi (Google results)
    - Bing Search API
    - Custom web scraper
    """
    normalized = " ".join(re.findall(r"[a-z0-9]+", query.lower()))
    for key, content in MOCK_WEB_INDEX.items():
        if key in normalized:
            return content
    return "No relevant results found."
```

### The Agent Implementation

```python
def news_agent_solve(user_query: str) -> str:
    """
    Live RAG Agent implementation.
    
    Steps:
    1. Analyze the user query for intent and entities
    2. Generate a search query (keyword extraction)
    3. Call search_tool() to get live data
    4. Synthesize an answer based ONLY on the tool output
    
    Args:
        user_query: Natural language question from user
        
    Returns:
        Synthesized answer grounded in search results
    """
    # Step 1: Extract keywords for search
    # Remove punctuation, normalize case
    keywords = " ".join(re.findall(r"[a-z0-9]+", user_query.lower()))
    
    # Step 2: Call search tool
    search_result = search_tool(keywords)
    
    # Step 3: Synthesize answer
    if search_result == "No relevant results found.":
        return "I couldn't find relevant information for your query."
    
    return f"Based on current information: {search_result}"
```

## Common Pitfalls

1. **Hallucination Risk**
   - ❌ Don't let the LLM make up information when search returns nothing
   - ✅ Always return "I don't know" or "No results found"

2. **Query Extraction**
   - ❌ Searching the entire user query verbatim
   - ✅ Extract keywords and entities for better results

3. **Source Attribution**
   - ❌ Presenting information without citing sources
   - ✅ Always include "According to [source]" or similar

4. **Over-reliance on Search**
   - ❌ Searching for every query (wasteful)
   - ✅ Use routing (from tool-use-basics) to decide when search is needed
