# KV-Cache Optimization for RAG

LLMs compute key-value pairs for each token in the context. For RAG, we often send the same context prefix repeatedly. KV-cache optimization reuses these computations.

**Your task**: Build a system that maximizes KV-cache hits for RAG queries.

## Concept

```
Traditional RAG (no KV-cache reuse):
  Query 1: [System Prompt][Context Chunk 1][Context Chunk 2][Question 1] → Full compute
  Query 2: [System Prompt][Context Chunk 1][Context Chunk 2][Question 2] → Full compute
  
With KV-Cache Optimization:
  Query 1: [System Prompt][Context Chunk 1][Context Chunk 2][Question 1] → Full compute, cache prefix
  Query 2: [System Prompt][Context Chunk 1][Context Chunk 2][Question 2] → Reuse prefix cache!
  
Latency reduction: 40-60% for similar queries
```

### How KV-Cache Works

In transformer attention, each layer produces:
- **Key (K)**: What a token "offers" to other tokens
- **Value (V)**: What information a token provides

**Space Complexity**: $O(L \cdot d_{model} \cdot n_{layers} \cdot 2)$ where $L$ is sequence length

**Time Savings**: Avoid $O(L^2 \cdot d_{head} \cdot n_{heads})$ operations on cached prefix

### Real-World Impact

| System | Without Cache | With KV Cache | Savings |
|--------|--------------|---------------|---------|
| 2K context | 500ms | 220ms | 56% |
| 4K context | 800ms | 320ms | 60% |
| 8K context | 1.5s | 550ms | 63% |

**Companies Using This**: Anyscale (Ray Serve), Together AI, Fireworks AI, Groq

def compute_prefix_hash(self, system_prompt: str, context: List[str]) -> str:
    # Combine system prompt and context (order matters!)
    prefix_text = system_prompt + "|||" + "|||".join(context)
    return hashlib.sha256(prefix_text.encode()).hexdigest()[:16]

def store_prefix_cache(self, prefix_hash, prefix_tokens, kv_cache):
    # Evict if at capacity (LRU)
    if len(self.cache) >= self.max_cache_entries:
        # Find entry with oldest access (fewest hits or oldest)
        oldest_key = min(
            self.cache.keys(),
            key=lambda k: (self.cache[k].hits, self.cache[k].created_at)
        )
        del self.cache[oldest_key]
    
    self.cache[prefix_hash] = CacheEntry(
        prefix_hash=prefix_hash,
        prefix_tokens=prefix_tokens,
        kv_cache=kv_cache,
        created_at=time.time()
    )

## Theory: Why KV-Cache Works

### Attention Mechanism Recap

Transformer attention computes:

$$Attention(Q, K, V) = softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

For a sequence of length $L$, computing $K$ and $V$ involves:
- Matrix multiplication: $O(L \cdot d_{model}^2)$
- For $n_{layers}$ layers: $O(n_{layers} \cdot L \cdot d_{model}^2)$

### With KV-Cache

Once prefix $P$ is processed:
- Cache $(K_P, V_P)$ for all layers
- For new tokens $T$, only compute $(K_T, V_T)$
- Concatenate: $K = [K_P, K_T]$, $V = [V_P, V_T]$

**New computation**: Only for $|T|$ tokens instead of $|P| + |T|$

### Complexity Analysis

| Metric | Without Cache | With Cache | Ratio |
|--------|---------------|------------|-------|
| Compute | $O((P+T)^2)$ | $O(P^2 + PT + T^2)$ | ~50% for P≥T |
| Memory | -- | $O(P \cdot d \cdot h)$ | PagedAttention reduces |

### Production Considerations

1. **Cache Sizing**: Memory = 2 × layers × heads × head_dim × seq_len × batch_size
2. **Prefix Caching**: Use exact match or fuzzy deduplication
3. **Multi-GPU**: Cache per GPU, share within node
4. **Eviction Policy**: LRU works well; consider query frequency patterns
