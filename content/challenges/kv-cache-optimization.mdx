# KV-Cache Optimization for RAG

LLMs compute key-value pairs for each token in the context. For RAG, we often send the same context prefix repeatedly. KV-cache optimization reuses these computations.

**Your task**: Build a system that maximizes KV-cache hits for RAG queries.

## Concept

```
Traditional RAG (no KV-cache reuse):
  Query 1: [System Prompt][Context Chunk 1][Context Chunk 2][Question 1] → Full compute
  Query 2: [System Prompt][Context Chunk 1][Context Chunk 2][Question 2] → Full compute
  
With KV-Cache Optimization:
  Query 1: [System Prompt][Context Chunk 1][Context Chunk 2][Question 1] → Full compute, cache prefix
  Query 2: [System Prompt][Context Chunk 1][Context Chunk 2][Question 2] → Reuse prefix cache!
  
Latency reduction: 40-60% for similar queries
```

<summary>Hint 1: Prefix hash</summary>

Concatenate and hash the stable parts:

```python
def compute_prefix_hash(self, system_prompt: str, context: List[str]) -> str:
    # Combine system prompt and context (order matters!)
    prefix_text = system_prompt + "|||" + "|||".join(context)
    return hashlib.sha256(prefix_text.encode()).hexdigest()[:16]
```

def simulate_generation(self, prefix_tokens, question_tokens, cached_kv):
    MS_PER_TOKEN = 10  # Simulated: 10ms per token
    
    if cached_kv:
        # Only compute question tokens

    else:
        # Compute all tokens
        compute_tokens = len(prefix_tokens) + len(question_tokens)
    
    latency = compute_tokens * MS_PER_TOKEN

<details>
<summary>Hint 3: LRU eviction</summary>

Track access order, evict oldest:

```python
def store_prefix_cache(self, prefix_hash, prefix_tokens, kv_cache):
    # Evict if at capacity (LRU)
    if len(self.cache) >= self.max_cache_entries:
        # Find entry with oldest access (fewest hits or oldest)
        oldest_key = min(
            self.cache.keys(),
            key=lambda k: (self.cache[k].hits, self.cache[k].created_at)
        )
        del self.cache[oldest_key]
    
    self.cache[prefix_hash] = CacheEntry(
        prefix_hash=prefix_hash,
        prefix_tokens=prefix_tokens,
        kv_cache=kv_cache,
        created_at=time.time()
    )
```

def test_kv_cache():
    rag = KVCacheOptimizedRAG()
    system = "You are a helpful assistant."
    
    for scenario in TEST_SCENARIOS:
        print(f"\n{'='*60}")
        print(f"Scenario: {scenario['name']}")
        
        cache_hits = 0
        
        if "context_variations" in scenario:
            # Different contexts
            for ctx in scenario["context_variations"]:
                result = rag.generate(system, ctx, scenario["question"])
                if result.cache_hit:
                    cache_hits += 1
                print(f"  Context size {len(ctx)}: "
                      f"{'HIT' if result.cache_hit else 'MISS'} "
                      f"({result.latency_ms:.0f}ms)")
        else:
            # Same context, different questions
            for q in scenario["questions"]:
                result = rag.generate(system, scenario["context"], q)
                if result.cache_hit:
                    cache_hits += 1
                print(f"  '{q[:30]}...': "
                      f"{'HIT' if result.cache_hit else 'MISS'} "
                      f"({result.latency_ms:.0f}ms)")
        
        expected = scenario["expected_cache_hits"]
        status = "✓" if cache_hits == expected else "✗"
        print(f"{status} Cache hits: {cache_hits} (expected {expected})")
    
    # Print overall stats
    stats = rag.get_stats()
    print(f"\n{'='*60}")
    print(f"Overall Stats:")
    print(f"  Total queries: {stats['total_queries']}")
    print(f"  Cache hit rate: {stats['hit_rate']:.0%}")

## Real-World Implementation Notes

In production, KV-cache optimization requires:

1. **Model support**: vLLM, TensorRT-LLM, or custom inference
2. **Prefix caching**: Some providers (e.g., Anthropic) offer this natively
3. **Careful ordering**: Context order must be consistent
4. **Memory management**: KV-caches are large (GB scale)
