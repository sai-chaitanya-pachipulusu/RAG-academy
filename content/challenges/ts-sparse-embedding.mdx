## Why Sparse Embeddings Matter in Production

Sparse embeddings (TF-IDF, BM25 vectors) are the "S" in hybrid search. They excel at exact term matching where dense embeddings fail — like product codes or technical terms. Sparse embeddings provide:

- **Exact term matching**: "API-123" matches exactly, not approximately
- **Interpretability**: Non-zero dimensions correspond to actual terms
- **Efficiency**: Sparse storage and computation
- **Complementarity**: Different failure modes than dense embeddings

### Real-World Scenario

Query: "USB-C cable 2m"

**Dense embedding**: Might match "HDMI cable" (similar concept) but miss exact specs
**Sparse embedding (TF-IDF)**: 
- "USB-C" → dimension 1234 = 0.8
- "cable" → dimension 567 = 0.6  
- "2m" → dimension 890 = 0.9

Matches documents containing these exact terms.

## The Mathematical Foundation

### Sparse Vector Representation

```
Dense vector: [0.1, -0.3, 0.5, ...] (all dimensions have values)
Sparse vector: {123: 0.8, 456: 0.6, 789: 0.9} (only non-zero dimensions stored)

Storage:
- Dense: O(d) for d dimensions
- Sparse: O(k) for k non-zero values (k << d)
```

### TF-IDF Weighting

$$\text{TF-IDF}(t, d) = \text{tf}(t, d) \times \text{idf}(t)$$

Where:
- $\text{tf}(t, d)$ = term frequency in document
- $\text{idf}(t) = \log(\frac{N}{\text{df}(t)})$ = inverse document frequency

## Theoretical Deep Dive

### Vocabulary Construction

```
Approach 1: Fixed vocabulary (e.g., 50K most frequent terms)
Approach 2: Hashing (unbounded vocabulary)
Approach 3: Learned (neural sparse like SPLADE)
```

### Term Weighting Schemes

| Scheme | Formula | Characteristics |
|--------|---------|-----------------|
| **Binary** | 1 if present, 0 otherwise | Simple, no frequency |
| **Raw TF** | term count | Favors long documents |
| **Log TF** | 1 + log(tf) | Diminishing returns |
| **TF-IDF** | tf × idf | Balanced weighting |
| **BM25** | complex | Length normalized |

### Sparsity Patterns

```
Typical sparsity: 95-99% zeros
- Vocabulary: 50,000 terms
- Non-zero per document: 100-500 terms
- Sparsity: 99%+
```

### Similarity Computation

```typescript
function sparseCosineSimilarity(
  a: SparseVector,
  b: SparseVector
): number {
  // Only iterate over common keys
  const commonKeys = intersection(a.keys, b.keys);
  let dotProduct = 0;
  for (const key of commonKeys) {
    dotProduct += a.get(key) * b.get(key);
  }
  return dotProduct / (a.norm * b.norm);
}
// Complexity: O(min(|a|, |b|)) instead of O(d)
```

### Validation Checklist

- [ ] Vocabulary built correctly from corpus
- [ ] Document frequencies calculated correctly
- [ ] TF computed correctly (raw or sublinear)
- [ ] IDF computed correctly (log(N/df))
- [ ] Sparse vector contains only non-zero entries
- [ ] Unknown terms handled (skip or hash)
- [ ] Empty text returns empty vector
- [ ] Dot product uses common indices only

## Common Pitfalls

- **Not handling out-of-vocabulary terms**: Decide on skip or hash strategy
- **Forgetting to normalize by document length**: Raw TF favors long docs
- **Not using sparse-aware operations**: Dense ops waste computation
- **Vocabulary explosion**: Limit size or use hashing
- **IDF calculation errors**: Check log base and smoothing
