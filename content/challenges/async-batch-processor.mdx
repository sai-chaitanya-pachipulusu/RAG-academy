# Async Batch Embedding Processor

Embedding APIs accept batches. Sending one text at a time is **100x slower** than batching.

### The Math

| Method     | API Calls | Time        |
| ---------- | --------- | ----------- |
| One-by-one | 10,000    | 100 minutes |
| Batch (32) | 313       | ~3 minutes  |

### Rate Limiting

APIs have rate limits. Add delays between batches to avoid 429 errors.

```python
for batch in batches:
    embeddings = api.embed(batch)
    time.sleep(0.1)  # Rate limit delay
```

### Your Task

Implement a batch processor that:

- Groups texts into batches of `batch_size`.
- Calls the embedding function per batch.
- Adds delay between batches.

### Production Best Practices

- Use async/await for concurrent processing.
- Implement exponential backoff for retries.
- Monitor throughput and adjust batch size.

## Mathematical Analysis

### Throughput Optimization

The total processing time can be modeled as:

$$
T_{\text{total}} = \frac{N}{B} \cdot (T_{\text{api}} + T_{\text{delay}}) + T_{\text{overhead}}
$$

Where:
- $N$ = Total number of texts
- $B$ = Batch size
- $T_{\text{api}}$ = API latency per batch
- $T_{\text{delay}}$ = Rate limit delay between batches
- $T_{\text{overhead}}$ = Local processing overhead

### Optimal Batch Size

The optimal batch size balances throughput and memory:

$$
B_{\text{optimal}} = \min(B_{\text{max\_api}}, \frac{M_{\text{available}}}{D \cdot L_{\text{avg}}})
$$

Where:
- $B_{\text{max\_api}}$ = API maximum batch size
- $M_{\text{available}}$ = Available memory
- $D$ = Embedding dimension
- $L_{\text{avg}}$ = Average text length in tokens

## Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| Batch grouping | O(N) | O(B) |
| Sequential batch processing | O(N/B × T_api) | O(B × D) |
| Async parallel processing | O(N/B × T_api / C) | O(C × B × D) |
| Retry with backoff | O(N/B × R × T_api) | O(B × D) |

Where:
- N = total texts
- B = batch size
- D = embedding dimension
- C = concurrency level
- R = max retries
- T_api = API latency

## Common Pitfalls

1. **Memory Exhaustion**: Loading all embeddings into memory at once
2. **API Rate Limits**: Not implementing proper backoff and retry
3. **Partial Batch Failures**: One failed text fails entire batch
4. **Token Overflow**: Exceeding max tokens per batch
5. **Blocking I/O**: Not using async for concurrent API calls

## Advanced Techniques

### Adaptive Batch Sizing

```python
class AdaptiveBatchProcessor:
    def __init__(self, initial_batch_size=32):
        self.batch_size = initial_batch_size
        self.success_rate = 1.0
        self.latency_history = []
    
    def adjust_batch_size(self):
        """Dynamically adjust batch size based on performance."""
        avg_latency = sum(self.latency_history) / len(self.latency_history)
        
        if avg_latency < 0.5 and self.success_rate > 0.99:
            self.batch_size = min(self.batch_size * 2, 256)
        elif avg_latency > 2.0 or self.success_rate < 0.95:
            self.batch_size = max(self.batch_size // 2, 8)
```

### Concurrent Processing with Semaphore

```python
import asyncio
from asyncio import Semaphore

class ConcurrentBatchProcessor:
    def __init__(self, max_concurrent=5):
        self.semaphore = Semaphore(max_concurrent)
    
    async def process_batch(self, batch: list[str]) -> list[list[float]]:
        async with self.semaphore:
            return await self.embed_async(batch)
    
    async def process_all(self, texts: list[str], batch_size: int) -> list[list[float]]:
        batches = [texts[i:i+batch_size] for i in range(0, len(texts), batch_size)]
        tasks = [self.process_batch(batch) for batch in batches]
        results = await asyncio.gather(*tasks, return_exceptions=True)
        return self.flatten_results(results)
```

### Circuit Breaker Pattern

```python
class CircuitBreaker:
    """Prevent cascading failures during API outages."""
    
    def __init__(self, failure_threshold=5, recovery_timeout=30):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.failure_count = 0
        self.last_failure_time = None
        self.state = "CLOSED"  # CLOSED, OPEN, HALF_OPEN
    
    def can_execute(self) -> bool:
        if self.state == "CLOSED":
            return True
        elif self.state == "OPEN":
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = "HALF_OPEN"
                return True
            return False
        return True
    
    def record_success(self):
        self.failure_count = 0
        self.state = "CLOSED"
    
    def record_failure(self):
        self.failure_count += 1
        self.last_failure_time = time.time()
        if self.failure_count >= self.failure_threshold:
            self.state = "OPEN"
```

## Interview Questions

**Q1: How would you handle a batch where one text is much longer than others?**

*Answer:*
- Pre-tokenize and estimate tokens before batching
- Group texts by similar token lengths
- Split oversized texts or process separately
- Use dynamic batching based on token count, not item count

**Q2: Design a system that processes 1M texts with 99.9% reliability.**

*Answer:*
- Implement idempotent processing with deduplication
- Use persistent queue (SQS, RabbitMQ) for durability
- Checkpoint progress every N batches
- Dead letter queue for failed items
- Automatic retry with exponential backoff
- Circuit breaker for API protection

**Q3: How do you maintain ordering guarantees in async processing?**

*Answer:*
- Assign sequence IDs to inputs
- Use ordered result collection (asyncio.as_completed doesn't preserve order)
- Reorder results based on original indices
- Or use structured concurrency patterns

async def test_batch_processor():

    elapsed = time.time() - start
    assert elapsed > 1.0  # Should respect rate limits
