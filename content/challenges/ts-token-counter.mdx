## Why Token Counting Matters in Production

Token counting is essential for context window management. Every RAG system needs to track tokens to avoid truncation and manage costs. Accurate token counting enables:

- **Context window management**: Fit content within limits
- **Cost estimation**: Predict API costs before calls
- **Optimization**: Maximize useful content per request
- **Error prevention**: Avoid context overflow errors

### Real-World Scenario

Building a RAG prompt with 4K context limit:

```
System prompt: 200 tokens
Retrieved context: ? tokens
User query: 50 tokens
Response buffer: 500 tokens
Safety margin: 100 tokens
Available for context: 4000 - 850 = 3150 tokens

Without token counting: Might include 4000 tokens of context → overflow
With token counting: Precisely include 3150 tokens → perfect fit
```

## The Mathematical Foundation

### Tokenization Basics

```
Text → Tokenizer → Tokens → Model

"Hello world" → ["Hello", " world"] → [15496, 995] → Embedding
```

### Estimation Methods

| Method | Formula | Accuracy | Speed |
|--------|---------|----------|-------|
| **Character ratio** | chars / 4 | ~75% | Fast |
| **Word count** | words × 1.3 | ~70% | Fast |
| **Actual tokenizer** | tiktoken, etc. | 99%+ | Slow |

### Character-to-Token Ratio

```
English text: ~4 characters per token
Code: ~3-5 characters per token (varies by language)
Multilingual: ~2-4 characters per token
```

## Production Considerations

### Estimation vs Exact

```typescript
// Fast estimation for initial sizing
const estimatedTokens = text.length / 4;

// Exact count for final check
const exactTokens = await tiktoken.count(text);
```

### Budget Allocation

```typescript
interface TokenBudget {
  total: number;
  system: number;
  context: number;
  query: number;
  response: number;
  margin: number;
}

function allocateBudget(total: number): TokenBudget {
  return {
    total,
    system: Math.floor(total * 0.1),
    context: Math.floor(total * 0.6),
    query: Math.floor(total * 0.1),
    response: Math.floor(total * 0.15),
    margin: Math.floor(total * 0.05)
  };
}
```

### Streaming Count

For large texts:

```typescript
async function* countTokensStream(
  textStream: ReadableStream
): AsyncGenerator<{ text: string; tokenCount: number }> {
  let buffer = '';
  let totalTokens = 0;
  
  for await (const chunk of textStream) {
    buffer += chunk;
    const tokens = estimateTokens(buffer);
    if (tokens >= 100) {  // Batch size
      totalTokens += tokens;
      yield { text: buffer, tokenCount: totalTokens };
      buffer = '';
    }
  }
  
  if (buffer) {
    totalTokens += estimateTokens(buffer);
    yield { text: buffer, tokenCount: totalTokens };
  }
}
```

## Your Task

Implement a token counter:

```typescript
interface TokenCountResult {
  count: number;
  method: 'exact' | 'estimate';
  confidence?: number;  // For estimates
}

interface TokenCounterConfig {
  method: 'exact' | 'character' | 'word';
  charsPerToken?: number;  // Default: 4
  wordsPerToken?: number;  // Default: 0.75
  tokenizer?: {
    encode: (text: string) => number[];
  };
}

class TokenCounter {
  constructor(private config: TokenCounterConfig) {}

  count(text: string): TokenCountResult {
    /**
     * Count tokens in text.
     * 
     * Args:
     *   text: Input text to count
     * 
     * Returns:
     *   TokenCountResult with count and method info
     * 
     * Methods:
     *   - 'exact': Use provided tokenizer (most accurate)
     *   - 'character': text.length / charsPerToken (~75% accurate)
     *   - 'word': wordCount × wordsPerToken (~70% accurate)
     * 
     * Edge Cases:
     *   - Empty text: return 0
     *   - Whitespace only: count may vary by method
     *   - Very long text: use estimation for speed
     */
  }

  countBatch(texts: string[]): TokenCountResult[] {
    /**
     * Count tokens for multiple texts.
     */
  }

  estimateMaxChars(tokenBudget: number): number {
    /**
     * Estimate maximum characters that fit in token budget.
     * 
     * Returns: tokenBudget × charsPerToken
     */
  }

  fitsInBudget(text: string, budget: number): boolean {
    /**
     * Check if text fits within token budget.
     */
  }

  truncateToBudget(text: string, budget: number): string {
    /**
     * Truncate text to fit within token budget.
     * 
     * Strategy:
     *   1. Estimate truncation point
     *   2. Verify with actual count
     *   3. Adjust if needed
     *   4. Return truncated text
     */
  }
}
```

## Common Pitfalls

- **Underestimating tokens for code/technical content**: Code has different ratios
- **Not accounting for prompt template overhead**: System prompts add tokens
- **Assuming all languages have same ratio**: CJK languages differ
- **Ignoring special tokens**: <|endoftext|> counts too
- **Integer truncation**: Use Math.ceil for safety
