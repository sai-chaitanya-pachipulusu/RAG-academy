## Why Groundedness Checking Matters in Production

Groundedness checking prevents hallucinations by verifying that LLM claims are supported by retrieved context. This is how production RAG systems build trust. Without groundedness checking:

- LLMs may invent facts not in the sources
- Users can't verify answer accuracy
- Compliance requirements can't be met
- System reliability suffers

### Real-World Scenario

A medical Q&A system answering "What are the side effects of aspirin?"

**LLM Response:**
> "Aspirin commonly causes stomach upset [1]. It may also reduce the risk of heart attack [2]. However, it can cause Reye's syndrome in children [3]."

**Groundedness Check:**
- Claim 1: "stomach upset" → Found in source [1] ✓
- Claim 2: "reduce heart attack risk" → Found in source [2] ✓
- Claim 3: "Reye's syndrome in children" → NOT found in any source ✗

**Result**: Flag claim 3 for review or remove from answer.

## The Mathematical Foundation

### Groundedness Score

```
groundedness = (supported_claims) / (total_claims)
```

| Score | Interpretation | Action |
|-------|---------------|--------|
| 1.0 | Fully grounded | Deliver with confidence |
| 0.7-0.9 | Mostly grounded | Minor caveats |
| 0.5-0.7 | Partially grounded | Significant caveats |
| <0.5 | Poorly grounded | Reject or escalate |

### Claim Extraction

Split response into atomic claims:

```
"Aspirin causes stomach upset and reduces heart attack risk."
→
1. "Aspirin causes stomach upset"
2. "Aspirin reduces heart attack risk"
```

Methods:
- **Sentence splitting**: Simple but may miss compound claims
- **LLM extraction**: Accurate but expensive
- **Dependency parsing**: Linguistic approach

### Claim Verification

For each claim, find supporting evidence:

```
verification_score = max(similarity(claim_embedding, source_embedding))

if verification_score > threshold:
    claim is supported
else:
    claim is unsupported
```

## Theoretical Deep Dive

### Types of Groundedness

| Type | Definition | Example |
|------|-----------|---------|
| **Entailment** | Source directly implies claim | Source: "A causes B", Claim: "A causes B" |
| **Paraphrase** | Claim restates source | Source: "B is caused by A", Claim: "A causes B" |
| **Inference** | Claim logically follows | Source: "All A are B, X is A", Claim: "X is B" |
| **Unsupported** | No evidence in sources | Source: "A exists", Claim: "A causes B" |
| **Contradicted** | Source contradicts claim | Source: "A does not cause B", Claim: "A causes B" |

### The Attribution Problem

Groundedness requires **attribution** — linking claims to specific sources:

```
Claim ←→ Source Passage ←→ Source Document
```

Challenges:
- **Abstractive summarization**: LLM paraphrases, making matching hard
- **Synthesis**: LLM combines multiple sources
- **Implication**: LLM draws unstated conclusions

### Semantic vs Lexical Matching

| Method | Pros | Cons |
|--------|------|------|
| **Lexical (exact)** | Precise, fast | Misses paraphrases |
| **Semantic (embedding)** | Catches paraphrases | May have false positives |
| **Hybrid** | Balanced | More complex |

## Production Considerations

### Threshold Tuning

Balance precision vs recall:

```typescript
const thresholds = {
  strict: 0.8,    // High precision, may miss valid paraphrases
  balanced: 0.6,  // Default
  lenient: 0.4    // High recall, may allow hallucinations
};
```

### Claim Granularity

Too coarse: Misses partial hallucinations
Too fine: Excessive computation

Optimal: One claim per fact/assertion

### Real-time vs Batch

| Mode | Use Case | Latency |
|------|----------|---------|
| **Real-time** | User-facing responses | <100ms |
| **Batch** | Content moderation, audit | Minutes acceptable |

  text: string;
  position: { start: number; end: number };

  id: string;
  text: string;
  embedding?: number[];

  isSupported: boolean;

  score: number;           // 0-1 overall groundedness
  claims: VerificationResult[];
  unsupportedClaims: Claim[];
  stats: {
    totalClaims: number;
    supportedClaims: number;
    unsupportedClaims: number;
  };
}

function checkGroundedness(
  response: string,
  sources: Source[],
  config?: Partial<GroundednessConfig>
): GroundednessResult {
  /**
   * Check if LLM response is grounded in provided sources.
   * 
   * Args:
   *   response: LLM-generated text to check
   *   sources: Retrieved context documents

   * 
   * Returns:
   *   GroundednessResult with score and per-claim verification
   * 
   * Algorithm:
   *   1. Split response into atomic claims
   *   2. For each claim:
   *      a. Compute embedding
   *      b. Find most similar source passage
   *      c. Mark as supported if similarity > threshold
   *   3. Calculate overall groundedness score
   *   4. Return detailed results

### Validation Checklist

- [ ] Empty response handled (score 0, no claims)
- [ ] Each claim checked against all sources
- [ ] Best match selected per claim
- [ ] Threshold comparison correct (>= vs >)
- [ ] Score calculated as supported/total
- [ ] Unsupported claims listed separately
- [ ] Position tracking accurate for highlighting

## Common Pitfalls

- **Splitting on punctuation inside quotes**: "Dr. Smith said..." shouldn't split
- **Setting similarity threshold too high**: False negatives on paraphrases
- **Not handling negation**: "Aspirin doesn't cause X" vs "Aspirin causes X"
- **Ignoring claim context**: Surrounding text may clarify
- **Single-sentence claims**: Compound sentences need splitting
