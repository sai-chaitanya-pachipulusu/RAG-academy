# Conversational Query Rewriting

## The Problem with Follow-ups

**Conversation**:

```
User: "Tell me about Pinecone"
AI: "Pinecone is a vector database..."
User: "What about its pricing?"  ← Has "its" pronoun!
```

If we search for "What about its pricing?", retrieval fails. We need "What is Pinecone's pricing?"

---

## The Rewriting Solution

Before retrieval, rewrite the query to be **standalone**:

```python
history = [
    {"role": "user", "content": "Tell me about Pinecone"},
    {"role": "assistant", "content": "Pinecone is a vector database..."}
]
current = "What about its pricing?"

rewritten = "What is Pinecone's pricing?"
```

Now retrieval works!

---

## Pronoun Resolution

| Pronoun         | Resolution                    |
| --------------- | ----------------------------- |
| "it", "its"     | Most recent noun from history |
| "they", "their" | Most recent plural entity     |
| "this", "that"  | Most recent topic             |

### Rule-Based

```python

```

### LLM-Based

```python
prompt = f"""
Given this conversation history: {history}
Rewrite this follow-up to be standalone: {query}
"""
rewritten = llm.generate(prompt)
```

## ⚠️ Tradeoffs

### Rule-Based

- ✅ Fast (no LLM call)
- ❌ Limited patterns

### LLM-Based

- ✅ Handles complex cases
- ❌ Adds latency (+200ms)
- ❌ Cost per query
