## The Problem

Semantic similarity alone isn't enough. A **2019 revenue report** shouldn't outrank a **2024 revenue report** just because it has slightly better keyword overlap:

```python
# Without recency boost:
results = [
    ("Q3 2019 Revenue Report", score=0.92, date=2019-09-30),
    ("Q3 2024 Revenue Report", score=0.88, date=2024-09-30),
]
# ❌ Old report wins despite being outdated!
```

**Real-world impact**: Financial analysts, news aggregators, and policy researchers need the latest information, not the most semantically similar.

## The Solution: Time Decay

Use **exponential time decay** to boost recent documents:

```python
age_days = (reference_time - doc_timestamp) / 86400
boost = 1 / (1 + decay_factor * age_days)
new_score = original_score * boost
```

## Theoretical Foundation

### Decay Functions

| Function | Formula | Characteristics |
|----------|---------|-----------------|
| **Exponential** | $e^{-\lambda t}$ | Smooth, memoryless |
| **Hyperbolic** | $\frac{1}{1 + \lambda t}$ | Slower initial decay |
| **Step** | $1$ if $t < T$ else $0$ | Binary cutoff |
| **Gaussian** | $e^{-(t/\sigma)^2}$ | Bell-shaped decay |

### Hyperbolic Decay (Recommended)

$$\text{boost}(t) = \frac{1}{1 + \lambda t}$$

Where:
- $t$ = age in days
- $\lambda$ = decay factor (tuning parameter)

**Properties**:
- At $t = 0$: boost = 1.0 (no reduction)
- At $t = 1/\lambda$: boost = 0.5 (50% reduction)
- As $t \to \infty$: boost $\to$ 0 (complete decay)

### Tuning the Decay Factor

| Decay Factor (λ) | 1-day decay | 30-day decay | 1-year decay | Use Case |
|-----------------|-------------|--------------|--------------|----------|
| **0.01** | 99% | 77% | 21% | Academic papers, slow-changing docs |
| **0.1** | 91% | 25% | 0.03% | News, financial reports |
| **0.5** | 67% | 6% | ~0% | Real-time data, stock prices |
| **1.0** | 50% | 3% | ~0% | Breaking news, alerts |

## Production Considerations

### Metadata Requirements

Documents must have reliable timestamps:

```python
class Document:
    id: str
    content: str
    embedding: list[float]
    metadata: {
        "created_at": "2024-01-15T10:30:00Z",  # ISO 8601
        "updated_at": "2024-06-20T14:45:00Z",
        "published_at": "2024-01-16T09:00:00Z",
    }
```

**Which timestamp to use?**
- **News**: `published_at`
- **Docs**: `updated_at` (if available) else `created_at`
- **Financial**: `reporting_period_end`

### Combining with Other Signals

```python
def combined_score(
    semantic_score: float,
    recency_boost: float,
    popularity_boost: float = 1.0,
    authority_boost: float = 1.0,
) -> float:
    """
    Combine multiple ranking signals.
    
    All boosts are multiplicative:
    final_score = semantic * recency * popularity * authority
    """
    return semantic_score * recency_boost * popularity_boost * authority_boost
```

### Query-Dependent Recency

Not all queries need recency:

```python
RECENCY_SENSITIVE_QUERIES = [
    "latest", "recent", "news", "update",
    "2024", "this year", "last month",
    "current", "today", "now",
]

def needs_recency_boost(query: str) -> bool:
    """Detect if query is time-sensitive."""
    query_lower = query.lower()
    return any(term in query_lower for term in RECENCY_SENSITIVE_QUERIES)
```
