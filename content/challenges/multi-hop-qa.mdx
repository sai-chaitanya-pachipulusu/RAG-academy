# Multi-Hop Question Answering

Some questions can't be answered from a single document. They require "hopping" between multiple sources to connect information.

**Your task**: Build a multi-hop RAG system that can answer questions requiring 2-3 document lookups.

## Mathematical Foundation

### Multi-Hop Reasoning as Graph Traversal

Multi-hop QA can be modeled as finding paths in a knowledge graph:

$$
G = (V, E)
$$

Where:
- $V$ = Documents (nodes)
- $E$ = Entity overlaps between documents (edges)
- $\text{weight}(e_{ij}) = |\text{Entities}(d_i) \cap \text{Entities}(d_j)|$

### Hop Scoring

The relevance of a document at hop $t$:

$$
\text{score}_t(d) = \alpha \cdot \text{sim}(q, d) + \beta \cdot \max_{d' \in D_{t-1}} \text{overlap}(d, d') + \gamma \cdot \text{coverage}_t(d)
$$

Where:
- $\text{sim}(q, d)$ = Semantic similarity to query
- $\text{overlap}(d, d')$ = Entity overlap with previous hop
- $\text{coverage}_t(d)$ = New information coverage
- $\alpha + \beta + \gamma = 1$

### Stopping Criteria

Stop when:

$$
\text{answer\_confidence} > \theta \lor \text{hop\_count} \geq H_{\text{max}}
$$

## Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| Entity extraction | O(n × m) | O(e) |
| Graph construction | O(n² × e) | O(n²) |
| Single hop retrieval | O(n log n) | O(k) |
| Multi-hop (H hops) | O(H × n log n) | O(H × k) |
| Answer generation | O(G) | O(v) |

Where:
- n = number of documents
- m = average document length
- e = number of unique entities
- k = documents per hop
- H = number of hops
- G = generation time
- v = vocabulary size

## Common Pitfalls

1. **Infinite Hops**: No stopping criteria or cycle detection
2. **Irrelevant Hops**: Drifting away from original question
3. **Redundant Information**: Retrieving same facts multiple times
4. **Missing Connections**: Entity extraction failures break chains
5. **Context Overflow**: Too many hops exceed context window

## Advanced Techniques

### Entity-Guided Retrieval

```python
class EntityGuidedMultiHop:
    """Use entity linking to guide multi-hop retrieval."""
    
    def __init__(self, entity_linker, retriever):
        self.entity_linker = entity_linker
        self.retriever = retriever
        self.entity_graph = {}
    
    def retrieve(self, query: str, max_hops: int = 3) -> list[dict]:
        """Multi-hop retrieval using entity connections."""
        # Extract entities from query
        query_entities = self.entity_linker.extract(query)
        
        all_documents = []
        current_entities = query_entities
        
        for hop in range(max_hops):
            # Retrieve documents matching current entities
            docs = self.retriever.retrieve_by_entities(current_entities)
            
            # Filter out already seen documents
            new_docs = [d for d in docs if d not in all_documents]
            
            if not new_docs:
                break
            
            all_documents.extend(new_docs)
            
            # Extract new entities for next hop
            current_entities = self._extract_new_entities(new_docs, current_entities)
        
        return all_documents
    
    def _extract_new_entities(self, docs: list[dict], 
                              seen_entities: set) -> set:
        """Extract entities not yet seen."""
        new_entities = set()
        for doc in docs:
            doc_entities = self.entity_linker.extract(doc["content"])
            new_entities.update(doc_entities - seen_entities)
        return new_entities
```

### Beam Search for Multi-Hop

```python
class BeamSearchMultiHop:
    """Use beam search to explore multiple reasoning paths."""
    
    def __init__(self, beam_width: int = 3):
        self.beam_width = beam_width
    
    def search(self, query: str, documents: list[dict], max_hops: int) -> list[dict]:
        """Beam search over document chains."""
        # Initialize beam with top-k documents
        beam = self._initialize_beam(query, documents)
        
        for hop in range(max_hops):
            candidates = []
            
            for chain in beam:
                # Extend each chain with possible next documents
                extensions = self._extend_chain(chain, documents)
                candidates.extend(extensions)
            
            # Keep top beam_width chains
            beam = sorted(candidates, 
                         key=lambda c: c["score"], 
                         reverse=True)[:self.beam_width]
        
        # Return best chain
        return beam[0]["documents"]
    
    def _score_chain(self, chain: list[dict], query: str) -> float:
        """Score a document chain."""
        # Combine coverage, coherence, and relevance
        coverage = self._compute_coverage(chain, query)
        coherence = self._compute_coherence(chain)
        relevance = self._compute_relevance(chain, query)
        
        return 0.4 * coverage + 0.3 * coherence + 0.3 * relevance
```

### Confidence-Based Stopping

```python
class ConfidenceBasedStopper:
    """Stop when answer confidence is high enough."""
    
    def __init__(self, confidence_threshold: float = 0.8):
        self.threshold = confidence_threshold
    
    def should_stop(self, query: str, documents: list[dict], 
                   answer: str) -> bool:
        """Determine if we have enough information."""
        # Check if all query entities are covered
        query_entities = set(self.extract_entities(query))
        covered_entities = set()
        
        for doc in documents:
            covered_entities.update(self.extract_entities(doc["content"]))
        
        coverage = len(query_entities & covered_entities) / len(query_entities)
        
        # Check answer confidence
        answer_confidence = self._compute_answer_confidence(answer, documents)
        
        return coverage > 0.9 and answer_confidence > self.threshold
```

## Interview Questions

**Q1: How do you handle cases where multiple valid reasoning paths exist?**

*Answer:*
- Use beam search to explore multiple paths
- Score paths by coherence and coverage
- Aggregate answers from multiple paths
- Present alternative answers with confidence scores
- Use voting mechanism for final answer

**Q2: What signals indicate a reasoning chain has gone off track?**

*Answer:*
- Decreasing relevance scores across hops
- No new entities introduced in recent hops
- Semantic drift from original query
- Contradictions between documents
- Low answer confidence despite many hops

**Q3: Design a system that explains its multi-hop reasoning.**

*Answer:*
- Track reasoning chain: Query → Doc1 → Doc2 → ... → Answer
- For each hop, store: entity extracted, document retrieved, connection made
- Generate natural language explanation from chain
- Highlight supporting evidence in each document
- Show confidence at each hop
