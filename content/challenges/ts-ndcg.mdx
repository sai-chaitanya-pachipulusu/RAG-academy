## Why nDCG Matters in Production

nDCG considers both relevance and position: highly relevant documents at the top matter more. It's the standard for benchmarks like BEIR and MTEB. Unlike binary metrics, nDCG handles:

- **Graded relevance**: Documents can be highly, somewhat, or slightly relevant
- **Position discount**: Top ranks matter more than bottom ranks
- **Partial credit**: Better than binary hit/miss

### Real-World Scenario

Search results for "machine learning tutorial":

| Rank | Document | Relevance Grade | Gain |
|------|----------|-----------------|------|
| 1 | Comprehensive ML course | Highly relevant (3) | 3 |
| 2 | Quick ML intro | Somewhat relevant (2) | 2 |
| 3 | Advanced deep learning | Slightly relevant (1) | 1 |
| 4 | Cooking recipes | Not relevant (0) | 0 |

nDCG captures that rank 1 with grade 3 is better than rank 3 with grade 3.

## The Mathematical Foundation

### Cumulative Gain (CG)

Simple sum of relevance grades:

$$\text{CG}@k = \sum_{i=1}^{k} \text{rel}_i$$

Doesn't consider position.

### Discounted Cumulative Gain (DCG)

Add position discount:

$$\text{DCG}@k = \sum_{i=1}^{k} \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}$$

Or alternative formulation:

$$\text{DCG}@k = \sum_{i=1}^{k} \frac{\text{rel}_i}{\log_2(i + 1)}$$

Use the first (exponential) version when grades are on a log scale.

### Ideal DCG (IDCG)

DCG with perfect ranking (sorted by relevance descending):

$$\text{IDCG}@k = \sum_{i=1}^{k} \frac{2^{\text{rel}_i^{\text{sorted}}} - 1}{\log_2(i + 1)}$$

### Normalized DCG

$$\text{nDCG}@k = \frac{\text{DCG}@k}{\text{IDCG}@k}$$

Range: [0, 1] where 1 = perfect ranking.

## Theoretical Deep Dive

### The Discount Factor

Why $\log_2(i + 1)$?

| Position | Discount | Interpretation |
|----------|----------|----------------|
| 1 | $\log_2(2) = 1$ | Full value |
| 2 | $\log_2(3) ≈ 1.58$ | 63% value |
| 3 | $\log_2(4) = 2$ | 50% value |
| 10 | $\log_2(11) ≈ 3.46$ | 29% value |

The discount reflects that users pay less attention to lower ranks.

### Comparison with Binary Metrics

| Scenario | Binary (Precision) | nDCG |
|----------|-------------------|------|
| [Relevant, Not, Not, Not] | 0.25 | High (good top result) |
| [Not, Not, Not, Relevant] | 0.25 | Low (buried relevant) |
| [Highly, Somewhat, Slightly] | 1.0 | High (graded relevance) |

nDCG distinguishes these cases.

### Graded Relevance Scales

| Scale | Values | Use Case |
|-------|--------|----------|
| **Binary** | 0, 1 | Simple relevance |
| **3-point** | 0, 1, 2 | Not, somewhat, highly |
| **5-point** | 0-4 | Detailed judgments |
| **Continuous** | 0-1 | Model probabilities |

## Production Considerations

### Choosing k

Common nDCG@k values:

| k | Use Case |
|---|----------|
| @3 | Mobile, quick answers |
| @5 | Desktop search first page |
| @10 | Full first page |
| @100 | Deep evaluation |

### Handling Ties

When documents have equal relevance:
- **Conservative**: Assume worst-case ordering
- **Optimistic**: Assume best-case ordering
- **Average**: Average over all permutations

### Statistical Significance

```typescript
function bootstrapNDCG(
  queries: QueryResult[],
  k: number,
  iterations: number = 1000
): { mean: number; ci95: [number, number] } {
  const samples = [];
  for (let i = 0; i < iterations; i++) {
    const sample = resample(queries);
    samples.push(calculateNDCG(sample, k));
  }
  return {
    mean: mean(samples),
    ci95: [percentile(samples, 0.025), percentile(samples, 0.975)]
  };
}
```

### Validation Checklist

- [ ] Position 1 has discount log2(2) = 1
- [ ] Position 2 has discount log2(3) ≈ 1.585
- [ ] Uses 1-indexed positions
- [ ] IDCG calculated from sorted relevance
- [ ] nDCG = 1.0 for perfect ranking

- [ ] k limits consideration to top k
- [ ] Handles k > length gracefully

## Common Pitfalls

- **Using log2(i + 1) instead of log2(i + 2)**: i is 0-indexed in code
- **Not handling IDCG = 0**: Division by zero when all relevance scores are 0
- **Integer division**: Use floating-point arithmetic
- **Wrong formula variant**: Clarify if using exponential (2^rel - 1) or linear (rel)
- **0-indexed ranks**: Remember position 1 has i=0 in arrays
