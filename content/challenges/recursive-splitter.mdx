## The Strategy

This is the **default chunking strategy in LangChain** and for good reason: it's robust for any document type.

### The Fallback Ladder

```
1. Try to split by paragraph (\n\n)
   ↓ (if chunk too long)
2. Split by newline (\n)
   ↓ (if chunk too long)
3. Split by sentence (. )
   ↓ (if chunk too long)
4. Split by word (space)
   ↓ (if chunk too long)
5. Split by character (hard limit)
```

### Why It Works

| Document Type | Primary Separator | Fallback Behavior |
|--------------|-------------------|-------------------|
| Legal contract | Paragraphs | Long paragraphs → sentences |
| Code file | Newlines | Functions → lines |
| Markdown | Headers (##) | Sections → paragraphs |
| Plain text | Sentences | Words → characters |

The recursive approach **adapts to whatever structure the document has**.

## Theoretical Foundation

### Hierarchical Document Structure

Documents naturally have hierarchical structure:

```
Document
├── Section
│   ├── Paragraph
│   │   ├── Sentence
│   │   │   ├── Word
│   │   │   │   └── Character
```

Recursive splitting respects this hierarchy, trying coarse boundaries before fine ones.

### Semantic Preservation

| Level | Semantic Unit | Information Loss |
|-------|---------------|------------------|
| Paragraph | Complete argument | Minimal |
| Sentence | Complete thought | Low |
| Word | Partial meaning | High |
| Character | None | Maximum |

**Goal**: Stay as high in the hierarchy as possible while respecting size constraints.

### Chunk Size Trade-offs

| Chunk Size | Context Window | Retrieval Precision | Token Cost |
|------------|----------------|---------------------|------------|
| Small (200) | Low | High (specific) | Low |
| Medium (500) | Medium | Medium | Medium |
| Large (1000) | High | Low (broader) | High |

**Recommendation**: 300-500 tokens for most RAG applications.

## Production Implementations

### LangChain RecursiveCharacterTextSplitter

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    separators=["\n\n", "\n", ". ", " ", ""],
    chunk_size=1000,
    chunk_overlap=200,
    length_function=len,
)

chunks = splitter.split_text(text)
```

### Key Parameters

| Parameter | Purpose | Typical Value |
|-----------|---------|---------------|
| `chunk_size` | Target token count | 300-1000 |
| `chunk_overlap` | Context preservation | 50-200 |
| `separators` | Priority-ordered list | See below |
| `length_function` | How to measure size | `len` or tokenizer |

### Custom Separators by Document Type

```python
# Markdown
md_separators = ["\n## ", "\n### ", "\n\n", "\n", ". ", " ", ""]

# Code
code_separators = ["\nclass ", "\ndef ", "\n\tdef ", "\n\n", "\n", " ", ""]

# Legal
legal_separators = ["\n\nARTICLE", "\n\nSection", "\n\n", "\n", ". ", " ", ""]
```

## Advanced Considerations

### Overlap Strategy

Chunk overlap preserves context across boundaries:

```
Chunk 1: "The quick brown fox. Jumps over the lazy dog."
Chunk 2: "Jumps over the lazy dog. The end."
         ^^^^^^^^^^^^^^^^^^^^^^^^
         Overlap (last sentence of previous)
```

**Benefits**:
- Prevents information loss at boundaries
- Improves embedding continuity
- Better for sequential reasoning

**Costs**:
- Increased storage (10-20% more vectors)
- Potential redundancy in retrieval

### Token-Aware Splitting

Character count ≠ token count:

```python
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")

def token_length(text: str) -> int:
    return len(enc.encode(text))

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,  # tokens, not characters
    length_function=token_length,
)
```
