  Implement Reciprocal Rank Fusion (RRF) — the simplest robust hybrid retrieval fusion used in production.
</Callout>

## Why this matters in production

Hybrid retrieval typically runs multiple retrievers (BM25 + dense) and then **fuses** results.

RRF is popular because it’s:

- stable
- hard to overfit
- works even when score scales differ (BM25 scores vs cosine similarity scores)

## The scoring rule

For each doc in a ranked list:

\[
\mathrm{score}(doc)=\sum_{lists}\frac{1}{k + rank}
\]

Where `rank` is **1-based**.

## When to use RRF

- You have **two+ retrievers** with different scoring scales.
- You want a strong baseline before learning-to-rank.
- You don’t have time to tune many weights.

## Common pitfalls

- Using 0-based rank (off by one).
- Forgetting to sum across lists (docs appearing in both should be rewarded).
