## Why this matters in production

Cosine similarity answers: "Are these vectors pointing in the same direction?"

That's why it's used for embeddings:

- magnitude can vary with length/frequency
- direction tends to capture meaning

## What you're implementing

```
cos(θ) = (a · b) / (||a|| × ||b||)
```

Where:
- `a · b` = dot product
- `||a||` = magnitude (L2 norm) of vector a
- `||b||` = magnitude (L2 norm) of vector b

## The Algorithm

```python
import math

def cosine_similarity(a: list[float], b: list[float]) -> float:
    """
    Compute cosine similarity between two vectors.
    
    Time Complexity: O(N) where N = vector dimension
    Space Complexity: O(1) additional
    
    Args:
        a: First vector
        b: Second vector
        
    Returns:
        Cosine similarity in range [-1, 1]
        
    Raises:
        ValueError: If vectors have different lengths or zero magnitude
    """
    if len(a) != len(b):
        raise ValueError(f"Vector length mismatch: {len(a)} vs {len(b)}")
    
    # Compute dot product
    dot = sum(x * y for x, y in zip(a, b))
    
    # Compute magnitudes
    mag_a = math.sqrt(sum(x * x for x in a))
    mag_b = math.sqrt(sum(x * x for x in b))
    
    # Guard against zero magnitude
    if mag_a == 0 or mag_b == 0:
        raise ValueError("Cannot compute cosine similarity for zero vector")
    
    return dot / (mag_a * mag_b)
```

## Complexity Analysis

| Aspect | Complexity | Notes |
|--------|------------|-------|
| Time | O(N) | Two passes (dot + norms) |
| Space | O(1) | No additional storage |
| Range | [-1, 1] | 1 = identical, -1 = opposite, 0 = orthogonal |

## Edge Cases (Critical for Production)

| Scenario              | Expected Behavior          | Why                                    |
| --------------------- | -------------------------- | -------------------------------------- |
| Mismatched lengths    | `ValueError`               | Can't compare different dimensions     |
| Zero-magnitude vector | `ValueError`               | Division by zero (undefined direction) |
| Empty vs non-empty    | `ValueError`               | Dimension mismatch                     |
| Both empty            | `ValueError`               | No direction to compare                |
| Very small magnitudes | Potential precision issues | See numerical stability below          |
| Identical vectors     | Exactly `1.0`              | Same direction                         |
| Opposite vectors      | Exactly `-1.0`             | Opposite directions                    |
| Orthogonal vectors    | Exactly `0.0`              | No correlation                         |

## Numerical Stability Considerations

In production with float32 embeddings:

```python
# BAD: Can overflow with large vectors
mag = sqrt(sum(x*x for x in vec))  # sum can overflow

# BETTER: Use numpy's stable norm
import numpy as np
mag = np.linalg.norm(vec)

# BEST: Pre-normalize your vectors at indexing time
# Then cosine similarity = dot product (fast!)
```

**Pro tip**: Most embedding APIs return L2-normalized vectors. Check your provider's docs — if normalized, just use dot product directly.

## Common pitfalls

- Not guarding the zero-norm case.
- Computing norms incorrectly (must be sqrt(sum(x^2))).
- Floating-point precision: `1.0000000001` should clamp to `1.0`.
- Using L2 distance when you meant cosine (they're related but different).

## Cosine vs L2 Distance

| Metric            | Formula            | Range   | Use when                 |
| ----------------- | ------------------ | ------- | ------------------------ |
| Cosine similarity | dot / (mag * mag) | [-1, 1] | Semantic similarity      |
| Cosine distance   | 1 - cosine_sim     | [0, 2]  | Some vector DBs use this |
| L2 (Euclidean)    | sqrt(sum((a-b)^2)) | [0, ∞) | Magnitude matters        |
| Dot product       | sum(a * b)        | (-∞, ∞) | Normalized vectors       |

For normalized vectors: **cosine similarity = dot product** and **L2 distance ∝ 1 - cosine similarity**
