## Dimension Reduction: Matryoshka Embeddings

OpenAI's text-embedding-3 models support **Matryoshka Representation Learning** — you can truncate dimensions with minimal quality loss:

| Dimensions  | Relative Performance | Cost Savings |
| ----------- | -------------------- | ------------ |
| 3072 (full) | 100%                 | Baseline     |
| 1536        | 98.5%                | 50% storage  |
| 1024        | 97.2%                | 67% storage  |
| 512         | 94.8%                | 83% storage  |
| 256         | 90.1%                | 92% storage  |

**Recommendation**: Use 1024 or 1536 dimensions for most production use cases.

## Edge Cases & Gotchas

1. **Instruction prefixes matter**: Some models (E5, GritLM) need "query:" / "passage:" prefixes
2. **Normalization**: Some models output normalized vectors, some don't — check before using cosine
3. **Tokenizer limits**: Exceeding context silently truncates — always check
4. **Batching**: API rate limits vary; batch appropriately
5. **Version pinning**: Models update; pin versions for reproducibility

## Production Testing Protocol

Before committing to a model:

1. **Prepare golden set**: 50-100 query/relevant-doc pairs from YOUR domain
2. **Test Recall@10**: Must exceed 80% on your data
3. **Test latency**: P99 under your SLA (typically <100ms for embedding)
4. **Test edge cases**: Short queries, long docs, special chars, numbers
5. **Cost projection**: Calculate monthly cost at expected scale
6. **Fallback plan**: What if the API goes down? (Cache, open-source backup)

## Theoretical Deep Dive

### What Makes a Good Embedding?

A good embedding model maps semantically similar text to nearby vectors:

$$\text{similarity}(\text{embed}(t_1), \text{embed}(t_2)) \propto \text{semantic\_similarity}(t_1, t_2)$$

### Training Objectives

| Objective | Description | Example Models |
|-----------|-------------|----------------|
| **Contrastive** | Pull similar pairs together, push dissimilar apart | SimCSE, E5 |
| **Masked Language Model** | Predict masked tokens | BERT, RoBERTa |
| **Autoregressive** | Predict next token | GPT, Llama |
| **Multitask** | Combine multiple objectives | GritLM, Instructor |

### The Curse of Dimensionality

Higher dimensions don't always mean better:

- **768-1024 dims**: Sweet spot for most applications
- **3072+ dims**: Diminishing returns, higher storage costs
- **Matryoshka**: Allows dynamic dimension selection
