 Lost in the Middle Ordering

**Difficulty**: Tier 3 - Advanced Retrieval  
**Prerequisites**: Re-ranking Basics, Context Window Management  
**Time Estimate**: 2-3 hours

## Objective

Order retrieved context to mitigate the "lost in the middle" effect, placing the most important evidence at positions where LLMs pay most attention (beginning and end).

## Purpose

Even with long-context models, attention isn't uniform—earliest and latest tokens receive more attention than the middle. This challenge teaches you to structure context for maximum information extraction.

### Real-World Impact
- **Legal document review**: Critical clauses at start/end of context
- **Medical diagnosis**: Key symptoms not buried in middle
- **Technical support**: Error details in high-attention positions
- **Research synthesis**: Important findings prominently placed

## The Problem

**The U-Shaped Attention Curve:**

```
Attention Weight
    │
1.0 ┤●                                    ●
    │  ●                                ●
0.8 ┤    ●                            ●
    │      ●                        ●
0.6 ┤        ●                    ●
    │          ●                ●
0.4 ┤            ●            ●
    │              ●        ●
0.2 ┤                ●    ●
    │                  ●●
0.0 ┼────┬────┬────┬────┬────┬────┬────┬────→ Position
    Start                          Middle                          End
```

**Research Finding**: LLM accuracy drops to ~50% when the correct answer is in the middle of a long prompt (Stanford et al., 2023).

### Why This Happens

1. **Positional encoding decay**: Sinusoidal encodings lose precision at distance
2. **Softmax normalization**: Middle positions compete with many tokens
3. **Training bias**: Documents often have important info at start/end
4. **Context window pressure**: Models learn to prioritize recent information

## Theory

### The "Lost in the Middle" Phenomenon

From the paper "Lost in the Middle: How Language Models Use Long Contexts":

| Answer Position | Accuracy |
|----------------|----------|
| Beginning | 85% |
| Early Middle | 70% |
| Center | 52% |
| Late Middle | 68% |
| End | 82% |

**Implication**: Information in the middle is effectively "lost" to the model.

### Ordering Strategies

**1. U-Shaped Ordering (Recommended)**
```
Position:  1    2    3    4    5    6    7    8
Rank:      1    3    5    7    8    6    4    2

Best doc at position 1, 2nd best at end (position 8),
3rd best at position 2, 4th best at position 7, etc.
```

**2. Descending Order**
```
Position:  1    2    3    4    5    6    7    8
Rank:      1    2    3    4    5    6    7    8

Simple, but buries middle-ranked docs.
```

**3. Ascending Order**
```
Position:  1    2    3    4    5    6    7    8
Rank:      8    7    6    5    4    3    2    1

Worst first, best last. Risk: model ignores early context.
```

### Mathematical Formulation

For U-shaped ordering with n documents:

```
position(i) = {
    2i - 1           if i ≤ ⌈n/2⌉  (odd positions from start)
    2(n - i + 1)     if i > ⌈n/2⌉  (even positions from end)
}

Where i is the rank (1 = best, n = worst)
```

**Example (n=5):**
| Rank | Position | Calculation |
|------|----------|-------------|
| 1 | 1 | 2(1) - 1 = 1 |
| 2 | 5 | 2(5 - 2 + 1) = 8? No, 2(5-2+1) for even... |

Corrected:
- i=1 (rank 1): position 1
- i=2 (rank 2): position 5 (last)
- i=3 (rank 3): position 2
- i=4 (rank 4): position 4
- i=5 (rank 5): position 3 (middle)

Result order by position: [1, 3, 5, 4, 2]

## Challenges

### Challenge 1: U-Shaped Ordering

Implement the U-shaped ordering algorithm.

**Acceptance Criteria:**
- Place highest relevance docs at positions 1 and n
- Place 2nd highest at positions 2 and n-1
- Continue alternating from start and end
- Handle both even and odd numbers of documents

**Example:**
```
Input ranks (by relevance): [A, B, C, D, E, F]

U-shaped output order: [A, C, E, F, D, B]

Position mapping:
  1: A (rank 1)
  2: C (rank 3)
  3: E (rank 5)
  4: F (rank 6)
  5: D (rank 4)
  6: B (rank 2)
```

### Challenge 2: Query-Aware Ordering

Some queries need different ordering strategies.

**Acceptance Criteria:**
- Factual queries: U-shaped (evidence at start/end)
- List queries: Descending (all items important)
- Comparison queries: Interleaved (alternating sources)
- Document strategy selection with > 75% accuracy

### Challenge 3: Position-Aware Reranking

Adjust relevance scores based on expected attention.

**Acceptance Criteria:**
- Apply position attention weights to relevance scores
- Weight formula: w(pos) = 1 + α × |pos - center| / center
- Find optimal α through grid search
- Show improvement over unweighted ordering

**Position Weights (α=0.5):**
```
Position: 1    2    3    4    5    6    7    8
Weight:  1.43 1.29 1.14 1.00 1.00 1.14 1.29 1.43
```

## Starter Code

```python
from typing import List, Tuple, Callable
from dataclasses import dataclass
import numpy as np

@dataclass
class ScoredDocument:
    id: str
    text: str
    relevance: float

class ContextOrderer:
    """
    Order documents to mitigate "lost in the middle" effect.
    """
    
    def __init__(self, strategy: str = "u_shaped"):
        """
        Args:
            strategy: Ordering strategy ("u_shaped", "descending", "ascending", "interleaved")
        """
        self.strategy = strategy
        
    def order(self, documents: List[ScoredDocument]) -> List[ScoredDocument]:
        """
        Order documents according to strategy.
        
        Args:
            documents: List of documents with relevance scores
            
        Returns:
            Ordered list of documents
        """
        if not documents:
            return []
            
        # Sort by relevance descending
        sorted_docs = sorted(documents, key=lambda d: -d.relevance)
        
        if self.strategy == "u_shaped":
            return self._u_shaped_order(sorted_docs)
        elif self.strategy == "descending":
            return sorted_docs
        elif self.strategy == "ascending":
            return list(reversed(sorted_docs))
        elif self.strategy == "interleaved":
            return self._interleaved_order(sorted_docs)
        else:
            raise ValueError(f"Unknown strategy: {self.strategy}")
            
    def _u_shaped_order(self, sorted_docs: List[ScoredDocument]) -> List[ScoredDocument]:
        """
        U-shaped ordering: best at start and end, alternating.
        
        Algorithm:
        - Place rank 1 at position 1
        - Place rank 2 at position n
        - Place rank 3 at position 2
        - Place rank 4 at position n-1
        - Continue...
        """
        n = len(sorted_docs)
        result = [None] * n
        
        left = 0      # Fill from left
        right = n - 1 # Fill from right
        
        for i, doc in enumerate(sorted_docs):
            if i % 2 == 0:
                # Even index (0, 2, 4...) → fill from left
                result[left] = doc
                left += 1
            else:
                # Odd index (1, 3, 5...) → fill from right
                result[right] = doc
                right -= 1
                
        return result
        
    def _interleaved_order(self, sorted_docs: List[ScoredDocument]) -> List[ScoredDocument]:
        """
        Interleave documents from different sources.
        Assumes documents have source information.
        """
        # Group by source
        from collections import defaultdict
        by_source = defaultdict(list)
        for doc in sorted_docs:
            source = getattr(doc, 'source', 'default')
            by_source[source].append(doc)
            
        # Round-robin from each source
        result = []
        sources = list(by_source.keys())
        source_iters = {s: iter(docs) for s, docs in by_source.items()}
        
        while len(result) < len(sorted_docs):
            for source in sources:
                try:
                    result.append(next(source_iters[source]))
                except StopIteration:
                    continue
                    
        return result
        
    def apply_position_weights(self, 
                              documents: List[ScoredDocument],
                              alpha: float = 0.5) -> List[ScoredDocument]:
        """
        Adjust relevance scores based on position attention.
        
        Higher positions (start and end) get boosted.
        """
        n = len(documents)
        if n == 0:
            return documents
            
        center = (n - 1) / 2
        weighted = []
        
        for i, doc in enumerate(documents):
            # Distance from center (0 at center, max at edges)
            distance = abs(i - center)
            
            # Weight: 1 + alpha × normalized distance
            weight = 1 + alpha * (distance / center if center > 0 else 0)
            
            # Apply weight to relevance
            adjusted_relevance = doc.relevance * weight
            
            weighted.append(ScoredDocument(
                id=doc.id,
                text=doc.text,
                relevance=adjusted_relevance
            ))
            
        return weighted
        
    def select_strategy(self, query: str) -> str:
        """
        Select ordering strategy based on query type.
        
        Heuristics:
        - Factual/definition queries → u_shaped
        - List/enumeration queries → descending
        - Comparison queries → interleaved
        - Summary queries → descending
        """
        query_lower = query.lower()
        
        # Comparison indicators
        comparison_words = ['compare', 'difference', 'versus', 'vs', 'better']
        if any(w in query_lower for w in comparison_words):
            return "interleaved"
            
        # List indicators
        list_words = ['list', 'enumerate', 'all', 'examples']
        if any(w in query_lower for w in list_words):
            return "descending"
            
        # Default: u_shaped for most queries
        return "u_shaped"
        
    def evaluate_ordering(self,
                         ordered_docs: List[ScoredDocument],
                         answer_positions: List[int]) -> Dict[str, float]:
        """
        Evaluate how well ordering helps find answers.
        
        Args:
            answer_positions: Indices where answers were found
            
        Returns:
            Metrics dict
        """
        if not answer_positions:
            return {}
            
        n = len(ordered_docs)
        
        # Categorize positions
        start_positions = list(range(int(n * 0.25)))
        middle_positions = list(range(int(n * 0.25), int(n * 0.75)))
        end_positions = list(range(int(n * 0.75), n))
        
        start_hits = sum(1 for p in answer_positions if p in start_positions)
        middle_hits = sum(1 for p in answer_positions if p in middle_positions)
        end_hits = sum(1 for p in answer_positions if p in end_positions)
        
        total = len(answer_positions)
        
        return {
            'start_recall': start_hits / total,
            'middle_recall': middle_hits / total,
            'end_recall': end_hits / total,
            'position_bias': abs((start_hits + end_hits) / 2 - middle_hits) / total
        }
```

```python
def analyze_attention_weights(model, tokenizer, context: str, query: str):
    """
    Extract attention weights to verify ordering effectiveness.
    """
    inputs = tokenizer(query + " " + context, return_tensors="pt")
    
    with torch.no_grad():
        outputs = model(**inputs, output_attentions=True)
        
    # Average attention across layers and heads
    attentions = torch.stack(outputs.attentions).mean(dim=(0, 1))
    
    # Get attention to context tokens
    query_len = len(tokenizer.tokenize(query))
    context_attention = attentions[query_len:].mean(dim=0)
    
    return context_attention.numpy()
```

### 2. Dynamic Position Weighting

Learn optimal position weights from data:

```python
def learn_position_weights(training_data: List[Tuple[List[ScoredDocument], int]]):
    """
    Learn position weights that maximize answer finding.
    
    Args:
        training_data: List of (ordered_docs, answer_position)
    """
    from scipy.optimize import minimize
    
    def objective(weights):
        total_loss = 0
        for docs, answer_pos in training_data:
            # Compute weighted scores
            weighted_scores = [d.relevance * weights[i] 
                             for i, d in enumerate(docs)]
            
            # Loss: want answer position to have high score
            answer_score = weighted_scores[answer_pos]
            max_score = max(weighted_scores)
            
            # Minimize difference between answer score and max
            total_loss += (max_score - answer_score) ** 2
            
        return total_loss
        
    # Initialize with uniform weights
    n_positions = max(len(docs) for docs, _ in training_data)
    initial_weights = np.ones(n_positions)
    
    # Optimize
    result = minimize(objective, initial_weights, 
                     method='L-BFGS-B',
                     bounds=[(0.5, 2.0)] * n_positions)
    
    return result.x
```

### 3. Chunk Size Optimization

Smaller chunks reduce "lost in the middle":

```python
def optimal_chunk_size(context_length: int, num_chunks: int) -> int:
    """
    Compute optimal chunk size given context constraints.
    
    Trade-off:
    - Larger chunks: more context per chunk
    - Smaller chunks: less "lost in the middle" per chunk
    """
    # Empirical: keep chunks under 200 tokens for best attention
    max_chunk_tokens = 200
    
    # Available tokens for context
    available_tokens = context_length - 500  # Reserve for query and generation
    
    # Optimal: as many small chunks as fit
    optimal_chunks = available_tokens // max_chunk_tokens
    
    return min(optimal_chunks, num_chunks)
```

```python
def check_position_bias(answer_positions: List[int], n_docs: int):
    """Alert if answers consistently in certain positions."""
    from collections import Counter
    
    position_counts = Counter(answer_positions)
    
    # Check for middle avoidance
    middle_start = n_docs // 4
    middle_end = 3 * n_docs // 4
    middle_count = sum(position_counts[i] 
                      for i in range(middle_start, middle_end))
```

## Summary

The "lost in the middle" effect is a fundamental limitation of transformer attention. U-shaped ordering is a simple, effective mitigation.

**Key Takeaways:**
1. **Attention is U-shaped**: Middle positions get less attention
2. **U-shaped ordering**: Best docs at start AND end
3. **Query-aware**: Different strategies for different query types
4. **Position weights**: Boost scores for high-attention positions
5. **Monitor bias**: Track where answers are found

Don't let your best evidence get lost in the middle!
