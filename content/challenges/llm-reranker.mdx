## When to Use LLM Reranking

Cross-encoders are great for "Is this relevant?" questions, but LLMs can answer complex questions like "Which of these documents **contradicts** the other?"

### Use Cases

- **Complex reasoning**: "Find the document that provides counter-evidence"
- **Multi-hop queries**: "Find docs about X that also mention Y"
- **Nuanced relevance**: "Which doc would a lawyer prefer?"
- **Comparative analysis**: "Which document is more authoritative?"

### The Tradeoff

| Approach | Speed | Cost | Quality | Best For |
|----------|-------|------|---------|----------|
| Bi-Encoder | Fast (<10ms) | Cheap | Good | Initial retrieval |
| Cross-Encoder | Medium (~100ms) | Medium | Great | Standard reranking |
| LLM Reranker | Slow (~1s) | Expensive | Best* | Complex queries |

\*For complex queries only; overkill for simple lookups.

## Theoretical Foundation

### Why LLMs Excel at Reranking

Traditional rerankers (cross-encoders) are trained on specific relevance judgments. LLMs bring:

1. **Broad world knowledge**: Understand domain-specific terminology
2. **Reasoning capabilities**: Can evaluate "which document better answers..."
3. **Instruction following**: Adapt to custom relevance criteria
4. **Context understanding**: Grasp nuanced relationships between query and documents

### The Reranking Pipeline

```
Query → [Bi-Encoder Retrieval: 100 docs] → [Cross-Encoder: 20 docs] → [LLM Reranker: 5 docs]
         (Fast, approximate)                (Medium, accurate)          (Slow, precise)
```

**Cascading approach**: Each stage filters for the next, optimizing cost vs. quality.

### LLM Reranking Prompts

#### Basic Relevance

```
Rate how relevant this document is to the query on a scale of 0-10.

Query: {query}
Document: {document}

Relevance score (0-10):
```

#### Comparative Ranking

```
Rank the following documents by relevance to the query. 
Consider: accuracy, authority, and completeness.

Query: {query}

Documents:
1. {doc1}
2. {doc2}
3. {doc3}

Ranked order (most relevant first):
```

#### Structured Scoring

```
Evaluate this document for the query across multiple dimensions:

Query: {query}
Document: {document}

Score each (0-10):
- Relevance: ___
- Authority: ___
- Recency: ___
- Comprehensiveness: ___

Total score: ___
```

## Production Considerations

### Cost Optimization

LLM reranking is expensive. Strategies to reduce costs:

| Strategy | Savings | Implementation |
|----------|---------|----------------|
| **Token truncation** | 50-70% | Truncate docs to 200-300 tokens |
| **Batch scoring** | 30-50% | Score multiple docs in one prompt |
| **Early termination** | 20-40% | Stop if top score is very high |
| **Caching** | Variable | Cache frequent query patterns |
| **Selective reranking** | 60-80% | Only rerank ambiguous cases |

### Latency Management

```python
import asyncio

async def llm_rerank_async(query: str, docs: list[str]) -> list[tuple[int, float]]:
    """
    Parallel LLM scoring for multiple documents.
    """
    tasks = [score_document(query, doc) for doc in docs]
    scores = await asyncio.gather(*tasks)
    return sorted(enumerate(scores), key=lambda x: -x[1])
```

### Hybrid Approach

```python
def smart_rerank(query: str, docs: list[str]) -> list[str]:
    """
    Use LLM reranking only when needed.
    """
    # Fast cross-encoder pass
    cross_scores = cross_encoder.score(query, docs)
    
    # If top scores are very close, use LLM to break ties
    if max(cross_scores) - min(cross_scores[:5]) < 0.1:
        return llm_rerank(query, docs[:10])
    
    return docs[:5]
```
