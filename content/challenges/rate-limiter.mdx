## The Problem

LLM APIs are expensive. One bad actor — or one buggy script — can drain your monthly budget in minutes:

```python
# Without rate limiting:
while True:
    response = rag_api.query(user_input)  # $0.01 per call
    # 6000 calls/minute = $360/hour = $8,640/day!
```

**Real-world impact**: Production RAG systems need rate limiting to:
- Prevent abuse and DDoS attacks
- Ensure fair resource allocation
- Control costs and prevent billing surprises
- Maintain service stability

## How Token Bucket Works

### The Algorithm

1. **Bucket** starts full of tokens (e.g., 100 tokens)
2. Each request **consumes** a token
3. Tokens **refill** over time (e.g., 10 tokens/sec)
4. If bucket is empty, request is **rejected** (HTTP 429)

### Visual Representation

```
Time →

Bucket: [██████████] 100 tokens (full)
Request 1: [████████░] 90 tokens (-10)
Request 2: [███████░░] 80 tokens (-10)
... (time passes, refills) ...
Refill: [██████████] 100 tokens (+20 over 2 sec)
Burst: [░░░░░░░░░░] 0 tokens (10 rapid requests)
Reject: HTTP 429 Too Many Requests
```

### Why Token Bucket?

| Algorithm | Burst Handling | Smooth Rate | Implementation |
|-----------|---------------|-------------|----------------|
| **Token Bucket** | ✅ Excellent | ✅ Smooth | ✅ Simple |
| Fixed Window | ❌ Poor | ❌ Jagged | ✅ Simple |
| Sliding Window | ⚠️ Good | ✅ Smooth | ❌ Complex |
| Leaky Bucket | ❌ None | ✅ Smooth | ⚠️ Moderate |

**Token bucket is the industry standard** for APIs that need to allow bursts while maintaining sustainable average rates.

## Theoretical Foundation

### Mathematical Model

The token bucket is a **leaky bucket with a faucet**:

$$\text{tokens}(t) = \min(C, \text{tokens}(t_0) + r \cdot (t - t_0) - \sum_{\text{requests}} c_i)$$

Where:
- $C$ = bucket capacity (max burst)
- $r$ = refill rate (tokens/second)
- $c_i$ = cost of request $i$

### Rate Limiting Strategies

| Strategy | Bucket Size | Refill Rate | Use Case |
|----------|-------------|-------------|----------|
| **Conservative** | 10 | 1/sec | Critical endpoints |
| **Standard** | 100 | 10/sec | General API |
| **Generous** | 1000 | 100/sec | Internal services |
| **Burst-friendly** | 1000 | 10/sec | Batch operations |

### Cost-Based Rate Limiting

Different operations have different costs:

```python
COSTS = {
    "query": 1,           # 1 token
    "generate": 10,       # 10 tokens (uses LLM)
    "embed": 5,           # 5 tokens (embedding API)
    "index": 20,          # 20 tokens (write operation)
}

def consume_for_operation(bucket: TokenBucket, operation: str) -> bool:
    cost = COSTS.get(operation, 1)
    return bucket.consume(cost)
```

## Production Considerations

### Distributed Rate Limiting

Single-server token buckets don't work in distributed systems:

```python
# Redis-based distributed rate limiting
import redis

class DistributedTokenBucket:
    def __init__(self, redis_client: redis.Redis, key: str, capacity: int, refill_rate: float):
        self.redis = redis_client
        self.key = key
        self.capacity = capacity
        self.refill_rate = refill_rate
    
    def consume(self, tokens: int = 1) -> bool:
        # Lua script for atomic operation
        script = """
            local key = KEYS[1]
            local capacity = tonumber(ARGV[1])
            local refill_rate = tonumber(ARGV[2])
            local requested = tonumber(ARGV[3])
            local now = tonumber(ARGV[4])
            
            local bucket = redis.call('HMGET', key, 'tokens', 'last_refill')
            local current_tokens = tonumber(bucket[1]) or capacity
            local last_refill = tonumber(bucket[2]) or now
            
            -- Calculate refill
            local delta = now - last_refill
            local new_tokens = math.min(capacity, current_tokens + delta * refill_rate)
            
            -- Check and deduct
            if new_tokens >= requested then
                new_tokens = new_tokens - requested
                redis.call('HMSET', key, 'tokens', new_tokens, 'last_refill', now)
                return 1
            else
                redis.call('HSET', key, 'last_refill', now)
                return 0
            end
        """
        now = time.time()
        result = self.redis.eval(script, 1, self.key, self.capacity, 
                                 self.refill_rate, tokens, now)
        return bool(result)
```

### Per-User Rate Limiting

```python
class UserRateLimiter:
    def __init__(self):
        self.buckets: dict[str, TokenBucket] = {}
    
    def get_bucket(self, user_id: str) -> TokenBucket:
        if user_id not in self.buckets:
            self.buckets[user_id] = TokenBucket(
                capacity=100,
                refill_rate=10
            )
        return self.buckets[user_id]
    
    def allow_request(self, user_id: str) -> bool:
        bucket = self.get_bucket(user_id)
        return bucket.consume(1)
```

### Validation Checklist

- [ ] Bucket starts full
- [ ] First N requests allowed (where N = capacity)
- [ ] Request N+1 rejected when no refill
- [ ] Tokens refill over time
- [ ] Refilled tokens allow more requests
- [ ] Never exceeds capacity (no overflow)
