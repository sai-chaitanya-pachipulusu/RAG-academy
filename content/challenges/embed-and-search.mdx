  Build an end-to-end "toy" dense retrieval loop without any external embedding APIs.
</Callout>

## Why this matters in production

You shouldn't start learning RAG by wiring 6 vendors together.

This lab forces you to understand the mechanics:

- embed docs
- embed query
- score
- return Top‑K

In production you'll swap toy embeddings for a real model — the retrieval logic stays.

## What you're implementing

- a deterministic "toy embedding" function (hashing into buckets)
- cosine scoring
- a `search()` function returning top‑k doc indices + scores

## The Algorithm

```python
import hashlib
import numpy as np

def toy_embed(text: str, dim: int = 128) -> np.ndarray:
    """
    Create deterministic toy embedding from text.
    
    Time Complexity: O(L) where L = text length
    Space Complexity: O(dim) for output vector
    
    Args:
        text: Input text
        dim: Embedding dimension
        
    Returns:
        Normalized embedding vector
    """
    # Use hash for deterministic but "semantic" behavior
    hash_val = hashlib.md5(text.encode()).hexdigest()
    
    # Generate vector from hash
    np.random.seed(int(hash_val[:8], 16))
    vec = np.random.randn(dim)
    
    # Normalize
    return vec / np.linalg.norm(vec)

class ToyRetriever:
    """Simple dense retrieval system with toy embeddings."""
    
    def __init__(self, dim: int = 128):
        self.dim = dim
        self.documents = []
        self.embeddings = []
    
    def index(self, documents: list[str]):
        """Index documents with toy embeddings."""
        self.documents = documents
        self.embeddings = [toy_embed(doc, self.dim) for doc in documents]
    
    def search(self, query: str, k: int = 5) -> list[tuple[int, float]]:
        """
        Search for top-k similar documents.
        
        Time Complexity: O(N × d) where N = docs, d = dimension
        """
        query_vec = toy_embed(query, self.dim)
        
        # Score all documents
        scores = []
        for i, doc_vec in enumerate(self.embeddings):
            similarity = np.dot(query_vec, doc_vec)  # Cosine for normalized vectors
            scores.append((i, similarity))
        
        # Return top k
        scores.sort(key=lambda x: x[1], reverse=True)
        return scores[:k]
```

## Complexity Analysis

| Aspect | Complexity | Notes |
|--------|------------|-------|
| Indexing | O(N × L) | N docs, L = avg length |
| Search | O(N × d) | Linear scan (brute force) |
| Space | O(N × d) | Store all embeddings |

## Real-World Applications

The pattern you learn here scales to production:

| Component | Toy Version | Production Version |
|-----------|-------------|-------------------|
| **Embedding** | Hash-based | OpenAI, Cohere, or fine-tuned models |
| **Scoring** | Cosine similarity | Cosine, dot product, or learned metrics |
| **Index** | Brute force | HNSW, IVF, or approximate nearest neighbors |
| **Top-K** | Sort all | Optimized heap-based selection |

## The Full Loop

```python
# 1. Index documents (offline)
retriever = ToyRetriever()
retriever.index(documents)

# 2. Query (online)
results = retriever.search("machine learning", k=5)
# Returns: [(doc_index, score), ...]

# 3. Display results
for idx, score in results:
    print(f"Score: {score:.3f} | Doc: {documents[idx][:50]}...")
```

## Common pitfalls

- Using Python's built-in `hash()` (not stable across runs).
- Not normalizing/scoring consistently.
- Forgetting to handle empty queries.
