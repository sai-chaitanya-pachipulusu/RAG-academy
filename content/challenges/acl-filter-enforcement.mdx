<Callout title="Goal" variant="info">
  Enforce **ACL/role filters at retrieval time** (deny-by-default) so the model never sees unauthorized chunks.
</Callout>

## Why this matters (non-negotiable)

In production, you cannot rely on prompts like "don't leak data."

If unauthorized content is in the retrieved context window, the system can leak it.

So the rule is:

> **ACL first. Retrieval second.**

## What you'll implement

- Allow if user roles intersect chunk allowed roles
- Deny by default if ACL metadata is missing
- Admin override

## Mathematical Foundation

### Role-Based Access Control (RBAC)

The access decision can be modeled as a set intersection problem:

$$
\text{Access Granted} = \begin{cases}
\text{True} & \text{if } R_{\text{user}} \cap R_{\text{chunk}} \neq \emptyset \text{ or } \text{admin} \in R_{\text{user}} \\
\text{False} & \text{otherwise}
\end{cases}
$$

Where:
- $R_{\text{user}}$ = Set of roles assigned to the user
- $R_{\text{chunk}}$ = Set of roles allowed to access the chunk

### Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| Role check (set intersection) | O(min(\|R_user\|, \|R_chunk\|)) | O(1) |
| ACL filtering (n chunks) | O(n × r) | O(k) |
| Admin override check | O(1) | O(1) |

Where n = number of chunks, r = average roles per chunk, k = filtered results

## Common Pitfalls

1. **Default-Allow Bug**: Forgetting to deny when ACL metadata is missing
2. **Role Inheritance**: Not handling hierarchical roles (e.g., "manager" implies "employee")
3. **Case Sensitivity**: "Admin" ≠ "admin" in string comparisons
4. **Filter Bypass**: Allowing retrieval without ACL check in "debug" mode
5. **Race Conditions**: ACL changes during multi-stage retrieval

### Dynamic ACL Updates

Handle real-time permission changes:

```python
class DynamicACLManager:
    def __init__(self):
        self.acl_cache = {}  # Cache for performance
        self.version_counter = 0
    
    def update_acl(self, chunk_id: str, new_roles: set):
        """Update ACL and invalidate cache."""
        self.acl_cache[chunk_id] = new_roles
        self.version_counter += 1
    
    def check_access(self, chunk_id: str, user_roles: set, acl_version: int) -> bool:
        """Check access with version validation."""
        if acl_version != self.version_counter:
            # ACL changed during query - revalidate
            return self._revalidate(chunk_id, user_roles)
        return bool(self.acl_cache.get(chunk_id, set()) & user_roles)
```

## Interview Questions

### FAANG-Style Questions

**Q1: Design a system that handles 10M chunks with 100K concurrent users and complex ACL rules.**

*Answer approach:*
- Use bitmap indexes for role membership (1 bit per role)
- Pre-filter at vector DB level using metadata filters
- Cache ACL decisions with TTL
- Shard by tenant for horizontal scaling

**Q2: How would you handle ACL inheritance (e.g., folder → document → chunk)?**

*Answer approach:*
- Compute effective ACL at indexing time (denormalize)
- Store inheritance chain for audit purposes
- Use union of all parent ACLs with most restrictive wins

**Q3: What happens if ACL service is down during retrieval?**

*Answer approach:*
- Fail closed (deny all) for security
- Use cached ACLs with short TTL
- Circuit breaker pattern to degraded mode
