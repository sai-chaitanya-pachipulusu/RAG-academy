# BERT vs Sentence Transformers: Which Embeddings for RAG?

A common confusion in RAG is whether to use **BERT** or **Sentence Transformers** for embeddings. They're related but optimized for different tasks.

## The Key Difference

| Aspect              | BERT                                | Sentence Transformers                 |
| ------------------- | ----------------------------------- | ------------------------------------- |
| **Objective**       | Predict masked words, next sentence | Sentence-level semantic similarity    |
| **Embedding level** | Token-level (one per word)          | Sentence-level (one per sentence)     |
| **Training data**   | General text corpora                | Sentence pairs with similarity labels |
| **Architecture**    | Single encoder                      | Siamese/Triplet networks              |
| **Best for**        | Token-level tasks (NER, QA)         | Sentence similarity, retrieval        |

## Why This Matters for RAG

For RAG, you need to compare **whole chunks** to **queries**. This is sentence-level comparison:

```python
# What we need for RAG:
query = "What is the capital of France?"
chunk = "Paris is the capital city of France, located on the Seine River."

# We need ONE vector per text, not one per token
similarity = cosine_similarity(embed(query), embed(chunk))
```

## The Problem with Raw BERT

BERT produces **one vector per token**. To get a sentence embedding, you must aggregate:

```python
def bert_sentence_embedding(text: str, bert_model) -> np.ndarray:
    """
    Get sentence embedding from BERT.

    Common approaches:
    1. Use [CLS] token embedding
    2. Mean pooling of all tokens
    3. Max pooling of all tokens
    """
    outputs = bert_model(text)
    token_embeddings = outputs.last_hidden_state  # [batch, seq_len, hidden_dim]

    # Option 1: [CLS] token (NOT great for similarity)
    cls_embedding = token_embeddings[:, 0, :]

    # Option 2: Mean pooling (better)
    attention_mask = outputs.attention_mask
    input_mask_expanded = attention_mask.unsqueeze(-1).expand(token_embeddings.size())
    mean_embedding = torch.sum(token_embeddings * input_mask_expanded, 1) / torch.clamp(
        input_mask_expanded.sum(1), min=1e-9
    )

    return mean_embedding.numpy()
```

**Problem**: BERT wasn't trained to make these aggregated embeddings semantically meaningful!

## Why Sentence Transformers Work Better

Sentence Transformers are specifically trained for semantic similarity:

```python
from sentence_transformers import SentenceTransformer

# This model was trained for similarity tasks
model = SentenceTransformer('all-MiniLM-L6-v2')

# Single vector per sentence, optimized for similarity
query_embedding = model.encode("What is the capital of France?")
chunk_embedding = model.encode("Paris is the capital of France.")

# These embeddings are DESIGNED to be compared
similarity = cosine_similarity([query_embedding], [chunk_embedding])[0][0]
# Output: 0.87 (high similarity - correct!)
```

## Training Differences

### BERT Training

```
Input: "The [MASK] sat on the mat."
Task: Predict that [MASK] = "cat"

Input: "Sentence A" + "Sentence B"
Task: Are these consecutive sentences? (Yes/No)
```

### Sentence Transformer Training

```
Input: ("A dog is running", "A canine is jogging")
Task: These should have HIGH similarity (0.9+)

Input: ("A dog is running", "The stock market crashed")
Task: These should have LOW similarity (0.1-)
```

## When to Use Each

| Use Case                     | Recommendation        | Why                      |
| ---------------------------- | --------------------- | ------------------------ |
| **RAG retrieval**            | Sentence Transformers | Optimized for similarity |
| **Named Entity Recognition** | BERT                  | Token-level task         |
| **Question Answering**       | BERT (fine-tuned)     | Span extraction          |
| **Semantic search**          | Sentence Transformers | Sentence-level matching  |
| **Document clustering**      | Sentence Transformers | Need document vectors    |

## Key Takeaways

1. **BERT** = token-level, not designed for sentence similarity
2. **Sentence Transformers** = sentence-level, trained for similarity
3. For RAG, **always prefer Sentence Transformers** or similar embedding models
4. Popular choices: `all-MiniLM-L6-v2`, `all-mpnet-base-v2`, OpenAI `text-embedding-3-small`
