# BERT vs Sentence Transformers: Which Embeddings for RAG?

A common confusion in RAG is whether to use **BERT** or **Sentence Transformers** for embeddings. They're related but optimized for different tasks.

## The Key Difference

| Aspect              | BERT                                | Sentence Transformers                 |
| ------------------- | ----------------------------------- | ------------------------------------- |
| **Objective**       | Predict masked words, next sentence | Sentence-level semantic similarity    |
| **Embedding level** | Token-level (one per word)          | Sentence-level (one per sentence)     |
| **Training data**   | General text corpora                | Sentence pairs with similarity labels |
| **Architecture**    | Single encoder                      | Siamese/Triplet networks              |
| **Best for**        | Token-level tasks (NER, QA)         | Sentence similarity, retrieval        |

## Why This Matters for RAG

For RAG, you need to compare **whole chunks** to **queries**. This is sentence-level comparison:

```python
# What we need for RAG:
query = "What is the capital of France?"
chunk = "Paris is the capital city of France, located on the Seine River."

# We need ONE vector per text, not one per token
similarity = cosine_similarity(embed(query), embed(chunk))
```

## The Problem with Raw BERT

BERT produces **one vector per token**. To get a sentence embedding, you must aggregate:

```python
def bert_sentence_embedding(text: str, bert_model) -> np.ndarray:
    """
    Get sentence embedding from BERT.

    Common approaches:
    1. Use [CLS] token embedding
    2. Mean pooling of all tokens
    3. Max pooling of all tokens
    """
    outputs = bert_model(text)
    token_embeddings = outputs.last_hidden_state  # [batch, seq_len, hidden_dim]

    # Option 1: [CLS] token (NOT great for similarity)
    cls_embedding = token_embeddings[:, 0, :]

    # Option 2: Mean pooling (better)
    attention_mask = outputs.attention_mask
    input_mask_expanded = attention_mask.unsqueeze(-1).expand(token_embeddings.size())
    mean_embedding = torch.sum(token_embeddings * input_mask_expanded, 1) / torch.clamp(
        input_mask_expanded.sum(1), min=1e-9
    )

    return mean_embedding.numpy()
```

**Problem**: BERT wasn't trained to make these aggregated embeddings semantically meaningful!

## Why Sentence Transformers Work Better

Sentence Transformers are specifically trained for semantic similarity:

```python
from sentence_transformers import SentenceTransformer

# This model was trained for similarity tasks
model = SentenceTransformer('all-MiniLM-L6-v2')

# Single vector per sentence, optimized for similarity
query_embedding = model.encode("What is the capital of France?")
chunk_embedding = model.encode("Paris is the capital of France.")

# These embeddings are DESIGNED to be compared
similarity = cosine_similarity([query_embedding], [chunk_embedding])[0][0]
# Output: 0.87 (high similarity - correct!)
```

## Training Differences

### BERT Training

```
Input: "The [MASK] sat on the mat."
Task: Predict that [MASK] = "cat"

Input: "Sentence A" + "Sentence B"
Task: Are these consecutive sentences? (Yes/No)
```

### Sentence Transformer Training

```
Input: ("Paris is in France", "France's capital is Paris", 0.9)
Task: Learn embeddings where similar sentences are close

Input: ("Paris is in France", "The cat sat on the mat", 0.1)
Task: Learn embeddings where different sentences are far
```

## Mathematical Foundation

### Embedding Space Properties

**BERT Token Embeddings:**
- Dimension: 768 (BERT-base) or 1024 (BERT-large)
- Space: Contextual token representations
- Similarity: Tokens in similar contexts have similar embeddings

**Sentence Transformer Embeddings:**
- Dimension: 384 (MiniLM) to 768 (MPNet)
- Space: Semantic sentence representations
- Similarity: Semantically similar sentences cluster together

### Similarity Metrics

For RAG, we typically use cosine similarity:

$$
\text{cosine\_similarity}(a, b) = \frac{a \cdot b}{\|a\| \|b\|}
$$

Sentence Transformers are trained to maximize this for similar pairs and minimize for dissimilar pairs.

### Contrastive Loss

Sentence Transformers use contrastive loss during training:

$$
\mathcal{L} = \frac{1}{N} \sum_{i=1}^{N} \left( \underbrace{(1 - y_i) \cdot d_i^2}_{\text{push apart}} + \underbrace{y_i \cdot \max(0, m - d_i)^2}_{\text{pull together}} \right)
$$

Where:
- $y_i$ = 1 if similar, 0 if dissimilar
- $d_i$ = distance between embeddings
- $m$ = margin hyperparameter

## Complexity Analysis

| Operation | BERT | Sentence Transformers |
|-----------|------|----------------------|
| Forward pass | O(n² × d) | O(n² × d) |
| Embedding extraction | O(n × d) | O(d) |
| Similarity computation | O(d) | O(d) |
| Memory per sentence | O(n × d) | O(d) |

Where:
- n = sequence length
- d = embedding dimension

## Common Pitfalls

1. **Using BERT [CLS] token directly**: Poor similarity performance
2. **Wrong pooling strategy**: Max pooling can lose important information
3. **Not normalizing**: Cosine similarity requires normalized vectors
4. **Domain mismatch**: Using general model for specialized domain
5. **Ignoring context window**: BERT limited to 512 tokens

## Model Selection Guide

### When to Use BERT

- Token-level tasks (NER, POS tagging)
- Question answering (extractive)
- Fine-tuning for specific downstream tasks
- When you need contextual token representations

### When to Use Sentence Transformers

- Semantic search
- Document clustering
- RAG retrieval
- Duplicate detection
- Semantic similarity tasks

## Advanced Techniques

### Domain Adaptation

```python
from sentence_transformers import SentenceTransformer, InputExample, losses
from torch.utils.data import DataLoader

# Load base model
model = SentenceTransformer('all-MiniLM-L6-v2')

# Prepare domain-specific training data
train_examples = [
    InputExample(texts=["medical term A", "medical term A synonym"], label=0.9),
    InputExample(texts=["medical term A", "unrelated term"], label=0.1),
    # ... more examples
]

train_dataloader = DataLoader(train_examples, shuffle=True, batch_size=16)
train_loss = losses.CosineSimilarityLoss(model)

# Fine-tune
model.fit(train_objectives=[(train_dataloader, train_loss)], epochs=3)
```

### Quantization for Speed

```python
from sentence_transformers import SentenceTransformer
import torch

model = SentenceTransformer('all-MiniLM-L6-v2')

# Quantize to int8 for faster inference
model.eval()
quantized_model = torch.quantization.quantize_dynamic(
    model, {torch.nn.Linear}, dtype=torch.qint8
)
```

## Interview Questions

**Q1: Why does mean pooling of BERT tokens not work well for sentence similarity?**

*Answer:*
- BERT is trained for token-level predictions, not sentence similarity
- Token embeddings contain positional and contextual information that doesn't aggregate well
- No training signal to make sentence-level representations meaningful
- Stop words and punctuation dilute the semantic signal

**Q2: When would you choose a larger model (e.g., 768-dim) over a smaller one (384-dim)?**

*Answer:*
- Larger model when: Quality is critical, batch processing, sufficient compute
- Smaller model when: Latency-sensitive, edge deployment, high throughput
- Consider: Quality vs speed tradeoff, downstream task requirements, infrastructure constraints

**Q3: How would you evaluate if an embedding model is suitable for your RAG use case?**

*Answer:*
- Create domain-specific evaluation set
- Measure retrieval metrics: MRR, nDCG, Recall@K
- Test end-to-end RAG quality
- Compare against baseline (e.g., BM25)
- Consider latency and cost constraints

## Testing Your Implementation

```python
def test_embedding_models():
    from sentence_transformers import SentenceTransformer
    from sklearn.metrics.pairwise import cosine_similarity
    
    model = SentenceTransformer('all-MiniLM-L6-v2')
    
    # Test 1: Basic similarity
    emb1 = model.encode("Paris is in France")
    emb2 = model.encode("France's capital is Paris")
    emb3 = model.encode("The cat sat on the mat")
    
    sim_12 = cosine_similarity([emb1], [emb2])[0][0]
    sim_13 = cosine_similarity([emb1], [emb3])[0][0]
    
    assert sim_12 > 0.7  # Similar sentences
    assert sim_13 < 0.5  # Dissimilar sentences
    
    # Test 2: Encoding consistency
    emb1_repeat = model.encode("Paris is in France")
    assert np.allclose(emb1, emb1_repeat)
    
    # Test 3: Batch encoding
    sentences = ["Sentence A", "Sentence B", "Sentence C"]
    embeddings = model.encode(sentences)
    assert embeddings.shape == (3, 384)
```
