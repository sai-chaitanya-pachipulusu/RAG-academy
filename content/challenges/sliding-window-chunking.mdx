# Sliding Window Chunking: Maximum Coverage

## When 20% Overlap Isn't Enough

For **critical documents** (legal contracts, medical records), missing a single clause could mean:

- A lawsuit
- A misdiagnosis
- Regulatory non-compliance

Standard overlap has "blind spots". Sliding window eliminates them.

---

## The Dense Overlap Insight

Instead of 20% overlap, what if we create MANY views with small strides?

```
Standard overlap (stride = 80% of window):
[AAAAAAAAAA]
        [BBBBBBBBBB]

Sliding window (stride = 10% of window):
[AAAAAAAAAA]
  [AAAAAAAAAB]
    [AAAAAAABBB]
      [AAAAABBBBB]
        ...
```

**Some chunk will contain ANY possible query exactly.**

---

## The Algorithm

```python
def sliding_window(text: str, window_size: int, stride: int):
    """
    Generate overlapping windows with position tracking.

    Returns: List of (chunk_text, start_position) tuples
    """
    chunks = []
    for i in range(0, len(text) - window_size + 1, stride):
        chunks.append((text[i:i + window_size], i))
    return chunks
```

## The Numbers

For 10,000 chars with window_size=500:

| Stride            | Chunks Created | Storage Multiplier |
| ----------------- | -------------- | ------------------ |
| 500 (no overlap)  | 20             | 1x                 |
| 100 (80% overlap) | 96             | ~5x                |
| 50 (90% overlap)  | 191            | ~10x               |
| 10 (98% overlap)  | 951            | ~50x               |

## ⚖️ Tradeoffs

### Pros

- ✅ Near-perfect recall
- ✅ Position tracking for citations
- ✅ No blind spots

### Cons

- ❌ 5-50x more storage
- ❌ 5-50x more embedding cost
- ❌ More retrieval candidates to filter

## Position Tracking

Critical for citations:

```python
chunks = sliding_window(document, 500, 50)
for chunk, position in chunks:
    if relevant(chunk, query):
        print(f"Found at character {position}")
        print(f"Source: {document[position:position+20]}...")
```
