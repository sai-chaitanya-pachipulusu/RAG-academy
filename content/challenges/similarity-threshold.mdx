## The Problem with Top-K

Top-K retrieval always returns K results, even if none of them are relevant:

```python
query = "How to build a rocket?"
top_k_results = [
    ("Banana recipes", 0.25),
    ("Weather forecast", 0.22),
    ("Cat videos", 0.20),
]
# All terrible, but top-K=3 returns them anyway!
```

**The Cost**: Your LLM will try to answer "How to build a rocket?" using banana recipes, leading to hallucinations and user frustration.

## The Solution: Threshold Filtering

Add a `min_score` filter to ensure minimum quality:

```python
filter_by_threshold(results, min_score=0.6)
# Returns: []  # Nothing passes!
```

Now your RAG system can trigger a **"I don't have relevant information"** refusal instead of hallucinating from garbage context.

## Theoretical Foundation

### Score Distribution Analysis

In a typical RAG system, similarity scores follow a bimodal distribution:

```
Score Distribution
│
│    ██                    ██
│    ██                    ██
│    ██                    ██
│    ██                    ██
│   ████                  ████
│   ████                  ████
│  ██████                ██████
│  ██████                ██████
└────────────────────────────────
  0.0   0.3   0.5   0.7   1.0
  
  Irrelevant ─┬─ Relevant
           Threshold
```

**Key insight**: There's often a "valley" between relevant and irrelevant scores. Thresholding at this valley maximizes precision.

### Threshold Selection Strategies

| Strategy | Method | Use Case |
|----------|--------|----------|
| **Fixed** | `min_score = 0.7` | Consistent domain, validated data |
| **Dynamic** | Mean + 2σ | Variable query difficulty |
| **Percentile** | Top 10% of all scores | Competitive retrieval |
| **Adaptive** | Learned from user feedback | Production optimization |

### Statistical Threshold Tuning

```python
import numpy as np

def find_optimal_threshold(scores: list[float], labels: list[bool]) -> float:
    """
    Find threshold that maximizes F1 score.
    
    scores: similarity scores
    labels: True if relevant, False otherwise
    """
    best_threshold = 0.0
    best_f1 = 0.0
    
    for threshold in np.arange(0.1, 0.95, 0.05):
        predictions = [s >= threshold for s in scores]
        
        tp = sum(p and l for p, l in zip(predictions, labels))
        fp = sum(p and not l for p, l in zip(predictions, labels))
        fn = sum(not p and l for p, l in zip(predictions, labels))
        
        precision = tp / (tp + fp) if (tp + fp) > 0 else 0
        recall = tp / (tp + fn) if (tp + fn) > 0 else 0
        f1 = 2 * precision * recall / (precision + recall) if (precision + recall) > 0 else 0
        
        if f1 > best_f1:
            best_f1 = f1
            best_threshold = threshold
    
    return best_threshold
```

### Combining with Top-K

```python
def retrieve_with_quality_control(
    query: str,
    index: VectorIndex,
    top_k: int = 10,
    min_score: float = 0.6,
) -> RetrievalResult:
    """
    Retrieve with both quantity (top_k) and quality (min_score) controls.
    """
    # Get candidates
    candidates = index.search(query, k=top_k * 2)  # Over-fetch
    
    # Apply quality filter
    qualified = [c for c in candidates if c.score >= min_score]
    
    # Return top_k of qualified
    return qualified[:top_k]
```

### Refusal Policy Integration

```python
def generate_or_refuse(query: str, context: list[str], min_score: float) -> str:
```
