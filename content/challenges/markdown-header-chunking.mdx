## Why this matters in production

Docs are usually structured:

- headings
- sections
- subsections
- code blocks and lists

If you chunk without structure, you often:

- separate definitions from their headings
- mix unrelated topics into one chunk
- make metadata filtering impossible (because you lost the section info)

## Offline vs online

- **Offline (ingestion)**: chunk by headers and store metadata (`h1/h2/h3`).
- **Online (query time)**: use metadata filters and routing (e.g., "only search under Usage").

## The Structure Advantage

```markdown
# Installation
pip install rag-academy

## Quick Start
Run this command...

## Advanced Options
Configure these settings...
```

**Without structure-aware chunking:**
- "pip install rag-academy" (Installation heading lost!)
- "Run this command... Configure these settings..." (Mixed sections!)

**With structure-aware chunking:**
- Chunk 1: `# Installation` + `pip install rag-academy`
- Chunk 2: `## Quick Start` + `Run this command...`
- Chunk 3: `## Advanced Options` + `Configure these settings...`

## The Algorithm

```python
def markdown_header_chunk(text: str, headers: list[str] = None) -> list[dict]:
    """
    Chunk markdown by headers with hierarchical metadata.
    
    Time Complexity: O(L) where L = number of lines
    Space Complexity: O(N) for output
    
    Args:
        text: Markdown text
        headers: List of header levels to split on (e.g., ['#', '##'])
        
    Returns:
        List of chunks with header metadata
    """
    if headers is None:
        headers = ['#', '##', '###']
    
    chunks = []
    current_chunk = []
    current_header = None
    header_stack = []
    
    for line in text.split('\n'):
        # Check if line is a header
        stripped = line.lstrip()
        header_level = 0
        for i, char in enumerate(stripped):
            if char == '#':
                header_level += 1
            else:
                break
        
        if header_level > 0 and stripped[:header_level] in headers:
            # Save previous chunk
            if current_chunk:
                chunks.append({
                    'text': '\n'.join(current_chunk),
                    'header': current_header,
                    'breadcrumb': ' > '.join(header_stack)
                })
            
            # Update header tracking
            current_header = stripped[header_level:].strip()
            header_stack = header_stack[:header_level-1] + [current_header]
            current_chunk = [line]
        else:
            current_chunk.append(line)
    
    # Don't forget the last chunk
    if current_chunk:
        chunks.append({
            'text': '\n'.join(current_chunk),
            'header': current_header,
            'breadcrumb': ' > '.join(header_stack)
        })
    
    return chunks
```

## Complexity Analysis

| Operation | Time | Space |
|-----------|------|-------|
| Line parsing | O(L) | O(1) |
| Header tracking | O(L × H) | O(H) |
| Chunk storage | O(N) | O(N) |

Where L = lines, H = header depth, N = text length

## What you're building

A chunker that:

- starts a new chunk at each `#`, `##`, `###` heading
- attaches hierarchical metadata so chunks know where they live in the doc

## Production extensions (optional)

- preserve a `path` array like `["Title", "Usage", "Advanced"]`
- add `chunk_id` (combine this with the "Stable Chunk IDs" lab)
- special-handle fenced code blocks so they don't get split incorrectly
