# RAG Failure Diagnosis

When a RAG system gives a wrong answer, **where did it fail?** Based on the [Seven Failure Points paper](https://arxiv.org/abs/2401.05856) by Barnett et al. (2024), we can systematically diagnose issues.

## The Seven Failure Points

| Code    | Failure Point     | Stage         | Quick Description                     |
| ------- | ----------------- | ------------- | ------------------------------------- |
| **FP1** | Missing Content   | Corpus        | Answer doesn't exist in your data     |
| **FP2** | Missed Top Rank   | Retrieval     | Answer exists but wasn't in top-K     |
| **FP3** | Not in Context    | Consolidation | Retrieved but dropped during assembly |
| **FP4** | Not Extracted     | Generation    | In context but LLM didn't use it      |
| **FP5** | Wrong Format      | Generation    | Content correct, format wrong         |
| **FP6** | Wrong Specificity | Generation    | Too specific or too general           |
| **FP7** | Incomplete        | Generation    | Partial answer, missing info          |

def keyword_overlap(text: str, keywords: List[str]) -> float:
    """Calculate what fraction of keywords appear in text."""
    text_lower = text.lower()
    found = sum(1 for kw in keywords if kw.lower() in text_lower)
    return found / len(keywords) if keywords else 0.0

## Implementation Tips

### FP1: Missing Content Check

```python
def check_fp1_missing_content(self, query, expected_keywords, search_k=100):
    # Try to find ANY doc with the expected content
    all_docs = self.retriever.retrieve(query, k=search_k)

    best_overlap = 0.0
    for doc in all_docs:
        text = doc.get("text", doc.get("content", ""))
        overlap = keyword_overlap(text, expected_keywords)
        best_overlap = max(best_overlap, overlap)

    if best_overlap < 0.3:  # Less than 30% keyword match
        return DiagnosisResult(
            failure_point=FailurePoint.FP1_MISSING_CONTENT,
            confidence=1.0 - best_overlap,
            details=f"Expected keywords not found. Best overlap: {best_overlap:.1%}",
            suggested_fix="Add the missing content to your corpus"
        )
    return None
```

### FP2: Ranking Check

Compare recall@K vs recall@100 to detect ranking issues.

### FP3: Context Assembly

Check if content was in retrieved docs but got truncated during prompt assembly.

### FP4: Extraction

Check if the answer was in the context but the LLM ignored it or gave a generic response.

## Extensions

1. **FP5 (Format)**: Add regex patterns to detect format requests (table, list, JSON)
2. **FP6 (Specificity)**: Detect multi-entity queries and check coverage
3. **FP7 (Completeness)**: Check if all aspects of multi-part questions were addressed

## Why This Matters

In production, knowing **which** stage failed is crucial:

- FP1/FP2 → Fix your data or retrieval
- FP3 → Fix context assembly
- FP4-7 → Fix prompts or model

Without diagnosis, you waste time optimizing the wrong component.
