# Reasoning RAG Implementation

Traditional RAG retrieves once and generates. This fails for complex questions that require connecting information from multiple sources.

**Your task**: Build a Reasoning RAG system that thinks, retrieves iteratively, and verifies its answers.

```python
def retrieve(self, query: str, k: int = 3) -> List[Document]:
    query_terms = set(query.lower().split())
    scores = []
    for doc in self.documents:
        doc_terms = set(doc.content.lower().split())
        overlap = len(query_terms & doc_terms)
        scores.append((doc, overlap))
    scores.sort(key=lambda x: x[1], reverse=True)
    return [doc for doc, score in scores[:k] if score > 0]
```

```python
def plan_next_step(self, question: str, steps: List[ReasoningStep]):
    # No steps yet → start with retrieval
    if not steps:
        return ReasoningStep("Need initial information", "retrieve", question)
    
    # Just retrieved → reason about what we have
```

## Theoretical Foundation

### Multi-Hop Reasoning

Reasoning RAG addresses questions that require connecting information from multiple documents:

$$
\text{Answer} = f(d_1, d_2, ..., d_n) \text{ where } d_i \in \text{Retrieved}(q_i)
$$

Where each $q_i$ is a sub-query derived from the original question.

### Iterative Retrieval Process

```
For each step t:
  1. State s_t = (question, context_{<t})
  2. Action a_t = π(s_t)  // Plan next action
  3. If a_t = retrieve:
       - Generate query q_t
       - Retrieve docs D_t
       - Update context
  4. If a_t = reason:
       - Analyze current context
       - Identify gaps
  5. If a_t = answer:
       - Generate from context
       - Verify and cite
```

### Verification Formula

The verification score measures answer support:

$$
V(a, D) = \frac{1}{|claims(a)|} \sum_{c \in claims(a)} \max_{d \in D} \text{sim}(c, d)
$$

Where:
- $a$ = answer
- $claims(a)$ = extracted factual claims
- $D$ = retrieved documents
- $sim$ = semantic similarity

## Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|----------------|------------------|
| Single retrieval | O(n × m) | O(k) |
| Reasoning step | O(L) | O(1) |
| Verification | O(|a| × k) | O(1) |
| Full pipeline (t steps) | O(t × (n×m + L)) | O(t × k) |

Where:
- n = corpus size
- m = avg doc length
- k = docs retrieved per step
- L = LLM inference cost
- t = reasoning steps

## Best Practices

1. **Limit iterations**: Set max_steps to prevent infinite loops
2. **Deduplicate**: Track retrieved docs to avoid re-fetching
3. **Early stopping**: Verify and answer when confident
4. **Citation tracking**: Always record document sources
5. **Error handling**: Gracefully handle retrieval failures
