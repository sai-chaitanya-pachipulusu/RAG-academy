## Agentic RAG

Classic RAG is a straight line: `Retriever -> Reranker -> LLM`.

**Agentic RAG** is a loop. The system can:

1.  **Reason**: "I need to search for the weather."
2.  **Act**: Call a weather API.
3.  **Observe**: Read the API result.
4.  **Loop**: Generate the final answer.

The simplest agent is a **Router**. It classifies the user's intent to pick the right path.

## The Router Pattern

```
User Query
    ↓
Router/Classifier
    ↓
    ├─→ Small Talk → Direct Response
    ├─→ Math → Calculator Tool
    ├─→ Facts → RAG Pipeline
    └─→ Real-time → External API
```

### Router Decision Formula

The router assigns a query $q$ to tool $t$ based on:

$$t^* = \arg\max_{t \in T} P(t|q)$$

Where $T$ is the set of available tools and $P(t|q)$ is the probability that tool $t$ is appropriate for query $q$.

## Why this matters in production

You don't want to RAG everything.

- **Small talk ("Hi")**: RAG is wasteful/slow.
- **Math ("25 * 4")**: LLMs are bad at math; use a calculator.
- **Fact ("Who is the CEO?")**: RAG or Search is essential.

### Cost Analysis

| Approach | Avg Cost/Query | Latency | Accuracy |
|----------|---------------|---------|----------|
| Always RAG | $0.05 | 2.5s | 85% |
| Smart Router | $0.02 | 1.2s | 92% |
| **Savings** | **60%** | **52%** | **+7%** |

## Implementation details

In this challenge, you will implement a simple classification heuristic.
In production, you would use:

- **Zero-shot classification** (ask the LLM to pick).
- **Fine-tuned classifier** (BERT/distil-bert) for latency sensitive routing.
- **Function calling** (OpenAI/Anthropic tool use API).

### Tool Selection Algorithm

```python
class ToolRouter:
    """Route queries to appropriate tools."""
    
    def __init__(self):
        self.tools = {
            'calculator': self._is_math_query,
            'weather_api': self._is_weather_query,
            'rag': self._is_knowledge_query,
            'direct': self._is_small_talk
        }
    
    def route(self, query: str) -> str:
        """
        Route query to appropriate tool.
        
        Time Complexity: O(|T|) where |T| = number of tools
        Space Complexity: O(1)
        """
        scores = {}
        for tool_name, classifier in self.tools.items():
            scores[tool_name] = classifier(query)
        
        # Return tool with highest confidence
        return max(scores, key=scores.get)
```

## Common pitfalls

- Routing everything to RAG (wasteful).
- Not handling ambiguous queries.
- Latency overhead from routing decision.
- Missing fallback when primary tool fails.
