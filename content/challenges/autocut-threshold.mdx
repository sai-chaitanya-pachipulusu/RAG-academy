## The "Fixed Top-K" Problem

Most RAG systems retrieve exactly `k` documents (e.g., Top 5).
But what if only 2 documents are relevant? You end up with 3 "hallucinated" or noisy chunks in your context.
What if 10 documents are relevant? You miss 5 critical facts.

## The Autocut Solution

**Autocut** (pioneered by Weaviate) looks at the _gaps_ between scores. If there is a sudden, large drop in similarity score between result #3 and result #4, Autocut "cuts" the list at #3.

Instead of a hard limit, you use a **relative threshold**.

## Implementation

1. Calculate the gaps between consecutive scores.
2. Maintain a running average of gaps.
3. If a gap is significantly larger than the average (defined by a multiplier), terminate the list there.

## Mathematical Foundation

### Gap Detection

Given a sorted list of similarity scores $s_1 \geq s_2 \geq ... \geq s_n$, the gap between consecutive scores is:

$$
\text{gap}_i = s_i - s_{i+1}
$$

### Adaptive Threshold

The running average of gaps up to position $i$:

$$
\bar{g}_i = \frac{1}{i} \sum_{j=1}^{i} \text{gap}_j
$$

### Cut Decision

Cut at position $k$ where:

$$
\text{gap}_k > \alpha \cdot \bar{g}_k
$$

Where $\alpha$ is the sensitivity parameter (typically 1.5-2.0).

### Alternative: Standard Deviation Approach

For more robust cutting, use standard deviation:

$$
\text{cut if } \text{gap}_k > \bar{g} + \beta \cdot \sigma_g
$$

Where $\sigma_g$ is the standard deviation of gaps and $\beta$ is typically 2-3.

## Complexity Analysis

| Operation | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| Score sorting | O(n log n) | O(n) |
| Gap calculation | O(n) | O(n) |
| Running average | O(n) | O(1) |
| Cut detection | O(n) | O(1) |

Where n = number of retrieved candidates

## Common Pitfalls

1. **Over-cutting**: High sensitivity causes too few results
2. **Under-cutting**: Low sensitivity includes irrelevant chunks
3. **Score Distribution**: Doesn't work well with uniform scores
4. **Small Result Sets**: Unreliable with < 5 results
5. **Multiple Clusters**: May cut in the middle of a relevant cluster

## Advanced Techniques

### Multi-Level Autocut

```python
class MultiLevelAutocut:
    """Detect multiple natural boundaries in results."""
    
    def find_all_cuts(self, scores: list[float], alpha: float = 1.5) -> list[int]:
        gaps = [scores[i] - scores[i+1] for i in range(len(scores)-1)]
        avg_gap = sum(gaps) / len(gaps)
        
        cuts = []
        for i, gap in enumerate(gaps):
            if gap > alpha * avg_gap:
                cuts.append(i + 1)
        
        return cuts
    
    def cluster_results(self, scores: list[float]) -> list[list[int]]:
        """Group results into relevance clusters."""
        cuts = self.find_all_cuts(scores)
        clusters = []
        start = 0
        
        for cut in cuts:
            clusters.append(list(range(start, cut)))
            start = cut
        clusters.append(list(range(start, len(scores))))
        
        return clusters
```

### Dynamic Alpha Tuning

```python
class AdaptiveAutocut:
    """Adjust sensitivity based on score distribution."""
    
    def compute_alpha(self, scores: list[float]) -> float:
        """Compute optimal alpha based on score statistics."""
        if len(scores) < 5:
            return float('inf')  # Don't cut small result sets
        
        # Higher variance = need higher alpha
        variance = statistics.variance(scores)
        
        # Adjust alpha inversely with variance
        base_alpha = 1.5
        if variance > 0.01:
            return base_alpha * 1.5
        elif variance < 0.001:
            return base_alpha * 0.8
        
        return base_alpha
```

### Hybrid Approach: Autocut + Min/Max Constraints

```python
def autocut_with_constraints(
    scores: list[float], 
    alpha: float = 1.5,
    min_results: int = 3,
    max_results: int = 10
) -> int:
    """Autocut with safety bounds."""
    
    # Calculate autocut point
    cut_point = autocut(scores, alpha)
    
    # Apply constraints
    cut_point = max(cut_point, min_results)
    cut_point = min(cut_point, max_results)
    
    return cut_point
```

## Interview Questions

**Q1: When would you prefer fixed K over Autocut?**

*Answer:*
- When consistent latency is required (variable results = variable processing)
- When downstream systems expect fixed-size inputs
- When score distributions are unreliable (e.g., cross-encoder scores)
- For A/B testing with controlled variables

**Q2: How would you handle multi-modal scores (e.g., combining BM25 + semantic)?**

*Answer:*
- Normalize scores to same scale before gap calculation
- Use rank-based autocut instead of score-based
- Apply autocut separately to each modality, then merge
- Use learned threshold based on query type

**Q3: Design an autocut variant that considers query difficulty.**

*Answer:*
- Estimate query difficulty using query features (length, ambiguity, domain)
- Hard queries → lower alpha (include more results)
- Easy queries → higher alpha (be more selective)
- Train a small classifier to predict optimal alpha
