## Why this matters in production

Vector databases like **Pinecone**, **Weaviate**, and **Milvus** ultimately reduce "retrieval" to fast candidate **scoring**.

The Dot Product is the fundamental scoring operation:

- **Cosine Similarity** is just normalized dot product.
- **Attention Mechanisms** in Transformers use dot product (`Query · Key`).
- **Maximum Inner Product Search (MIPS)** is the standard retrieval task.

If you can't implement this efficiently, you can't build scalable RAG.

## What you're implementing

```
dot(a, b) = Σ(a_i × b_i)
```

- Validate equal lengths (raise `ValueError` if mismatch).
- Handle empty vectors (`dot([], []) == 0.0`).
- Return a `float`.

## The Algorithm

```python
def dot_product(a: list[float], b: list[float]) -> float:
    """
    Compute dot product of two vectors.
    
    Time Complexity: O(N) where N = vector dimension
    Space Complexity: O(1) additional
    
    Args:
        a: First vector
        b: Second vector
        
    Returns:
        Dot product as float
        
    Raises:
        ValueError: If vectors have different lengths
    """
    if len(a) != len(b):
        raise ValueError(f"Vector length mismatch: {len(a)} vs {len(b)}")
    
    return sum(x * y for x, y in zip(a, b))
```

## Complexity Analysis

| Aspect | Complexity | Notes |
|--------|------------|-------|
| Time | O(N) | Single pass through vectors |
| Space | O(1) | No additional storage |
| Operations | N multiplies + N-1 adds | Per comparison |

- Forgetting length checks (python's `zip` truncates silently!).
- Returning `int` instead of `float` (type safety matters in production).
